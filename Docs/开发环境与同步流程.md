# 开发环境与同步流程

> 版本：v3（WSL 开发、构建、测试与推送）
> 更新日期：2026-11-05
> 说明：规定 WSL 日常开发、测试、构建和 GitHub 推送方式；Windows 工作区目前主要保留文档等内容。迁移过程记录已归档于《归档/历史方案与原料/WSL智能体环境迁移交接_20261102.md》。

## 一、环境分工

| 环境 | 用途 | 项目目录 | 项目服务 |
|---|---|---|---|
| WSL Ubuntu | Codex 智能体唯一开发、构建、运行和测试环境 | `/home/it/ZhiYun` | 使用 WSL 的 JDK、Maven wrapper、Node/pnpm、PostgreSQL、Redis 与 MinIO |
| Windows | 用户桌面与迁移期旧工作副本 | `D:\ZhiYun` | 不再作为 Codex 日常编辑源；迁移完成后保持只读，除非用户另行指定 |
| Ubuntu 实体服务器（后续） | 独立测试/部署环境 | 由部署方案确定 | 按《部署与迁移.md》部署，配置和数据独立保存 |

源码在 WSL 工作区修改并由 Git 管理。WSL 与 Windows 的两个仓库是独立工作副本，不是实时镜像；不得用复制覆盖、`robocopy` 或 `rsync --delete` 同步代码。环境配置、数据库数据、上传文件、日志和构建缓存不跨环境复制。

## 二、日常开发流程

1. 在 Codex 中选择 WSL 智能体环境，并将项目工作区打开为 WSL Linux 路径 `/home/it/ZhiYun`。
2. 开工前确认 `pwd`、`git rev-parse --show-toplevel`、分支及 `git status --short`；若仍在 `/mnt/d/ZhiYun` 或 `D:\ZhiYun`，先切换工作区，不写文件。
3. 先检查现有未提交改动，只修改当前任务涉及的文件；不清理、重置或覆盖其他改动。
4. 按任务需要执行构建；数据库变更遵守 DDL 注释、迁移和单独审查规则。
5. 前端页面由 Vite HMR 更新。用户负责浏览器目视验收；除非用户明确要求，不主动打开浏览器。
6. 记录实际执行的构建、服务操作和未完成项；不得把“已构建”写成“已用户验收”。

## 三、当前仓库入口

- 后端：`RuoYi-Vue-Plus/`，Java 21、Maven；使用仓库内 `./mvnw`。
- 前端：`frontend/`，Vue 3 + TypeScript + Vite；项目脚本定义在 `frontend/package.json`，依赖管理使用 pnpm。
- WSL 服务脚本：`scripts/start.sh`、`scripts/stop.sh`、`scripts/status.sh`。
- 开发配置：WSL 项目根目录 `.env`；仓库只跟踪 `.env.example`。
- 后端开发 profile：`RuoYi-Vue-Plus/ruoyi-admin/src/main/resources/application-dev.yml`。
- 运行服务状态：`bash scripts/status.sh`。脚本 `start.sh` 会补启未运行的服务；`stop.sh` 会停止前后端，不适合只重启后端时使用。

常用命令（在 WSL 项目根目录执行）：

```bash
cd /home/it/ZhiYun/RuoYi-Vue-Plus
./mvnw -pl ruoyi-admin -am package -DskipTests
cd /home/it/ZhiYun
bash scripts/start.sh
bash scripts/status.sh
```

停止服务：

```bash
bash scripts/stop.sh
```

前端源码修改一般不需要重启 Vite。后端当前以 `ruoyi-admin.jar` 运行且没有 Spring DevTools；修改后端代码时先完成一次 Maven 构建，再按需仅重启后端一次。Maven 会覆盖运行中的 JAR，不能把后端构建当成热更新。

## 四、环境边界与安全

1. Codex 智能体在 WSL 运行；代码、构建和服务命令均从 `/home/it/ZhiYun` 执行，不从 `/mnt/d` 路径操作项目。
2. 不把 WSL 的 `.env`、数据库目录、MinIO 数据、日志或构建缓存复制到 Windows。
3. `.env` 不提交 Git；任何口令、Token、模型密钥、对象存储凭据不得写入代码或文档。
4. 配置变量名以 `.env.example` 为准。新增配置项时同步更新模板，模板不得填真实凭据。
5. 切换 Codex 智能体环境不会自动证明项目工作区也已切到 Linux 文件系统；每次新线程/新工作区都核对仓库绝对路径。
6. 不要把 Windows 用户目录下整个 Codex 配置、会话缓存或凭据目录复制进 WSL。只在确认具体需要后迁移项目级指令或技能，并检查其路径和依赖是否适用于 Linux。

## 五、后续服务器迁移

WSL 与实体 Ubuntu 均为 Linux 环境，优先复用相同构建命令、启动入口和配置变量。迁移时只迁移明确的源码提交及必要数据；数据库、MinIO 文件和 `.env` 应通过独立的备份/恢复与密钥配置流程处理，详见《部署与迁移.md》。

# 织云 ERP MCP 调用指南

> 适用对象：通过织云 ERP MCP Server 读取或维护业务数据的智能体。
> MCP 端点配置：`http://<ERP服务地址>/mcp`，传输协议为 Streamable HTTP。调用使用当前员工本人会话和项目要求的 `clientid`；不要把口令、Token 写进参数、Skill、提示词或日志。

连接配置通常需要请求头 `Authorization: Bearer <当前员工会话Token>` 和 `clientid: <项目客户端标识>`。Token 由 MCP 客户端安全配置提供，不要放在下面的工具 `arguments` 中，也不要把真实值写进文档或聊天记录。

## 1. 先确认工具与参数

1. 连接 MCP Server 后先读取 `tools/list`，确认目标工具确实出现在当前服务的工具目录中。
2. 以运行时返回的工具 `name`、`description`、`inputSchema` 为准；随后查看对应功能 Skill 与[功能 API 契约索引](../API/API文档.md)。若三者冲突，停止猜参并报告差异。
3. 当前智能体可见的工具目录可能经过员工权限过滤；工具未出现在本轮 `tools/list` 中，只能说明当前连接/身份下不可见，不能据此断言后端没有该能力。核对服务地址、运行版本及当前员工权限，不得绕过权限或改用管理员身份。
4. MCP 客户端的工具调用参数是一个 JSON 对象。参数名必须与 `inputSchema.properties` 完全一致；不得自行添加 `body`、`filter` 或 `query` 包装层，除非该工具 schema 中确实有这个参数。
5. `required` 中的参数必须传；其余参数可省略。字段级定义以[API 文档规范](../规范/API文档规范.md)和对应功能 API 字段表为准：除非字段表明确允许，否则不要传 JSON `null`、字符串 `"null"`、空白字符串 `""`、空数组 `[]` 或空对象 `{}`。`null`、省略和空集合不是可互换写法。
6. 调用对象/数组字段前，递归核对内部字段的必填条件与空值语义。`Map` 参数可能在 `inputSchema` 中表现为宽松对象；这不代表服务端支持任意字段或会自动补默认值。字段表未说明的输入先停止并核实，不根据 Java 类型或页面控件猜测。

## 2. MCP `tools/call` 请求示例

下面是标准 JSON-RPC 调用结构。实际使用时由 MCP 客户端代为发送；通常只需选择工具并填写 `arguments` 对象。

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "customer_list",
    "arguments": {
      "keyword": "示例客户",
      "status": "0",
      "pageNum": 1,
      "pageSize": 20
    }
  }
}
```

只查全部客户时，筛选字段可省略：

```json
{
  "name": "customer_list",
  "arguments": {
    "pageNum": 1,
    "pageSize": 20
  }
}
```

`material_list` 的筛选参数是名为 `filter` 的对象，不能把筛选字段放到工具参数顶层：

```json
{
  "name": "material_list",
  "arguments": {
    "filter": {
      "keyword": "棉布",
      "status": "0"
    }
  }
}
```

以上是 MCP 工具调用的 `name` 和 `arguments` 示例，不是 REST URL，也不是命令行参数。`arguments` 内的字段大小写必须按该工具 schema 原样填写。

## 3. 参数类型约定

- **主键 ID**：一般使用正十进制字符串，例如 `"123456789012345678"`；不能转换为 JSON 数字、浮点数或科学计数法，也不能传负数或带其他字符的值。示例 ID 仅用于展示格式，实际调用必须复制前序查询返回的 ID。明确约定特殊值的字段例外，例如客户列表 `categoryId="0"` 表示未分类。服务端会把格式错误作为参数错误返回，不会静默忽略错误 ID 并扩大筛选范围。
- **状态/枚举**：按工具描述中列出的精确值传递。不同功能可能分别使用 `"0"/"1"`、`"active"/"disabled"/"maintenance"` 或整数层级 `1/2/3`，不可跨功能套用。
- **客户/组织/岗位/建筑的状态筛选**：可选时省略或传空白；提供时只传该工具说明允许的状态值。非法状态会返回参数错误，不能依赖它自动忽略筛选。
- **对象**：`body`、`filter`、`rule` 等参数应传 JSON object，不要传序列化后的 JSON 字符串。
- **数组**：字段要求数组时传 JSON array，并保持其顺序；不能改成逗号分隔字符串。只有参数说明明确要求逗号分隔的 ID 字符串时才使用逗号分隔。
- **字段命名**：不同工具遵循各自控制器契约；例如客户资料部分字段使用下划线命名，仓库字段使用驼峰命名。不要全局把字段改成 snake_case 或 camelCase。
- **分页**：仅在 schema 中出现分页参数的工具支持分页；按说明使用默认值和上限。其他返回列表的工具可能一次返回完整目录，不能自行假设有 `pageNum`。
- **默认值**：工具说明写有默认值时，优先省略该参数，让服务端执行默认逻辑；不要传 `null` 试图触发默认值。

## 4. 推荐的数据读取顺序

1. 先选对工具：`*_list` 通常查询管理目录；`*_options` 通常返回业务可选项，二者的状态范围、字段和权限可能不同。
2. 先用无筛选条件确认结果范围；再按确切的字段名添加筛选。不要猜测分类、标签、人员或单位 ID。
3. 需要关联数据时，先从当前查询结果复制真实 ID，再调用详情/选项工具；不要用名称、编码或其他模块的 ID 替代。
4. 返回空结果不等于资料不存在。人员分类范围、记录状态和数据权限都可能过滤结果；说明“当前权限下未查到”，不要推断或泄露范围外数据。
5. 响应业务数据遵循 `code`、`msg`、`data` 语义，但 `data` 可能是数组、分页对象、树或详情对象。按实际返回结构解析，不要假设所有列表都有 `data.rows`。

## 5. 写操作约束

- 写工具会按当前员工身份再次校验服务端权限，但工具权限检查不等于员工已确认业务变更。
- 新增、修改、删除、启停、批量替换和规则调整前，先读取当前资料/选项，展示完整对象、实际变化和影响，取得员工本次确认后再调用。
- 工具描述中的确认要求属于调用方必须遵守的前置条件，MCP 工具自身不会弹出确认窗口。ERP 内嵌 Snail-AI 链路由服务端暂停写工具并通过页面确认卡放行；其他 MCP 客户端必须提供自己的展示和确认流程，未获得本次确认时不得调用写工具。
- ERP 内嵌链路只把经审核的完整工具名白名单视为只读；新工具或未知工具即使名称以 list、get、options 等结尾，也会走写工具确认路径。新增只读工具须先核对权限、数据范围和副作用，再登记精确名称；不得仅凭命名后缀放行。
- 全量替换类字段（如最终标签、颜色、尺码、成员列表）必须把最终集合按数组传入；空数组可能代表清空，调用前必须明确说明。
- 自动编码是可编辑建议。先读取建议，再向员工展示；不能擅自将建议当作最终编码，也不能为规避重复校验自行改号。
- 写请求超时或响应不明确时，先用查询工具核对是否已生效，再决定是否重试；批量工具可能部分成功，逐行核对并报告。
- 不通过 SQL、任意 HTTP、其他员工 Token 或管理员身份绕过 MCP、权限、数据范围和业务校验。

## 6. 错误处理

| 结果 | 含义与处理 |
|---|---|
| `401` | 员工会话失效或 `clientid` 不匹配；由员工重新建立本人会话后再试，不读取或索取其口令。 |
| `403` | 当前员工缺少该工具所需权限；停止操作，不换用超管身份。 |
| `500` | 通常是业务校验失败；向用户说明 `msg`，按提示补充资料或停止，不盲目重试写操作。 |
| 参数/schema 校验失败 | 对照 `tools/list` 的 `inputSchema`；修正参数名、类型或必填项，不发送 `null` 填充可选项。 |
| 查询为空 | 检查当前员工权限、数据范围、状态筛选及是否用错 `list`/`options`；不得直接断言资料不存在。 |

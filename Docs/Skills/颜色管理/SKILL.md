# 颜色管理

> 版本：v1
> 更新日期：2026-11-07
> 说明：用户已验收；2026-11-07 已发现8个 MCP 工具，并实际验证颜色查询、选项、编码建议、新增、修改、启停和删除。编码规则写入工具已发现但未实际调用；普通低权限角色验证未执行，详见 API 契约和验收清单。

## 适用范围与工具

维护物料、款式等业务共用的颜色主档。颜色使用稳定 ID 引用；此功能不维护供应商色号、缸号、实物色卡、色差结论或库存批次。

工具契约见 `Docs/API/颜色管理API.md`。工具名：

- 查询：`color_list`、`color_options`、`color_next_code`
- 维护：`color_create`、`color_update`、`color_set_status`、`color_delete`、`color_set_code_rule`

通用 MCP 请求结构和参数类型说明见[织云 ERP MCP 调用指南](../MCP调用指南.md)。

## 查询调用示例

查询颜色主档使用 `color_list`；需要给业务引用颜色时改用 `color_options`，并按 `selectable` 判断能否新选：

```json
{"name":"color_list","arguments":{}}
```

调用权限按当前员工本人检查。ID 用十进制字符串。若工具不可发现或调用失败，应如实报告 MCP 当前不可用；不得绕过 MCP 直接访问数据库。

## 操作流程

1. 用户要查颜色档案时，使用 `color_list`；业务选择现有颜色时用 `color_options`。停用颜色带 `selectable=false`，可以为历史资料显示，不得推荐给新建业务。
2. 用户要求新增时，先核对编码规则和重名情况；可调用 `color_next_code` 取建议。生成编码只是可编辑建议，不得擅自视为最终编码。
3. 写入前展示颜色编码、名称、屏幕色值、排序和备注，并明确色值只辅助屏幕识别，不能代替实物色卡或供应商色号。取得员工本次确认后调用 `color_create`。
4. 修改前通过 `color_list` 核对目标身份；展示修改前后值并确认，再调用 `color_update`。编码创建后固定，不提出编码变更。
5. 停用前说明它会阻止新业务引用但保留已有历史显示；确认后调用 `color_set_status`。启用只允许业务确认过的颜色重新进入新选项。
6. 删除前展示编码和名称并明确删除不可恢复。只有没有任何外键引用时服务端才允许删除；若被引用，停止重试并建议停用。
7. 修改编码规则前读取当前参数页面展示的规则，说明新旧开关、前缀、位数的变化与影响。取得确认后调用 `color_set_code_rule`。
8. 超时或响应不明确时先用 `color_list` 核对结果再决定下一步，不盲目重复新增或删除。逐项汇报成功和失败原因。

## 边界

- 屏幕色值为空是合法状态；提供色值时格式为 `#RRGGBB`。
- 物料可以关联多个颜色，但不要为每种颜色重复创建整份物料档案。
- 采购/BOM 行上的实际颜色选择与库存批次的实物颜色、缸号和供应批次属于对应业务，不从颜色主档推断。
- 编码、名称不区分大小写唯一；自动生成关闭后新增必须手工提供编码。
- 不绕过服务端权限、唯一性、外键引用保护或业务审计。

# 尺码管理

## 当前接入状态

- 功能状态：尺码管理已由用户验收通过（2026-11-04）。
- REST API 契约：[尺码管理 API](../../API/尺码管理API.md)。
- MCP 工具：尚未注册，契约里列出的 `size_*` 名称目前不可调用。
- **未接通 MCP/动作目录时，不得直接从 Skill 调用 REST 路由或数据库；应说明当前无法代操作，并引导用户在 ERP 页面操作。**

## 适用范围

- 管理尺码档案（编码、名称、英文名称、排序、备注、状态）。
- 查看尺码档案及已关联的类型标签。
- 给单个或多个尺码设置类型标签。
- 按明确请求调整尺码自动编码规则。
- **不管理尺码组**。尺码组功能尚未通过用户验收，不使用本 Skill 处理。

## 执行剧本

### 查询

1. 用户询问当前尺码、尺码编码、状态或类型标签时，调用 `size_list`。
2. 按编码、名称、状态或标签筛选结果；不要自行推断缺失字段。
3. 返回简洁列表，包含用户关心的字段；停用项标明“停用”。

### 新增或修改

1. 收集并复述编码（可留空使用自动编码）、名称、英文名称、排序、备注、类型标签。
2. 新增时检查是否明确要求手动编码；若未提供编码，依当前已配置规则自动生成。
3. 修改时先查询并确认目标尺码唯一；保留用户未要求改变的字段。
4. 展示完整变更内容并等待用户确认。
5. 确认后调用 `size_create` 或 `size_update`，以响应为准回报结果；失败时原样解释业务原因，不重试可能产生重复新增的请求。

### 批量替换类型标签

1. 查询尺码并确认目标尺码清单，最多 500 条。
2. 确认目标类型标签清单。该操作是**替换**：旧标签会全部移除，再应用新标签；空标签清单会清除所选尺码全部类型标签。
3. 明确展示影响尺码数量和最终标签集合，等待用户确认。
4. 确认后调用 `size_batch_set_tags`，成功后报告数量；若响应失败，先重新查询核对，不盲目重试。

### 启用或停用

1. 查询并确认目标尺码。
2. 说明启停结果：停用不清除历史关联，已被尺码组引用的尺码仍保留在原组，但不能新增引用。
3. 展示目标尺码编码、名称和目标状态，等待用户确认后调用 `size_set_status`。

### 删除

1. 查询并确认目标尺码编码和名称。
2. 说明删除不可恢复；被任何尺码组引用的尺码会被后端拒绝删除。禁止为完成删除而自动修改或删除尺码组。
3. 必须取得本次操作的明确确认后才能调用 `size_delete`。
4. 若后端提示仍被尺码组引用，停止操作并告知用户，不尝试绕过校验。

### 修改自动编码规则

1. 仅当用户明确要求修改时处理；先用 `size_get_code_rule` 读取现行规则，再收集启用开关、编码前缀、数字位数（1–10）。
2. 说明规则只影响以后新建尺码，不会修改已有编码。
3. 展示原规则和完整新规则并等待用户确认；必须具备 `system:config:edit` 后才调用 `size_set_code_rule`。

## 边界处理

- 同名或重复编码由后端校验；收到重复错误后停止，不换编码或名称替用户重试。
- 尺码删除受尺码组引用保护；禁止自动清理或改动引用它的尺码组。
- 标签必须属于尺码标签命名空间且可用；不要将其他功能标签迁入尺码。
- 不把尺码组的实现或本文存在解释为尺码组已验收。
- 在 MCP 工具未注册前，本文件仅为智能体 Skill 契约草案，不可执行。

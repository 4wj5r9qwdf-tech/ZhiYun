# Skill：新建小组（group_create_flow）

> 版本：v1
> 更新日期：2026-10-26
> 类型：**业务动作编排**（步骤顺序锁死，不靠模型临场决定——《内嵌智能体规范.md》七）
> 依赖能力：[MCP tool `group_create` / `group_list`](../../mcp-server/README.md)；契约见 [Docs/API/小组管理API.md](../API/小组管理API.md)
> 状态：契约已定稿；**待 agent 对话壳选型后按本文件加载执行**

---

## 一、动作定义

| 项 | 内容 |
|---|---|
| 动作名 | 新建小组（挂到指定上级下） |
| 触发场景 | 员工说"建一个XX组，挂在XX下面""新增小组：1车间裁剪3组"等 |
| 权限要求 | 员工具备 `system:dept:add`（无权限时该 Skill 不出现在动作集——《内嵌智能体规范》四.2） |
| 留痕 | 后端 `@Log(部门管理, INSERT)` 记操作人 = 员工本人工号（不记 AI） |
| 涉及 tool | `group_list`（只读校验）→ `group_create`（写）→ `group_list`（回读确认） |

## 二、输入（从员工话术中提取，缺项必须追问，不许猜）

| 参数 | 必填 | 说明 |
|---|---|---|
| dept_name | **是** | 小组名称（≤30 字符）；同级重名会被后端拒 |
| parent | **是** | 挂靠上级：员工说的部门名/小组名 → 经 `group_list(dept_name=...)` 解析成 dept_id；**同名多条时列出候选让员工选，不许擅自挑** |
| order_num | 否 | 默认 0 |
| status | 否 | 默认启用（'0'） |

## 三、执行步骤（顺序锁死）

```
步骤① 解析并校验挂靠上级
  tool: group_list(employee_token, dept_name=<员工说的上级名>)
  - 命中 1 条 → 记 parent_id，继续
  - 命中 0 条 → 停，回复"没找到叫 X 的部门/小组，可用的有：…（列前 10 个）"，等员工重述
  - 命中多条 → 停，列出候选（名称+层级路径），等员工指定

步骤② 创建
  tool: group_create(employee_token, dept_name, parent_id, order_num)
  - ok=true → 进步骤③
  - ok=false → 停，把 msg 原样告知员工（常见：部门名称已存在 / 不允许重复提交，请稍候再试 /
    没有访问权限 → 该员工无 system:dept:add，动作本不该出现在动作集，出现即为壳的过滤缺陷，记录告警）
    ※ "不允许重复提交"时不得立刻重试——先走步骤③回读确认是否已建成，避免双建

步骤③ 回读确认（create 不回包新 ID，必做）
  tool: group_list(employee_token, dept_name=<新名>)
  - 取唯一命中行，得到新 deptId + ancestors
  - 用 ancestors 拼层级路径（每段 id → group_list 全量映射名称，">" 连接）
  - 多条同名（重名历史数据）→ 以 parentId == 步骤①的 parent_id 为准

步骤④ 结果回显（给员工的固定文案模板）
  ✅ 已新建小组「{deptName}」
     挂靠：{上级名}（层级路径：{A > B > C}）
     层级：{N} 级　状态：{启用|停用}　ID：{deptId}
```

**禁止事项**
- 禁止跳过步骤①直接创建（上级名必须先解析成 ID）
- 禁止跳过步骤③就回复"已创建"（create 无回包，不回读无法确认落库）
- 禁止用超管/他人 token 代执行；`employee_token` 恒为发起员工本人
- 禁止改写后端失败 msg（原样透传，不许"翻译"成成功）

## 四、边界与例外汇总

| 情形 | 处理 |
|---|---|
| 上级是另一个小组（二级小组） | **允许**，正常执行 |
| 同级重名 | 后端拒（msg 透传）；提示员工换名或改用"编辑" |
| 间隔内重复提交 | msg 透传；转步骤③回读判断是否已建成 |
| 员工无 add 权限 | 动作集里就不该有本 Skill；若仍被调用 → 透传 403 并记录壳过滤缺陷 |
| 上级名歧义（多条同名） | 列候选等员工选，不擅自决定 |

## 五、后续可扩展的同族 Skill（验收后逐个补）

- 编辑小组（换挂靠上级/改名/换负责人）→ `group_update`（注意改 parent 会级联重算层级）
- 删除小组 → `group_delete`（先查有无下级/人员，给员工预检提示）
- 调整小组负责人（选人）→ `group_update(leader=user_id)`

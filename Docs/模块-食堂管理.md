# 模块-食堂管理

> 版本：v1（定稿）
> 更新日期：2026-10-23
> 说明：织云 ERP 食堂管理模块。地基引用 地基/属性标签（食堂/桌位可扩展属性）；与 模块-宿舍管理（早饭关联）、模块-人员管理（钉钉到岗/外包人员）联动。

---

## 〇、前提与范围
- 现状：一个食堂（1 楼），1 个大堂 + 2 个包间；食堂老板 + 帮厨；早中晚**定好菜单、轮换、不支持点菜**。
- **食堂实体可多个**（厂在扩，后期加层/加新楼栋食堂 = 新增食堂实体，不改表结构），挂"食堂 → 楼层/档口 → 桌位"三层。
- 费用：当前员工**免费**吃饭；是否给食堂补贴见第五节（按"外包/自营"切换口径）。

## 一、菜单（今日菜单可见，难点3）
- **菜单轮换库**：早/中/晚各列菜品，按天轮换，食堂老板维护。
- **今日菜单可见**：员工端（对话界面/看板/某处入口）能看"今日早中晚各是啥菜"；支持智能体答"今天中午吃啥"。
- 菜单按食堂实体组织（多食堂时各看各的）。

## 二、报备制（难点1 + 早饭关联宿舍）
- **报备入口 = Web 后台 + 小程序 两端都要**。
- **午饭**：按"钉钉当日到岗"自动汇总备餐人数（难点2），老板可当日微调、留痕；也可用报备覆盖。
- **早饭：不按员工单独报备，按【住宿人员】来**（跟宿舍模块联动）：
  - 早饭人数 = 宿舍"在住房间/床位 有人"的员工数（读 模块-宿舍 的入住状态）
  - 即**住宿者才有早饭报备/备餐**，不住厂的人不算早饭
  - 这条把早饭直接接上宿舍入住状态，不另做"员工报早饭"
- ****报备报表**：给"组内 + 食堂"看（谁报了/没报/预计几人），汇总给食堂备餐、给组内核对。
- **提醒规则：当天报当天，不提前 N 天**。每天 **15:00** 自动提醒"次日/当日未报备"的人 + 食堂（15:00 可配）。即"今天 15:00 报明天"这种，当天补报当天。
- **未报备直接去吃的处理**：现场登记"漏报"，**累计漏报 → 预警提醒**（默认不罚钱，只做统计+提醒；是否按次轻罚=开关，默认关）。

## 三、桌位 / 包间（难点4，走 地基/属性标签）
- **桌位档案**：大厅/包间、桌号、可坐几人、状态（空/占用/预留）。
- **包间可预留**：给部门饭/客户饭/会议订（预留走审批？待定，一期先登记预留）。
- 桌位/包间属性走 `食堂.` 前缀标签（`食堂.大桌`/`食堂.可包`…，自由文本+常用词提示）。
- 一期最简：桌位台账 + 包间预留，不做实时占座。

## 四、采购 / 消耗品记录（新增，你补的）
- **食堂采购记录**：买了什么（米/面/油/肉/蔬菜/消耗品）、数量、金额、供应商/批次、日期。
- **消耗品记录**：日常消耗（油盐酱醋、清洁消杀用品…）登记。
- 用途：算"食堂每日成本"（补贴对账、采购分析）；是"外包补贴按人头"还是"按实际成本"的基数。
- 先做**登记**（记清楚买了/耗了什么），成本核算/对账二期再深。

## 五、费用口径：外包/自营 开关 + 食堂人员必有账号

- **食堂老板/帮厨一律建系统账号**（要有身份：能被提醒、能操作、语音代办时认人），**不区分外包自营都建**。
- **发不发工资 = 开关切**（食堂实体级配置 `食堂用工性质`）：
  - 开关=**自营**：老板/帮厨算公司正式员工 → **进工资**（走 人员管理 发薪/考勤）；员工免费吃，**不给食堂补贴**。
  - 开关=**外包**：老板/帮厨是食堂承包人 → **不进公司工资**（他们自己管自己）；公司按"就餐人数×单餐标准"给**食堂补贴**（预留财务对接）。
- 即：**账号人人有，工资看开关**。改开关 = 换口径，不删账号、不动历史。
- **档口制**（外包更常见）：食堂实体下挂多个档口（快餐/面食/清真…，不同承包人做不同品类），各档口独立核算/独立补贴；档口走 地基/属性标签 `食堂.档口`。自营一般不分档口。

## 六、清洁 / 消杀（你补的 6，开关不强制）
- **食堂清洁/消杀记录**：谁、哪天、做了哪些清洁/消杀项（可配清单），登记留痕。
- **做成开关，不强管控**：开=必须登记/到期提醒；关=可登记不强制（"搞出来但不能强管控"，同你一贯风格）。
- 消杀超期 → 走统一预警（可配）。

## 七、后期预留（你说"做好对接刷卡的预留"）
- **刷卡/脸刷对接口子**：预留"消费流水表"（谁/哪天/哪餐/金额），一期金额=0（免费），接刷卡机后往这表填钱。
- **收费开关**（默认关）：开=将来"食堂收费/自费"，不用改表。
- 一期只做管理功能（菜单/报备/桌位/采购/清洁），**不做真刷卡扣款**。

## 八、智能体便捷化（食堂人员不用系统，语音代办）

> 背景：食堂老板/帮厨**不会用、也不该让他们硬用**系统。走内嵌智能体（《内嵌智能体规范》）语音/文字代办，食堂人只"说话+确认"，重活系统干。

- **食堂人员可语音问/代办**（智能体按"食堂权限"过滤，只对食堂岗开）：
  - 问："今天什么菜" → 答今日菜单（早中晚）
  - 问："今天用了什么东西" → 答今日消耗/领用（油盐酱醋等）
  - 问："今天采购了什么" → 答今日采购记录（买了啥/数量/金额）
- **代填报备/代填采购/代填消耗**：食堂人语音报数，智能体**先填成草稿 → 食堂人确认 → 才生效（审核）**。
  - 关键：**"食堂的人确认了再审核"**——智能体只代填、不直接生效，本人语音/点一下确认，动作才落库（防代填错、也留痕"谁确认的"）。
  - 确认人记的是**食堂本人**（对应权限红线：智能体以该员工身份操作，不记"AI"）。
- 一句话：**食堂人负责"说 + 确认"，智能体负责"填 + 查"，系统负责"记 + 留痕"。** 便捷化 = 让不会用系统的人也能把食堂管起来。

## 九、与地基/其他模块的接口
- 早饭人数 ↔ 模块-宿舍（在住房间/床位）
- 午饭备餐 ↔ 钉钉到岗（人员管理）
- 外包人员/补贴/档口 ↔ 人员管理/财务
- 桌位/包间/档口属性、清洁项 ↔ 地基/属性标签
- 补贴/采购成本/收费 ↔ 财务（预留接口）
- 食堂人员语音代办 ↔ 内嵌智能体规范（代填+本人确认+权限过滤）

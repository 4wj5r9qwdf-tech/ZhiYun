# 智能体框架评估（内嵌智能体"壳"选型）

> 版本：v1（评估稿，待拍板）
> 更新日期：2026-10-30
> 依据：《内嵌智能体规范.md》第五节（壳不是钥匙 + 三条选型红线）、技术边界共识（规则优先、不上优化求解）
> 范围：对话管理 / 工具编排的"壳"选型；模型网关（LLM/TTS/ASR/EMB 多套 OpenAI 协议）与 RAG 索引方案不受框架影响，按规范执行

## 〇、结论速览

**推荐 SnailAI（底座 RuoYi-Vue-Plus 自带，snail-ai-starter 1.1.1 / opensnail 项目）**，配 3 项合规配套落地。
理由：底座已铺好全部路（桥接控制器、23 张 `sai_*` 表已建库、app-id/令牌模板已配、chat 内嵌 UI 现成），零新增依赖、RAG 与 pgvector 方案天然吻合；代价是多跑一个服务进程，且两条红线需要我们在架构层补配套（见 §3）。
**备选 Spring AI 内嵌**（触发条件：不想维护多一个进程、或要"按单个员工"而非"按角色"过滤工具集）；**不推荐 Dify/FastGPT 类独立平台**。

## 一、候选与现状盘点

### 1.1 SnailAI（底座自带，当前"未实装"状态）

仓库内资产：
- `ruoyi-extend/ruoyi-snailai-server/`：独立服务端（HTTP 8900 context=/snail-ai + gRPC 18888），内含现成 chat 管理前端（静态资源）
- `ruoyi-modules/ruoyi-ai/`：ERP 侧桥接（`POST /snail-ai/user/register` 把当前 ERP 登录用户注册为 SnailAI OpenAPI 用户，externalId=ERP user_id），受 `snail-ai.open-api.enabled` 开关控制
- 23 张 `sai_*` 表已随框架 SQL 建好（`postgres_ry_ai.sql`），当前种子数据：agent=1 / model=1 / user=1（框架默认模板）

当前部署状态：**未实装**——`application-dev.yml` 里 `snail-ai.enabled: false`，start.sh 不含该服务，docker 里没有它；数据源模板指向 MySQL `ry-vue`（未改）。

能力面（按库表结构归纳）：

| 能力 | 载体 | 说明 |
|---|---|---|
| 智能体 | `sai_agent` | 每 agent 独立挂：LLM（chat_model_id）、记忆开关+窗口、MCP 开关、Skill 开关、联网开关、RAG（rag_ids+调用模式）、预设问题、多应用（app_id） |
| MCP 工具 | `sai_mcp_server` + `sai_agent_mcp_server` | 注册任意 MCP server（transport_type/base_uri/endpoint 或 command/args 本地 stdio，headers/env/超时）；agent↔MCP 多对多 = 每 agent 一个静态工具集 |
| Skill | `sai_skill` + `sai_skill_file` + `sai_agent_skill` | 技能包（文件型指令），agent 级关联；服务端有 skill 上传目录 |
| RAG | `sai_rag` / `_chunk` / `_document` / `sai_store_instance` | 文档解析（docling+OCR）→ 切块向量化；向量库类型含 **PG_VECTOR / MILVUS / ES / PG_FULLTEXT**；去重策略/上传确认等配置齐全 |
| 用户/配额 | `sai_user` / `sai_agent_usage_stat` | OpenAPI 用户（角色 0/1 + 配额），按 agent+user 用量统计 |
| 对话 UI | 服务端内置前端 | 内嵌模式可配：隐藏顶栏/侧栏、智能体市场开关、锁定 agent（适合 iframe 进 ERP 智能体页） |

### 1.2 Spring AI（备选，仓库无存量）

Java 侧内嵌进 ERP 进程：对话管理、MCP client（工具集可在调用时按"当前员工"动态过滤）、RAG 完全自研（pgvector+EMB 网关，与规范 §6 一致）。零新进程；代价是对话/Skill/UI 全要自建，且新依赖进底座 jar（RuoYi 升级冲突面变大）。

### 1.3 Dify / FastGPT 类（不推荐）

独立低代码平台：功能全，但身份/权限体系在对方（API key 粒度），"按员工身份过滤工具集"做不到（R2 不达标）；RAG 两套体系；引入 Python 运维栈。与"智能体是员工权限的放大器"的立场冲突。

## 二、三条红线逐条核对（SnailAI）

| 红线 | 结论 | 依据与落地方式 |
|---|---|---|
| ① 能接自定义 MCP 工具 | ✅ 直接过 | `sai_mcp_server` 支持注册任意 MCP server（远程 HTTP/SSE 或本地 stdio 命令）。ERP"面向动作 API"封装成一个（或按模块几个）MCP server，注册进 SnailAI 即可，不需要框架认识 ERP |
| ② 按调用方身份动态过滤工具集 | ⚠️ 需架构层配套 | 框架的工具集粒度是 **agent**（静态 agent↔MCP 关联），没有"按调用员工在调用时刻过滤"的内置开关。**落地**：ERP 建 `sys_role_agent(role_id, agent_id, del_flag)` 映射（角色→agent，一个角色一个 agent，该 agent 的 MCP 工具集 = 该角色权限过滤后的动作集）；桥接层把 ERP 登录人按其角色选出对应 agent，超管账号走全能力 agent。效果等价于"无权限不出现"，代价是变更频率=角色调整频率（低频，可接受）。 |
| ③ 框架不内置直连数据库 | ⚠️ 条件过（部署约束） | SnailAI 是独立进程，本身没有"连 ERP 业务库"的默认行为——但它的**数据源**由部署方配置，模板默认 MySQL ry-vue，我们没有部署过。**落地**：部署时给 snailai-server 专用 PG 账号（仅授权 `sai_*` 表或独立 schema），**禁止**使用 zhizhun 业务账号，杜绝壳拿业务表万能钥匙。 |

### 附加合规点（与规范的其他节交叉检查）

- **密钥落点**：`sai_model_config.api_key/api_endpoint` 把模型密钥存在 AI 服务自己的库里。与规范 §2"密钥只进 .env"的口径需要一条例外说明：**模型密钥放 AI 服务的独立库（专用账号可见范围），ERP 业务库与 .env 不存**；且 snailai-server 的 `snail-ai.crypto.secret-key` 模板有默认值，**部署时必须改**（`SNAIL_AI_CRYPTO_KEY/IV` 走 .env）。
- **RAG 方案吻合**：`sai_store_instance.type` 原生支持 PG_VECTOR（影子索引建在主库，零额外组件，比规范 §6 当初的 Chroma 更进一步）+ PG_FULLTEXT（全文降级路径 `EMB_FALLBACK_FULLTEXT=1` 可直接用它的类型切换）。
- **语音链路不冲突**：ASR/TTS 前端直连网关（规范 §3），对话壳只收文字意图、编排工具调用，互不干扰。
- **留痕**：`sai_agent_usage_stat` 有 agent×user×日 的用量；"操作人记员工工号不记 AI"由 ERP 侧执行——工具调用落回 ERP 动作 API 时按 ERP 登录态执行（桥接层透传 externalId），满足 §4。

## 三、结论与落地路线（待拍板）

**拍板项**：是否采用 SnailAI 作为对话壳（= 推荐）；`sys_role_agent` 映射放哪（角色管理页加"AI 智能体"配置项 vs 独立小页）。

若采用，落地顺序（每步独立可验证）：
1. **部署 snailai-server**：数据源改 PG **专用账号**（权限只到 `sai_*` schema/表）；`SNAIL_AI_CRYPTO_KEY/IV` 进 .env；start.sh 增加启停（与后端/前端并列，持久终端或容器）
2. **打通桥**：`snail-ai.enabled: true`；`/snail-ai/user/register` 联调（ERP 登录人 → sai_user）
3. **模型网关**：在 SnailAI 模型配置里录入 LLM/EMB 的 OpenAI 兼容端点（.env 的 `LLM_1_*`/`CODEX_CLI_*` 同批网关，密钥走 §2 附加合规点口径）
4. **首个 MCP server**：把 ERP 动作 API 封装成 MCP（先接只读类：查库存/看板/查单据），注册 + 挂到默认 agent
5. **角色映射**：建 `sys_role_agent` 表 + 角色管理"选 AI 智能体"，按角色建 agent（工具集=该角色可见动作）
6. **前端智能体页**：ERP 内 iframe 嵌 SnailAI chat（内嵌模式：锁 agent/隐藏壳 UI），语音 ASR/TTS 直连网关
7. **登记**：按规范 §5.4 写进《开发日志.md》（框架/版本/MCP 工具清单/权限接法）

## 四、触发切换备选（Spring AI）的条件

出现以下任一情况，重新评估换 Spring AI 内嵌：需要**按单个员工**（而非角色）过滤工具集；不想维护第 4 个常驻进程；SnailAI 升级与 RuoYi 底座版本冲突无法解。

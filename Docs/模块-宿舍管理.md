# 模块-宿舍管理

> 版本：v1（定稿）
> 更新日期：2026-10-23
> 说明：织云 ERP 宿舍管理模块（当前一栋楼、四层）。地基引用 地基/员工ID与工号、地基/审批与预警；与 模块-人员管理 的"住宿挂钩"接口对接。

---

## 〇、前提与范围（引用 地基/属性标签 做房间可扩展属性）
- 现状：一栋宿舍楼、四层；**按楼层分配男女**，房间有 单间/双人间/多人间。
- 管理粒度：**到床位**（不是到房间）。房间人数、床类型**支持编辑**（一间房可改配大床/标间、可改能住几人）。
- 物品：宿舍内公司配置的物品纳入管理——**可流通类**（钥匙，一人一把、会流转）、**固定绑定房间类**（床、桌、柜子，固定在房间）。
- 门禁：刷脸门禁，**一期先做"登记"**（记录是否已录人脸），真对接（ERP 下发/撤销人脸）二期再谈。

## 一、数据模型

### 1.1 房间 / 床位（楼层/房间/床位 均自填，不写死）
- **楼 / 楼层 / 房间号 / 床位号 全部由管理端自己填**（不写死"就一栋四层"），支持建多栋/多层/多房间/多床位，扩厂不改表。
- **房间**：楼层 / 房间号 / 性别倾向（男/女/不限）/ 床位数 / 状态（空/有人/锁定）。
- **房间标签（可扩展属性，引用 地基/属性标签）**：前缀 `宿舍.`，自由文本 + 常用词提示（双人/夫妻/独卫/无烟…）。原"房间类型"硬枚举**改为标签**，加新属性不动表结构；夫妻房 = 贴 `宿舍.夫妻` 标签，性别隔离提示时读它决定跳过。
- **床位**：属于某房间，床位号 / 床类型（大床/标间等，**可编辑**）/ 是否有人 / 入住人（挂员工ID）。
- **客户/访客住宿**：入住人**不强制是员工**，可挂"外部人员"（客户/访客，单独登记，不走员工ID 那套），支持"客户住几天"的临时住宿。
- **床类型支持编辑**：同一间房可改配大床/标间，改床型/改可住人数即时可编辑（不锁定）。

### 1.2 物品档案
- **可流通（钥匙）**：一人一把，走"号段池"逻辑（领/还/丢失补领），挂持有员工ID。
- **固定（床/桌/柜）**：绑定到房间，记录 所在房间 / 数量 / 状态（在位/缺失/损坏）。

## 二、入住流程（员工来了）
1. **是否住宿**：入职/档案里选"是否住宿"。选"是" → 触发提醒：
   - **给宿管 / 行政（可指定岗位或人员）发"待分配床位"代办提醒**（统一预警机制），谁指定就提醒谁。
2. 宿管开**分配单**：选楼层(男女) → 选房间 → 选床位 → 分配给该员工。
3. **性别隔离 = 提示**（不硬卡）：跨性别层/跨性别楼层 → 黄字提醒但不拦。
   - 原因：**有的多人间是给夫妻同住**的（夫妻房），性别隔离不能写死。
4. **录入人脸**：一期登记"是否已录人脸 + 录入时间"（真对接下发/撤销人脸=二期）。
5. **分配钥匙**：一人一把，从号段池领，挂该员工。
6. **检查物品初始状态**：入住前把该房间床/桌/柜**点一次**（初始清点：在/不在/好/坏）。
7. **确认入住**：床位→有人，房间→锁定"有人"状态；记录 入住时间、入住员工ID。

## 三、退房 / 离职流程（员工走了）
1. 离职触发提醒：**给宿管 / 行政指定岗位或人员发"待退房"提醒**。
2. 开**退房单**：
   - **交还钥匙**：登记已还/未还；
   - **检查物品终态**：退房时再点一次床/桌/柜（终清点）；
   - **取消人脸**：一期登记"已取消人脸"（撤销=二期）。
3. **物品损坏定责赔偿**：入住初始清点 vs 退房终清点，**两次对比**，缺/坏的定责（谁入住谁负责，或按规则），记**赔偿**（金额，接口预留财务）。
4. 床位→空、房间状态更新；钥匙释放回池子。

## 四、钥匙流转（细化）
- 一人一把；领/还/丢失补领走号段池。
- **补领收费**：**由行政或宿管管理**（补领单他们发起/核），**金额人为填写**（不填或填 0 = 不收）；补领费用**账到财务**（预留财务对接口子）。
- 钥匙记录挂员工ID（历史可查谁领过哪把、何时）。

## 五、查询
- **按房间查人**：某房间住了谁（床位维度）。
- **按人查房间**：某员工住哪个房间哪个床位（挂员工ID 反查）。
- 房间/床位状态总览（空/有人/锁定）。

## 六、费用（当前免费，收费预留）
- **现状：宿舍免费住**，不做费用、不碰财务。
- **收费功能加进来、默认不开启**：预留"是否收费 + 金额/口径"字段与开关；默认关（免费）。
- 开启后 → **预留财务对接接口**（宿舍费进扣款/对账，跟财务模块收口接上），一期不实现真扣款。

## 七、提醒汇总（统一预警机制）
| 触发 | 提醒对象 | 说明 |
|---|---|---|
| 选"住宿" | 宿管/行政（可指定岗位或人） | 待分配床位 |
| 离职 | 宿管/行政（可指定岗位或人） | 待退房 |
| 钥匙丢失 | 宿管/行政 | 待补领 |
| 物品损坏 | 宿管/行政/定责人 | 待处理赔偿 |

- 提醒对象**可配到岗位或到指定人**，走 地基/审批与预警 的统一预警表。

## 八、与地基/其他模块的接口
- 员工ID/工号：见 地基/员工ID与工号（入住退房记录挂员工ID）
- 人员管理"住宿挂钩"：是否住宿字段 ↔ 本模块床位
- 审批/预警：入住退房提醒、物品/钥匙提醒 → 统一预警
- 财务：赔偿金额、(预留)宿舍费 → 财务收口接口
- 门禁：一期登记，二期对接下发/撤销人脸

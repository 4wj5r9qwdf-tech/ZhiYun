## 〇、地基依赖（先读，本模块全部遵守）

- 主键/查询/历史记录：见 `地基/员工ID与工号.md`（员工ID 不变、工号六位可变可回收、操作流水只存ID、单据存当次工号快照、集中套壳只查当前号）
- 岗位/角色/数据范围：见 `地基/权限与组织树.md`（岗位→默认角色→组织树数据范围；一人主岗1+叠加N角色+挂1组织节点）
- 审批、预警：见 `地基/审批与预警.md`（入离职/调组走审批；证件到期/社保核对超期走统一预警表）
- 岗位字典：以《服装加工厂岗位列表.md》为准（裁剪/缝纫/后整/质检 等 13 组），本模块不另造岗位名

## 一、模块边界（做什么 / 不做什么）

**做**：员工全生命周期（入职/在职/离职）、组织隶属、岗位角色、考勤（钉钉）、社保登记、住宿挂钩接口、劳务工身份。
**不做**：宿舍床位/费用（归 模块-运营.md，本模块只留"是否住宿+床位关联"接口）；工资核算（归 生产流程规划 15.15.12 的工价/月度核算，本模块只喂"人头+考勤+加班+社保登记"）；钉钉考勤机硬件（第三方，本模块只对接数据）。

## 二、员工档案（一个员工一张卡）

| 字段组 | 内容 | 说明 |
|---|---|---|
| 身份 | 员工ID（主键不变）、工号（六位、可变）、姓名、性别、身份证号、手机号 | 身份证号/手机号按"敏感信息"规范，可脱敏展示 |
| 组织隶属 | 车间、工种、小组、岗位（→默认角色） | 调组改这里，**工号是否变按地基规则**；数据权限随组织节点 |
| 状态 | 在职 / 离职 / 长假 / 试用 | 状态机：试用/在职/离职/长假；临时工同表，岗位区分 |
| 合同 | 用工性质（正式/临时，临时工=岗位）、合同起止日期、签约主体 | 临工标记在此 |
| 技能 | 会哪些工序（吊挂报工/计件要用，关联工序档案） | 多对多，供 15.15 派工/报工 |
| 证件 | 健康证/电工证等 + 到期日 | 到期进统一预警表（证件预警） |
| 住宿 | 是否住宿 + 关联床位（指 模块-运营 宿舍） | 不住厂留空，不强制 |
| 社保 | 见第五节"社保登记单" | |

**临时工（岗位制，简化）**：临时工**不单独建身份/表**，就在员工档案表加一个岗位"临时工"（跟正式工同表）。
- **工号照领照用、走了不用改**：临时工从对应车间/组号段领一个号（与正式工同规则）；走人时号**释放回池子**，下个人接着用，**不做任何改号动作**。
- **历史不受影响**：临时工在任期间的记录全挂**员工ID**（不变），号给了别人也不影响查他旧数据（同 地基/员工ID与工号 规则）。
- **差异配置化**：临时工一般不缴社保、不住宿、按天/件计酬，用"岗位=临时工"走**差异配置**（哪个岗位走什么规则，配置化，不写死在代码里）。
- **临工协议/用工证明**：走"上传文档"挂该员工档案附件（不单独做劳务管理模块）。
- 走人 = 状态改"离职" + 号回池子，流程与正式工一致，无特殊工号逻辑。

### 一人多职位（岗位支持多个）
- 一个员工可挂**多个岗位/职务**（主岗 + 兼岗），不是只一个。例：既是车工、又兼小组统计；既是样衣工、又兼技术录工序。
- **每个岗位各带各的默认角色**（见 地基/权限与组织树），**最终权限 = 所有岗位对应角色的并集**。
- 组织节点仍只挂一个（主属），兼岗不另开组织节点（避免数据权限打架）；兼岗只加"能做那类事"的权限，不改变"他看哪个车间的数据"。
- 档案"岗位"字段从"单选"改"多选"（一个员工 N 个岗位，主岗标记一个）。
- 临工/临时岗 也是"多岗位"里的一种（岗位=临时工），同此机制。

## 三、入职 / 离职 / 调组## 三、入职 / 离职 / 调组

**入职**
1. 录档案 → 系统生成**员工ID**（建号定死）→ 分配**工号**（从对应车间/组号段池领一个空闲号，一期手填+唯一校验）
2. 选岗位（带默认角色）+ 挂组织节点（定数据范围）
3. 是否住宿 → 是则关联宿舍床位接口
4. **入职不挂审批**：录入/审核通过后即生效为"试用"状态，不做入职审批流
5. **转正（要）**：试用期满 → 系统**自动生成转正单据** + **给对应人员（人事/该员工/组长）发提醒**，核心目的是"防忘记"，不靠人盯
   - 单据记录：转正日期、试用起止、确认人；转正=状态 试用→正式
   - 提醒走统一预警/消息（复用 地基/审批与预警 的提醒机制）

**离职**
1. 发起离职（**保留审批**——离职要签核）→ 权限**即时收**（不能还能登录/操作）
2. 工号**释放回号段池**（标空闲，可给新入同段者复用）
3. 住宿=是 → 触发宿舍退床联动（模块-运营）
4. 员工ID 不变、状态=离职，**所有历史数据（报工/工资/考勤）保留可查**（靠员工ID）

**调组/调车间**
1. 改组织隶属字段（车间/工种/小组）；调组**暂不挂审批**（一期直接改，后期要再补审批）
2. **工号是否变**：按地基规则——跨组=原号释放、领新组段新号；同组内小调整工号可不变
3. 数据权限随新组织节点重算
4. **历史数据不受影响**（挂员工ID）；单据类记录用"当次工号快照"定格当时的号

## 四、考勤（钉钉为主）

**原则：考勤事实源 = 钉钉**（刷脸机接钉钉）。目标形态 = **钉钉 ↔ ERP 两条线并行打通**（员工两边都能打卡/请假/外出/调休，数据互相同步）。
- **结果进 ERP**：钉钉导表 / 钉钉开放平台 API 定时拉 → 打卡、请假、外出、调休结果进 ERP（钉钉→ERP）
- **申请回写钉钉**：ERP 内发的请假/调休/外出 → 回写钉钉（ERP→钉钉）
- **两条线并行、以钉钉为事实源**：任一端的打卡结果/加班时长按钉钉为准；ERP 只做申请入口+结果落库
- 考勤数据喂给工资核算（15.15.12）：人头 + 考勤 + 加班 三样输入
- 难度自知（双向同步最难）：架构上两条线都留接口，实现分期——先"钉钉结果进 ERP"（单向），再上"ERP 申请回写钉钉"（双向）

## 五、社保 / 商业保险（登记为主）

一张**社保登记单**挂员工档案下：

| 字段 | 说明 |
|---|---|
| 是否缴纳社保 | 是/否（临工可=否） |
| 是否有商业保险 | 是/否 + 险种 |
| 社保缴纳金额 | 元/月 |
| 社保补助金额 | 元/月 |
| 核对日期 | 何时核的（留痕） |

- **一期只登记、不算进工资**（工资核算读不读它留开关，二期再开）
- **核对预警**：核对日期超 N 个月未复核 → 进统一预警表（跟证件到期同一套机制）
- **预留对接**：先建"参保地/险种明细/发放银行"等列不填值；将来对接社保平台或做工资自动扣款时，表结构不动，只从"手填"变"拉数据"

## 六、住宿挂钩（接口，非本模块主体）

- 档案字段"是否住宿" + "床位关联"（指向 模块-运营 宿舍模块的床位档案）
- 不住厂留空；离职时"是否住宿=是" → 触发退床
- 宿舍的床位分配/调换/费用/访客，**全部归 模块-运营.md**，本模块只留这两个接口

## 七、与智能体的关系（引用《内嵌智能体规范》）

- 人事查询/录入动作 = MCP 工具，按该员工角色权限过滤（人事专员能改档案，车工只能查自己）
- 证件到期、社保核对超期 = 可主动推给相关员工/主管的对话预警

## 八、定稿确认（已定）

- 入职不挂审批（录/审后即试用）；**转正自动生成单据+提醒**（防忘记）；离职保留审批；调组暂不审批
- 考勤 = 钉钉 ↔ ERP 两条线并行打通（钉钉为事实源，申请回写钉钉）
- 社保当前只登记；能算进工资最好，但**扣减/补助算式待定**，预留开关+占位
- 临时工=加一个岗位"临时工"（不另建表/身份），**工号照领照用、走人不用改、号回池子复用**；差异（社保/宿舍/计酬）走岗位配置；协议走上传文档
- 证件到期/社保核对超期 = **系统自动判断**（阈值可配）→ 自动给**指定人员**（人事/对应主管）发提醒，复用统一预警机制

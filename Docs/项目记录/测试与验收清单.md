## 四、开发者测试与运行验证要求

- 新功能实现后，开发者/AI 先完成与本次范围相称的一轮构建、静态检查和自动化/功能测试，再交由用户进行业务验收。不得把代码检查或单元测试结果表述为用户验收通过。
- 用户验收后新增或修改的 Skill、MCP、API 契约和 Agent 配置，必须补做真实运行验证：检查注册/发现结果和输入 schema，使用实际权限上下文完成适用的读取或写入调用，核对结果、数据范围和业务审计。仅阅读 Skill、检查 JSON 或通过 mock 单测不算完成集成验证。
- 发现问题应先修复，再重跑失败用例及受影响回归。节省 token 或时间不能单独作为跳过相关验证的理由；测试范围应聚焦于本次改动及直接受影响功能，不要求无差别运行无关全量检查。
- 网页后台实际填报验证已获用户明确授权：相关功能可创建带明显测试标识的临时记录，实际提交并回读验证；不得覆盖或修改无关业务记录。仅清理本轮创建且确认安全可删的测试记录；付款、发货、通知等额外真实副作用仍需按业务风险单独控制。
- 外部环境不可用、测试账号/权限缺失或安全边界不允许时，记录具体阻塞、已完成验证和未测项，不得将静态检查推断为真实调用通过。

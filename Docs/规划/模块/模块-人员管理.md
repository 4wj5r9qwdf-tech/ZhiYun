# 模块-人员管理

> 版本：v1（主体需求已定，后续补充项见第九节）

> 说明：织云 ERP 人员管理模块需求。地基规则（员工ID/工号、权限组织树、审批预警）引用 `地基/` 与《术语词库索引.md》，本文件只写人员模块特有的需求。岗位清单以《服装加工厂岗位列表.md》为权威源。

## 〇、地基依赖（先读，本模块全部遵守）

- 主键/查询/历史记录：见 `地基/员工ID与工号.md`（员工ID 不变、工号六位可变可回收、操作流水只存ID、单据存当次工号快照、集中套壳只查当前号）
- 岗位/角色/数据范围：见 `地基/权限与组织树.md`（岗位→默认角色→组织树数据范围；一人主岗1+叠加N角色+挂1组织节点）
- 审批、预警：见 `地基/审批与预警.md`（入离职/调组走审批；证件到期/社保核对超期走统一预警表）
- 岗位字典：以《服装加工厂岗位列表.md》为准（裁剪/缝纫/后整/质检 等 13 组），本模块不另造岗位名

## 一、模块边界（做什么 / 不做什么）

**做**：员工全生命周期（入职/在职/离职）、组织隶属、岗位角色、考勤（钉钉）、社保登记、住宿挂钩接口、劳务工身份。
**不做**：宿舍床位/费用（归 模块-宿舍管理.md，本模块只留"是否住宿+床位关联"接口）；工资核算（归 生产流程规划 15.15.12 的工价/月度核算，本模块只喂"人头+考勤+加班+社保登记"）；钉钉考勤机硬件（第三方，本模块只对接数据）。

## 二、员工档案（一个员工一张卡）

| 字段组 | 内容 | 说明 |
|---|---|---|
| 身份 | 员工ID（主键不变）、工号（六位、可变）、姓名、性别、身份证号、手机号 | 身份证号/手机号按"敏感信息"规范，可脱敏展示 |
| 外部账号 | 钉钉账号绑定（后续接入） | 维护 ERP 员工与钉钉企业人员的对应关系；保存钉钉稳定人员标识，支持绑定/解绑校验与操作留痕。不是 ERP 登录主键，也不能用姓名模糊匹配 |
| **登录账号** | **建人员即建登录账号**（2026-10-24 用户定）：工号(6位)=登录用户名；默认密码 123456(BCrypt)；支持手机号(11位)登录；员工ID 不变工号可变 | 人员信息页直接录，**不做独立"用户管理"页**；账号状态随人员状态（离职即停用登录） |
| 组织隶属 | 车间、工种、小组、岗位（→默认角色） | 调组改这里，**工号是否变按地基规则**；数据权限随组织节点 |
| **角色** | **角色在人员信息里直接选**（2026-10-24 用户定）：一人主岗1+叠加N角色；内置仅"管理员"角色，其余角色后期用户在角色里手动建（不做预置） | 角色管理页归**系统模块**（基础配置下）；人员信息页只做"选角色"下拉 |
| **业务职责** | 可多选：业务员、跟单员、采购员、计划员、仓管员、质检员 | 只用于筛选单据责任人候选，不等同岗位、系统角色或新增/审核等权限；新增职责需同步业务选项与服务端校验 |
| 状态 | 在职 / 离职 / 长假 / 试用 | 状态机：试用/在职/离职/长假；临时工同表，岗位区分 |
| 合同 | 用工性质（正式/临时，临时工=岗位）、合同起止日期、签约主体 | 临工标记在此 |
| 技能 | 会哪些工序（吊挂报工/计件要用，关联工序档案） | 多对多，供 15.15 派工/报工 |
| 证件 | 健康证/电工证等 + 到期日 | 到期进统一预警表（证件预警） |
| 住宿 | 是否住宿 + 关联床位（指 模块-宿舍管理.md） | 不住厂留空，不强制 |
| 社保 | 见第五节"社保登记单" | |

**临时工（岗位制，简化）**：临时工**不单独建身份/表**，就在员工档案表加一个岗位"临时工"（跟正式工同表）。
- **工号照领照用、走了不用改**：临时工从对应车间/组号段领一个号（与正式工同规则）；走人时号**释放回池子**，下个人接着用，**不做任何改号动作**。
- **历史不受影响**：临时工在任期间的记录全挂**员工ID**（不变），号给了别人也不影响查他旧数据（同 地基/员工ID与工号 规则）。
- **差异配置化**：临时工一般不缴社保、不住宿、按天/件计酬，用"岗位=临时工"走**差异配置**（哪个岗位走什么规则，配置化，不写死在代码里）。
- **临工协议/用工证明**：走"上传文档"挂该员工档案附件（不单独做劳务管理模块）。
- 走人 = 状态改"离职" + 号回池子，流程与正式工一致，无特殊工号逻辑。

### 一人多职位（岗位支持多个）
- 一个员工可挂**多个岗位/职务**（主岗 + 兼岗），不是只一个。例：既是车工、又兼小组统计；既是样衣工、又兼技术录工序。
- **每个岗位各带各的默认角色**（见 地基/权限与组织树），**最终权限 = 所有岗位对应角色的并集**。
- 组织节点仍只挂一个（主属），兼岗不另开组织节点（避免数据权限打架）；兼岗只加"能做那类事"的权限，不改变"他看哪个车间的数据"。
- 档案"岗位"字段从"单选"改"多选"（一个员工 N 个岗位，主岗标记一个）。
- 临工/临时岗 也是"多岗位"里的一种（岗位=临时工），同此机制。

### 业务职责与单据责任人（2026-11-14）
- 人员档案中“业务职责”支持多选；一期职责码为 `SALES` 业务员、`FOLLOWER` 跟单员、`PURCHASER` 采购员、`PLANNER` 计划员、`WAREHOUSE` 仓管员、`QUALITY` 质检员。
- 业务职责回答“能否被选为某类业务单据的责任人”，不授予该模块的列表、新增、修改、审核、取消、数据范围等权限；仍须通过现有菜单/操作权限和数据权限。
- 客户档案业务员只可选在职且有“业务员”职责的人员；客户订单业务员/跟单员分别按“业务员/跟单员”职责过滤。后端保存接口重复校验，不能只依赖前端下拉过滤。
- 采购功能尚未实现。将来采购单的采购员只从有“采购员”职责的在职人员中选择；能否创建/提交/审核采购单仍按采购模块权限与流程判定。不得因有采购员职责自动赋予采购权限，也不得仅凭采购权限让没有采购员职责的人员作为单据采购员。
- 已有客户业务员、客户订单业务员/跟单员关联会在迁移时补相应职责，避免升级后旧记录失效。移除职责仅影响新选择；已有单据保留责任人快照/关联，历史数据不因此改写。

## 三、入职 / 离职 / 调组

**入职**
1. 录档案 → 系统生成**员工ID**（建号定死）→ 分配**工号**（从对应车间/组号段池领一个空闲号，一期手填+唯一校验）
2. 选岗位（带默认角色）+ 挂组织节点（定数据范围）
3. 是否住宿 → 是则关联宿舍床位接口
4. **入职不挂审批**：录入/审核通过后即生效为"试用"状态，不做入职审批流
5. **转正（要）**：试用期满 → 系统**自动生成转正单据** + **给对应人员（人事/该员工/组长）发提醒**，核心目的是"防忘记"，不靠人盯
   - 单据记录：转正日期、试用起止、确认人；转正=状态 试用→正式
   - 提醒走统一预警/消息（复用 地基/审批与预警 的提醒机制）

**离职**
1. 发起离职（**保留审批**——离职要签核）→ 权限**即时收**（不能还能登录/操作）
2. 工号**释放回号段池**（标空闲，可给新入同段者复用）
3. 住宿=是 → 触发宿舍退床联动（模块-宿舍管理.md）
4. 员工ID 不变、状态=离职，**所有历史数据（报工/工资/考勤）保留可查**（靠员工ID）

**调组/调车间**
1. 改组织隶属字段（车间/工种/小组）；调组**暂不挂审批**（一期直接改，后期要再补审批）
2. **工号是否变**：按地基规则——跨组=原号释放、领新组段新号；同组内小调整工号可不变
3. 数据权限随新组织节点重算
4. **历史数据不受影响**（挂员工ID）；单据类记录用"当次工号快照"定格当时的号

## 四、考勤（钉钉为主）

**原则：考勤事实源 = 钉钉**（刷脸机接钉钉）。目标形态 = **钉钉 ↔ ERP 两条线并行打通**（员工两边都能打卡/请假/外出/调休，数据互相同步）。
- **结果进 ERP**：钉钉导表 / 钉钉开放平台 API 定时拉 → 打卡、请假、外出、调休结果进 ERP（钉钉→ERP）
- **申请回写钉钉**：ERP 内发的请假/调休/外出 → 回写钉钉（ERP→钉钉）
- **两条线并行、以钉钉为事实源**：任一端的打卡结果/加班时长按钉钉为准；ERP 只做申请入口+结果落库
- 考勤数据喂给工资核算（15.15.12）：人头 + 考勤 + 加班 三样输入
- 难度自知（双向同步最难）：架构上两条线都留接口，实现分期——先"钉钉结果进 ERP"（单向），再上"ERP 申请回写钉钉"（双向）

## 五、社保 / 商业保险（登记为主）

一张**社保登记单**挂员工档案下：

| 字段 | 说明 |
|---|---|
| 是否缴纳社保 | 是/否（临工可=否） |
| 是否有商业保险 | 是/否 + 险种 |
| 社保缴纳金额 | 元/月 |
| 社保补助金额 | 元/月 |
| 核对日期 | 何时核的（留痕） |

- **一期只登记、不算进工资**（工资核算读不读它留开关，二期再开）
- **核对预警**：核对日期超 N 个月未复核 → 进统一预警表（跟证件到期同一套机制）
- **预留对接**：先建"参保地/险种明细/发放银行"等列不填值；将来对接社保平台或做工资自动扣款时，表结构不动，只从"手填"变"拉数据"

## 十一、钉钉账号绑定与审批消息（2026-11-15，后续集成规划）

- 人员档案需支持登记员工对应的钉钉账号。技术关联以钉钉开放平台的稳定企业人员标识（如 userId）为准，可同时展示便于管理员识别的钉钉账号信息；不得用姓名作为唯一关联依据，也不得替代 ERP 员工ID。
- 账号绑定、变更、解绑需检查人员状态、重复绑定及目标账号有效性，并记录操作审计；离职、停用人员不能继续作为新的审批通知接收人。既有审批历史仍按发起时的 ERP 员工身份保留。
- 接入审批通知后，当前审批节点产生待办时向对应审批人推送钉钉消息；通过、驳回、撤回、取消等审批结果通知发起人及流程配置的抄送人。系统站内通知继续保留，钉钉推送是额外渠道。
- 消息应支持回到对应审批办理页、审批进度或业务单据；打开后仍由 ERP 执行身份认证、权限及待办有效性检查。不能因收到钉钉消息而绕过 ERP 权限。
- 钉钉应用密钥等凭证使用服务端安全配置；推送经统一通知通道处理，支持幂等、结果记录、失败重试和告警。详细边界与审批事件清单以[审批与预警地基](../../地基/审批与预警.md)为准。
- 当前仅登记为后续规划，人员钉钉绑定界面、钉钉开放平台授权、消息发送和回跳均未实现。人员通讯录同步、考勤同步及钉钉内发起审批不在本项默认范围内。

## AI 沙盘相关人员资料补充（2026-11-19，规划待设计）

本节补充基础数据需求，具体字段、权限和业务规则进入人员与排班专项设计后确认，不表示功能已实现。人员仍使用稳定员工 ID 与现有组织、岗位、角色和管理范围。

- **人员标签分类**：复用“人员信息→标签分类→标签”，按实际业务可维护家庭情况、擅长工序工艺、擅长服装类型、设备操作能力、培训认证、工作时间偏好及其他分类。分类与标签由业务人员维护，不硬编码为固定清单。
- **技能及证据**：把工序、产品类型、设备经验与技能等级、认证、培训、历史报工、效率和质量关联，记录来源、验证人、有效期与最近复核时间。标签支持筛选，正式技能等级和计算口径由结构化记录确定。
- **周末及家庭照护场景**：员工可自主申报周六或周日通常需要照护家人、需提前协商等情况，维护人、可见范围、更新和撤回方式待专项设计。不得根据家庭信息推断个人情况。
- **长期偏好与具体日期分开**：周末通常不便加班是长期偏好，具体某一天是否可用以已确认排班、请假和其他正式记录为准。沙盘对无法确定的时间标“待确认”，列出影响；不能自动代请假、安排加班或推断已批准。
- **跨组支援**：关联当前组织、班组、岗位、技能、班次、已分配任务、正式请假、可支援时间以及原组最低保障规则，分别计算调出和调入对全部受影响订单的影响。方案先供有权人员确认并按既定流程审批。
- **权限**：家庭信息仅限授权人员查看，沙盘按最小必要原则使用可用、不可用或待确认等结果。部门/班组管理范围与角色权限共同生效，员工及管理人员自助维护边界待确认。


### 人员信息的标签分类与沙盘用途

人员信息功能内计划维护以下标签分类，名称和具体标签由业务配置，可按需要增减，不自动预置：

| 标签分类 | 示例和用途 | 配套核对 |
|---|---|---|
| 技能与擅长工序工艺 | 平车、包边、锁眼、钉扣、特殊面料加工；查找工序候选人员 | 工序主数据、技能记录与认证 |
| 工序熟练度与工作能力 | 初级、熟练、精通、多工序操作；识别技能结构 | 正式技能等级、审核证据、效率质量数据 |
| 服装类型经验 | 衬衫、裤装、羽绒服等；筛选相关产品经验 | 实际产品与订单记录 |
| 设备操作与培训认证 | 可操作设备、培训内容；匹配设备和资格 | 设备关联、认证有效期 |
| 工作时间与排班约束 | 周末可出勤、需提前协商、固定不可用时段 | 具体日期排班、任务及员工确认 |
| 请假与出勤状态 | 请假、临时不可排等可用于提示的分类 | 正式审批、实际出勤与生效时段 |
| 家庭情况自主申报 | 自主申报的照护安排，供授权人员维护 | 限制访问；沙盘仅取必要可用性 |

标签按人员信息功能归属，不以名称直接赋予技能等级或排产资格。AI 可结合报工、有效工时、质量、返工、工序难度及最近使用情况提出标签建议，关键认定由有权负责人按规则核实。周六日需要照顾孩子的情况由员工自主提供，偏好和某日已批准请假分别记录；未确定的排班标记待确认。具体标签维护和审核规则按人员专项设计。

# 衣拿吊挂 PO 识别打印工具一期方案

## 一、目标与范围

本方案规划一个独立运行的现场小工具，部署在织云一号车间当前使用的吊挂线服务器上。现场软件为衣拿 INA Hanger System（Chip Technology），用户提供截图显示版本 `7.42.35.10`。

工具直接读取对应吊挂产线的运行数据库，在尾查检验明确合格后，按配置的标签模板自动打印 PO 和成衣基础信息。标签字段由现场人员通过工具配置，不为每种字段布局修改程序代码。

一期主要解决多 PO 合并生产后的 PO 识别和尾查后自动出标。客户订单内不同 PO 默认对应不同交期；生产计划和吊挂线计划按 PO 识别。裁床仍可按实际情况合并多个订单、PO 和裁剪任务，不要求每床强制按 PO 拆分。

## 二、已确认的业务口径

1. 一个客户订单可以包含多个 PO；当前按一个 PO 对应一个交期/交付批次管理。
2. 当前口径下，吊挂 `TSPO_ID` 使用 PO 号。一个 PO 线计划可有多行颜色、尺码计划明细。
3. 2026-11-24 已用虚拟款号 `text261124` 验证同一个线计划号可以在衣拿计划选择页中显示多条颜色尺码行。验证样例为 2 种颜色 × 2 个尺码，共 4 行；这证明计划选择页接受同一计划号的多颜色尺码明细，不代表吊挂产线生产记录的回传字段已验证。
4. 挂片时由现场人员选择 PO 对应线计划；从此处开始，吊挂实际生产按所选线计划归集颜色、尺码和数量。
5. 尾查通过后触发打印；生产小组和尾查人员作为一期标签字段。下线时间也纳入可配置字段。
6. 一期不生成或打印每件成衣的唯一二维码，不提供 ERP 扫码后的单件履历，也不追踪全部工序的制作人员和制作时间。后续可另行规划单件追溯。

## 三、系统边界与数据流

```text
织云 ERP
  └─按 PO 生成线计划数据（同一 PO 号下可有多个颜色尺码行）
       └─沿现有衣拿导入方式进入吊挂系统

衣拿吊挂产线运行数据库
  └─吊挂线服务器上的 PO 识别打印工具只读本线数据库
       ├─识别尾查合格事件
       ├─读取标签配置所需字段
       ├─按源事件去重并进入本地打印队列
       └─通过本机打印驱动或配置的云打印服务打印标签

衣拿中继库（例如现有 IDS 数据库）
  └─继续供 ERP 适配器独立拉取业务数据；不参与一期现场打印触发
```

**吊挂产线运行数据库与中继库是两个数据源。**本工具的打印关键路径必须读取一号车间吊挂产线实际使用的运行数据库，不得把 IDS 中继数据库当作打印事件源。ERP 从中继库拉取生产记录仍按既有 ERP 对接规划独立运行。

本工具只读取衣拿数据库，不向厂商数据库写入打印状态、单件码或自定义字段。工具自己的连接配置、打印任务状态、错误和重打记录保存在本地受控存储中；如一期需要向 ERP 回传打印台账，另由 ERP 接口承接，不改写衣拿核心表。

## 四、现场业务流程

1. ERP 为每个 PO 下发对应的吊挂线计划；同一 `TSPO_ID` 下按实际计划数量分别维护各颜色、尺码行。
2. 挂片人员在衣拿吊挂软件中选择对应 PO 线计划并开始生产。
3. 工具从吊挂产线数据库监测配置的尾查工序及其检验结果；只有收到明确的合格结果才创建打印任务。返修、不合格、未检或状态未知均不自动打印。
4. 工具按合格数量生成标签任务。若源记录粒度是一件，则一条合格记录打印一张；若源记录代表多件，必须使用数据库明确的合格件数打印相同内容的相应份数，不得猜测件数。
5. 标签打印成功后，工具记录源事件、打印机、模板版本、份数、时间和结果。打印失败进入持久队列，恢复后按去重规则重试；人工重打须记录操作人和原因。
6. ERP 继续按其同步计划拉取中继库的吊挂记录。本期打印不等待 ERP 拉取完成。

## 五、标签字段与模板配置

工具提供标签模板配置界面。操作人员从经过映射和校验的吊挂数据库字段中选择打印项，并设置字段标题、显示顺序、位置、字号、对齐方式、条码/二维码类型、标签尺寸和打印机。配置界面展示字段中文说明及样例值；不开放任意 SQL 编辑，避免配置误查或修改生产数据。

一期建议提供以下可配置字段，具体名称和来源以吊挂产线数据库现场核对结果为准：

| 标签字段 | 业务含义 | 数据来源要求 |
|---|---|---|
| PO/线计划号 | 识别该成衣对应的 PO | 挂片所选线计划及其在产线记录中的回传值；需实测是否等于 `TSPO_ID`/PO 号 |
| 款号、款名 | 识别生产款式 | 产线数据库款式编号和描述 |
| 颜色、尺码 | 识别当前计划变体 | 尾查记录或当前生产计划中的颜色、尺码 |
| 生产小组 | 标识承担该线计划的生产组 | 优先读取计划/产线对应组别；若数据只有产线号，则配置经确认的产线到小组映射 |
| 尾查人员 | 显示实际执行尾查的人员 | 尾查合格事件中的员工编号，再映射到显示姓名 |
| 下线时间 | 记录成衣完成吊挂生产的时间 | 优先读取数据库明确的实际下线时间；若只有尾查合格完成时间，须在模板中按确认后的口径显示 |

如果模板包含条码或二维码，一期只允许编码 PO/线计划等批次级识别信息，不将其称为单件码，也不承诺扫码定位到某一件衣服。

## 六、运行与打印设计

### 6.1 本地程序

- 工具作为 Windows 后台服务或可随系统启动的现场程序运行；操作界面用于数据库连接配置、字段映射、模板维护、打印机选择和运行状态查看。
- 一期部署在一号车间吊挂线服务器；后续其他吊挂线需按各自数据库和打印机单独配置，不能默认共用一套字段映射。
- 数据库账号采用只读权限，只授予读取所需视图/字段的权限；凭据使用受保护的本机配置存储，不写进源代码或普通明文配置文件。

### 6.2 事件识别与防重

- 按数据库明确提供的尾查工序标识和合格状态过滤事件；工序名称、尾查站位和状态值通过配置映射，不依赖模糊名称匹配。
- 使用吊挂数据库的稳定源事件键建立本地唯一打印任务。重复轮询、程序重启或数据库补发同一事件时，不再次自动打印。
- 本地持久队列记录待打印、打印中、已提交打印队列、失败和人工重打状态。Windows 打印驱动或云打印服务只能确认其自身可确认的打印结果；对无法确认纸张是否实际出纸的情况，提供人工核对和受控重打流程。
- 断开数据库或打印机连接时暂存事件及失败任务；恢复后补拉和重试，并按源事件键去重。数据源若没有可靠的事件键和补查时间范围，须在开发前与衣拿供应商确认可用的增量读取方案。

### 6.3 打印机

支持安装在吊挂线服务器上的 Windows 打印机驱动，也预留配置云打印机。现场优先验证本机 USB/局域网标签打印机驱动；云打印需额外验证外网中断、服务授权、凭据保护和打印时延。每个打印任务明确使用的打印机、标签尺寸和模板版本。

## 七、一期不做的内容

- 每件衣服唯一的单件二维码/单件序列号，以及 ERP 扫码查看单件完整履历。
- 记录和打印所有吊挂工序的操作人、站位、开始/完成时间。
- 后整、包装等不在吊挂线上的员工报工与跨工段单件追踪。
- 通过单件履历自动判定返修责任人或建立质量责任结论。
- 将中继库轮询或 ERP 服务作为现场打印触发链路。
- 对衣拿生产数据库执行写入、结构变更或修改吊挂程序。

既有 ERP 吊挂数据回传、包码与衣架关联、未来单件追溯规划仍按《生产流程规划.md》第 15.14 节及后续专项需求维护；不得因本工具一期缩小范围而删除或改写这些后续规划。

## 八、开发前必须确认的接口项

1. 一号车间吊挂产线运行数据库的主机、数据库名、数据库类型/版本、读取视图或表及只读账号；确认其与 ERP 中继库的关系和访问范围。
2. 尾查工序在数据库中的稳定工序码、合格状态字段及失败/返修状态；确认合格事件何时写入、是否可能修订或重复。
3. 尾查记录中的 PO/线计划号、款号、颜色、尺码、操作员工号/姓名、生产小组/产线、下线时间和合格数量字段；明确每条记录的粒度。
4. 实际操作一次试验计划，核对 `TSPO_ID = PO` 是否在所选挂片计划及尾查记录中完整保留；导入选择页展示成功不等于生产回传字段已验证。
5. 确认本机驱动打印机型号、标签纸规格及目标模板；如使用云打印，确认可用平台、账号和离线行为。
6. 确认尾查合格后应打印几张、重复合格事件如何识别、人工补打权限与记录要求。

如果数据库没有明确的合格标志、生产小组、尾查员工或数量字段，先通过衣拿供应商确认现有数据源/视图能力。字段缺失不能用“没有返修记录”或“到了最后工序”代替合格判断。

## 九、一期验收口径

1. 在衣拿线计划选择页中，同一 PO/`TSPO_ID` 可展示并选择多个颜色尺码明细；本项已通过 `text261124` 测试款的导入页面验证。
2. 实际吊挂生产记录能识别挂片所选 PO/线计划和对应款色码；当前尚待产线数据库实测。
3. 只有尾查明确合格时才创建打印任务；标签上的 PO、款号、颜色、尺码、生产小组、尾查人员、下线时间与源记录一致。
4. 一条合格记录按明确合格数量打印；重复读取同一事件不会重复自动打印；失败可恢复重试，人工重打可追溯。
5. 数据库连接或打印机断开后，程序可恢复运行并处理待办；打印工具全程只读衣拿生产数据库。
6. ERP 中继库同步延迟或 ERP 停机不阻塞吊挂线打印；本期标签不声称具有单件级 ERP 追踪能力。

## 十、后续扩展方向

在一期运行稳定、吊挂产线的单件关联字段和各工段数据口径确认后，再评估为每件衣服建立唯一编码、逐工序人员/站位/时间追踪、ERP 扫码履历、后整包装追溯和质量返修闭环。后续扩展不得改变一期 PO、款色码字段和打印事件的既有含义。

## 一-1、岗位权威源（新增）

- **岗位/职务的权威清单以 `服装加工厂岗位列表.md` 为准**（26 类词库里的"岗位类 62 条"和"岗位与职务 197 条"是词库侧的词条，`服装加工厂岗位列表.md` 才是按部门/工段组织的正式岗位清单）。
- 建系统时"岗位字典表"取 `服装加工厂岗位列表.md` 的内容；词库的岗位类词条只作**英文口径参考**（岗位英文名从那两处查）。
- 若两份冲突（词库岗位类 vs 岗位列表.md），**以岗位列表.md 为准**，词库侧标注"已并入岗位列表"。

## 二、使用规则（强制）

1. **代码/表/字段/API 出现任何英文命名，先查词库对应分类有没有既定词，有就用既定词，没有才新增**。新增的必须回填进 JSON（分类、中文、英文、释义四字段），不许只在代码里私造。
2. **同一中文词在词库里只有一个英文口径**（如"后整"=Finishing），全系统统一，禁止同词不同译。若发现词库里两个分类撞了口径，优先合并到主分类，另一处标注"同 X"。
3. **数据库字典表取值**（料种、工序名、岗位名等）直接取词库该分类的"中文"列做值，英文列做备用字段；不要另起一套。
4. **缩写优先用词库"常见缩写速查"里的既定缩写**，不自造。新缩写要过这个分类先登记。
5. **港资厂粤普词（第十一类）不直接进字段名**，只用于界面文案的双语/地区化显示，字段名仍用普通话对应英文。
6. **词库版本**：JSON 里 `版本` 字段每次新增/修订递增。代码依赖词库命名时，提交信息里注明基于词库哪个版本。

## 三、与《开发规范》《功能命名清单》《API文档规范》的衔接

- 功能命名清单的"功能英文名"列 ← 取本词库对应分类既定英文，不自造。
- 数据库表/字段命名（开发规范 3.2）← 依据本词库，禁止拼音缩写或随意机翻。
- API 参数/返回字段的语义注释（API文档规范）← 释义列直接可用作字段中文注释底稿。
- 智能体意图理解（内嵌智能体规范）← 词库是 LLM 把员工口语（"帮我看看还有多少里布"）映射到标准字段的术语基础，词库不全会直接拉低意图识别准确率。

## 四、记忆锚点（读代码/写代码时最常要查的 5 类）

1. **ERP 与生产管理名词**（148 条）— 单据、计划、看板命名全在这里，写任何管理功能先翻这本。
2. **工艺/工序 + 整烫后整理**（74+42）— 码体系、报工、提成、后整分段（生产流程规划 15.15/15.16）的术语全在这里。
3. **服装部件与量度**（63）— 部件/裁片/料种字典（生产流程规划 15.4/15.5）的基础。
4. **常见缩写**（94）— 界面标签和字段简写，先查再写。
5. **AGV 机器人**（118）— 十四节预留方向的术语，做智能产线时启用。

# 仓库布局 API / MCP 契约

> 功能英文名：`warehouse_layout`；位置数据表：`inv_warehouse_location`；用户验收：2026-11-05 通过。
> REST：已实现。MCP：只读、位置 CRUD、状态和规则维护工具均已接入 `/mcp`；CSV/批量导入工具未注册。后端构建并重启成功；本轮未做认证 MCP 客户端工具发现烟测。
> 库区/货架/货位是一个仓库布局功能内的三级位置；`location_level` 分别为 1/2/3。AGV 字段只记录能力及外部映射，本功能不执行调度。

## 1. 通用约定

- 使用当前员工自己的 Sa-Token 会话；MCP `/mcp` 校验有效 token、匹配 `clientid` 和客户端访问范围。所有操作依权限码执行，不允许超管代办。
- ID 使用十进制字符串，避免 bigint 精度损失。REST 统一响应：`{"code":200,"msg":"操作成功","data":...}`；业务失败为 `code=500`、`data=null`。无权限为 `403`，登录/客户端校验失败为 `401`。
- 状态：`active`启用、`disabled`停用、`maintenance`维护。编码按仓库—库区—货架—货位逐级拼接；自动生成的建议用户可以编辑。未修改建议值时，服务端在仓库锁内重新分配。
- 写入不提供幂等键。超时后先查询核对，不能盲目重试新增或批量导入。

## 3. REST 接口

### 仓库选项 — `GET /system/warehouse-location/options`

无需参数。返回仓库 ID、编码、名称、`inbound_location_level`、状态；包含停用仓库以便历史查看。机器契约：幂等只读；无副作用；已登录即可；无需审批。

### 位置树 — `GET /system/warehouse-location/tree`

可选 `warehouseId`；不传读取全部仓库。返回嵌套树，节点含位置/仓库/父级信息、层级、状态、容量和 AGV 字段。机器契约：幂等只读；无副作用；需要 `inventory:location:list`；无需审批。

### 位置列表 — `GET /system/warehouse-location/list`

必填 `warehouseId`；可选 `parentId`、`level`（1–3）、`keyword`（编码/名称/外部映射码）、`status`。机器契约：幂等只读；无副作用；仓库和父级必须有效且同属该仓；需要 `inventory:location:list`；无需审批。

成功数据项示例：

```json
{"location_id":"5001","warehouse_id":"1001","parent_location_id":null,"location_code":"WH0001-Z01","location_name":"面料区","location_level":1,"agv_reachable":true,"capacity_limit":null,"capacity_unit":null,"location_status":"active","external_location_code":null,"remark":"","warehouse_code":"WH0001","warehouse_name":"一号仓","parent_location_code":null,"parent_location_name":null}
```

### 位置详情 — `GET /system/warehouse-location/{id}`

路径参数 `id` 为位置 ID。返回位置字段及父级编码/名称。机器契约：幂等只读；无副作用；记录存在且有 `inventory:location:query`；无需审批。

### 编码建议 — `GET /system/warehouse-location/next-code`

必填查询参数：`warehouseId`、`locationLevel`；可选 `parentLocationId`（库区不传）。返回 `data` 字符串建议。机器契约：幂等只读；无副作用；仓库与父级层级有效、自动编码开启且有 `inventory:location:add`；无需审批。

### 新增位置 — `POST /system/warehouse-location`

```json
{
  "warehouseId":"1001",
  "parentLocationId":null,
  "locationLevel":1,
  "locationCode":"WH0001-Z01",
  "autoGeneratedCode":"WH0001-Z01",
  "locationName":"面料区",
  "agvReachable":true,
  "capacityLimit":1000,
  "capacityUnit":"卷",
  "locationStatus":"active",
  "externalLocationCode":"AGV-Z01",
  "remark":""
}
```

库区直接归仓库；货架必须归库区；货位必须归货架。所属仓库、层级和父级建立后不可移动。用户可以改 `locationCode`；若与 `autoGeneratedCode` 相同，服务端保存时重新分配建议。

机器契约：非幂等；副作用为新增仓储位置及业务审计；前置为 `inventory:location:add`、仓库启用、父级存在且启用、层级正确、编码在仓库内唯一；无需审批，执行前展示仓库/父级/类型/编码/名称并取得员工确认。成功 `data` 为最终位置编码字符串。

### 编辑位置 — `PUT /system/warehouse-location`

新增字段外需 `locationId`。编码、仓库、父级和层级不可改变；编辑名称、AGV 能力、容量、状态、外部映射码和备注。

机器契约：目标状态幂等但会写审计；副作用为更新位置字段及业务审计；前置为 `inventory:location:edit`、记录有效且父子状态约束通过；无需审批，执行前确认具体变更。

### 启停/维护 — `PUT /system/warehouse-location/{id}/status`

请求体：`{"locationStatus":"maintenance"}`。值为 `active`、`disabled` 或 `maintenance`。机器契约：状态幂等；副作用为变更状态并写审计；前置为 `inventory:location:edit` 且父子状态约束通过；无需审批，执行前确认。父级状态不可与有效子级冲突。

### 删除位置 — `DELETE /system/warehouse-location/{id}`

机器契约：非幂等；副作用为逻辑删除位置并写审计；前置为 `inventory:location:remove`、没有未删除子级、没有业务单据外键引用；无需审批，但必须展示完整位置路径并取得员工确认。受引用位置应停用，不得绕过限制。

### 自动编码规则

- 读取固定参数：`GET /system/config/configKey/inventory.warehouseLayout.codeRule`；仅允许读取此固定键，勿开放通用任意参数读取工具。该接口没有单独 `@SaCheckPermission`，仍须登录并受全局客户端访问范围约束。
- 保存：`POST /system/config/warehouse-layout-code-rule`，权限 `system:config:edit`。请求示例：`{"enabled":true,"zonePrefix":"Z","zoneDigits":2,"rackPrefix":"R","rackDigits":2,"binPrefix":"B","binDigits":3}`。前缀为 1–8 位字母/数字，位数 1–6。
- 保存规则机器契约：相同规则值幂等；副作用为写入 `inventory.warehouseLayout.codeRule`、业务审计和清除缓存；无需审批，但智能体先展示完整新旧规则并等待确认。此配置不改变已有编码。

## 4. 错误及导入边界

常见业务错误包括仓库停用/不存在、父级跨仓或层级不符、父级停用、编码重复、父子状态冲突、仍有子级或已被单据引用。保留服务端中文错误原因，不自动改码或递归删除。

CSV 导入由前端解析并逐条调用 `POST /system/warehouse-location`，部分失败可能留下已成功记录；这不是事务型批量导入 API。Skill 仅可在 MCP 注册批量写工具后执行导入。

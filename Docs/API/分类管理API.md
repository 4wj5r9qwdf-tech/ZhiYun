# 分类管理 API 与 MCP 契约

> 版本：v1
> 更新日期：2026-11-20
> 说明：2026-11-06 用户验收通过。表为 `base_category_scheme`、`base_category`；功能键 `category`。各业务独立分类类型，共享管理能力。
> 契约迁移：2026-11-21 已补 MCP 字段矩阵，并收紧 Map 字段白名单、ID 字符串类型和更新完整性；类别 `next-code`/编码规则没有对应 MCP 工具。

## 一、公共契约

认证与响应沿用API总索引；员工本人token与clientid，ID均传十进制字符串。成功 `code=200`，数据在 `data`；权限403、未登录401、业务约束500并返回中文原因。管理目录全量返回，页面完整筛选分页，不存在只筛当前页。

| 方法/路径 | 用途 | 权限 | 机器契约 |
|---|---|---|---|
| GET `/system/category/schemes` | 全部分类类型 | `system:category:list` | 幂等、无副作用、已登录且有权限、无需审批 |
| GET `/system/category/scheme-options` | 公共分类类型选项 | 已登录 | 幂等、无副作用、包含停用项供历史显示、无需审批 |
| GET `/system/category/next-code?schemeId=...&parentId=...` | 当前类型和父级下的下一个编码建议 | `system:category:add` | `parentId`可省略表示根分类；返回`enabled/code`；只读预览，正式保存仍由服务端重新分配；关闭自动生成时返回空code |
| GET `/system/category/list?schemeId=...` | 单分类类型完整平铺树节点 | `system:category:list` | 幂等、无副作用、schemeId必填、无需审批 |
| GET `/system/category/options?schemeId=...` | 单分类类型业务选项 | 已登录 | 幂等、无副作用、schemeId必填、按整条父链及分类类型标记selectable、无需审批 |
| POST `/system/category/schemes` | 新增分类类型 | `system:category:add` | 非幂等、写分类类型与审计、编码/名称唯一、无审批但智能体须确认 |
| PUT `/system/category/schemes/{id}` | 完整更新/启停分类类型 | `system:category:edit` | 目标值幂等但写审计/时间、编码固定且深度不破坏现有树、须确认 |
| DELETE `/system/category/schemes/{id}` | 删除空分类类型 | `system:category:remove` | 非幂等、物理删除并记录删除前业务审计快照；类型下不能存在任何分类记录（含已删除节点）或外部引用；编码可重新使用；须确认不可恢复 |
| POST `/system/category` | 新增分类 | `system:category:add` | 非幂等、写分类与审计；自动编码建议可编辑，未改建议由类型行锁内重新分配；手工编码查重；分类类型/父级有效且唯一和深度通过、须确认 |
| PUT `/system/category/{id}` | 完整更新/移动/启停分类 | `system:category:edit` | 目标值幂等但写审计/时间、不能跨分类类型/成环/超深、须确认 |
| DELETE `/system/category/{id}` | 删除无引用叶节点 | `system:category:remove` | 非幂等、逻辑删除及审计、无未删除下级及外部引用、须确认 |

## 二、分类类型参数

| 字段 | 类型/必填/默认 | 中文 / English |
|---|---|---|
| code | string，必填，最多40 | 有效分类类型内编码唯一，字母数字开头及`_.-`；创建后不可修改，删除后可重新使用 / Unique among active category types; immutable after creation and reusable after physical deletion |
| name | string，必填，最多80 | 分类类型名称 / Category type name |
| maxDepth | integer，可选，默认5，范围1–20 | 类型下分类节点的最大层级，根节点计1级 / Maximum depth for category nodes under this type |
| sortOrder | integer，可选，默认0，范围0–999999 | 显示排序 / Display order |
| status | string，可选，默认0 | 0启用、1停用；停用分类类型后，其下分类均不可被新业务引用 / Availability |
| remark | string，可选，默认空，最多500 | 备注 / Business notes |

```json
{"code":"material","name":"物料分类","maxDepth":5,"sortOrder":0,"status":"0","remark":"供物料档案使用"}
```

## 三、分类参数

| 字段 | 类型/必填/默认 | 中文 / English |
|---|---|---|
| schemeId | string，必填 | 分类类型ID，创建后不可迁移 / Stable scheme ID |
| parentId | string或null，可选 | 同分类类型父级ID，null表示根 / Optional parent ID |
| code | string，自动规则开启时可由服务端补齐，手工编码必填，最多40 | 同分类类型内有效分类编码唯一；逻辑删除后可重新使用。自动建议格式为根分类为“类型编码+分隔符+序号”，下级为“上级编码+分隔符+序号”，输入始终可编辑 / Unique among active categories in a type; reusable after soft deletion. Editable suggestion uses the type or parent code as its prefix |
| name | string，必填，最多80 | 同父级名称唯一 / Sibling-unique category name |
| sortOrder | integer，可选，默认0，范围0–999999 | 显示排序 / Display order |
| status | string，可选，默认0 | 0启用、1停用 / Lifecycle status |
| remark | string，可选，默认空，最多500 | 备注 / Business notes |

```json
{"schemeId":"101","parentId":null,"code":"01-0001","autoGeneratedCode":"01-0001","name":"面料","sortOrder":0,"status":"0","remark":""}
```

分类编码规则位于参数设置，参数键为 `base.category.codeRule`，默认 `{"enabled":true,"separator":"-","digits":4}`。根分类以所属分类类型编码为前缀；下级分类以直接父级完整编码为前缀；同一父级下独立递增序号，例如 `01-0001`、`01-0001-0001`、`01-0001-0002`。分隔符可选短横线、下划线、点号或空，序号位数1–8位。自动生成只提供可编辑建议值；未修改时后端在分类类型行锁内按父级重新分配，防止并发重复；手工修改后服务端按类型校验编码唯一。关闭规则后必须手工填写。

参数设置写入路由：`POST /system/config/category-code-rule`，权限 `system:config:edit`；请求体为 `enabled:boolean`、`separator:string`、`digits:integer`。操作写业务审计并刷新系统参数缓存。

上例ID应替换为分类类型创建真实返回值。新增和更新都返回 `{"code":200,"msg":"操作成功","data":"102"}`。删除成功 `data:null`。

分类类型查询 `data` 为包含 `id` 和所有分类类型参数的数组；节点列表 `data` 包含 `id/schemeId/parentId/code/name/sortOrder/status/remark`。选项另外返回 `selectable:boolean`，停用分类类型/任意停用祖先/节点都使其false，历史仍显示。

```json
{"code":200,"msg":"操作成功","data":[{"id":"102","schemeId":"101","parentId":null,"code":"FABRIC","name":"面料","sortOrder":0,"status":"0","remark":"","selectable":true}]}
```

分类类型删除是物理删除：仅当类型下从未存在分类节点且无外部业务引用时允许；操作日志保留被删类型的编码、名称及删除结果，删除后不可从页面恢复。已有分类节点或引用的类型应停用，不允许删除。分类节点删除仍为逻辑删除；未引用叶节点删除后保留历史ID，编码可重新使用。

## 四、错误、并发与历史

编码/同级名称冲突、分类类型不存在或停用、跨类型父级、自为父级或移动到后代、子树深度超限、降低分类最大层级导致现有树超限、启用停用父级下节点均拒绝。停用父级需先停用下级；停用分类类型可统一阻止新引用。

示例：`{"code":500,"msg":"上级分类不能是自身或下级，禁止循环","data":null}`。分类被业务外键引用时不允许删除，只可停用。业务保存必须再校验分类类型和节点可用性，不能信任前端选项。

节点写入按分类类型行锁串行化，两个并发反向移动不会同时成功。重复提交无业务幂等键，超时先查询编码/ID确认结果。CSV按父级在前逐条调用创建，部分成功可保留，失败逐条反馈；不宣称整个导入原子事务。

## 五、MCP 与审计

- 分类类型：`category_schemes`、`category_scheme_options`、`category_scheme_create`、`category_scheme_update`、`category_scheme_delete`。
- 节点：`category_list`、`category_options`、`category_create`、`category_update`、`category_delete`。
- 查询列表/选项使用 `schemeId:string`；新增和更新用 `body:object`，更新/删除另有 `id:string`，对象字段见对应参数表。
- 写前展示目标分类类型、路径、变化及停用影响并确认，使用员工本人权限；记录对象身份、层级关系及字段前后值。
- 工具已实际发现；分类类型/节点的新增、更新、查询和删除均通过MCP实际调用，低权限写入拒绝亦已验证。

## MCP 输入字段矩阵（契约迁移批次 1）

`category_create`、`category_update`、`category_scheme_create`、`category_scheme_update` 的 inputSchema 只声明自由 object；适配器现在拒绝未知键、数字型 ID 和字段类型错误。更新操作必须先查当前记录，再提交完整对象。每个 ID 均从同范围列表复制为十进制字符串。

| 字段路径 | JSON 类型 / 示例 | 必填与省略结果 | `null` / 空白 / 空集合结果 | 用途、来源、约束与副作用 |
|---|---|---|---|---|
| `category_schemes.arguments`、`category_scheme_options.arguments` | object；`{}` | 无参数 | 不适用 | 管理列表需 `system:category:list`；业务选项需员工登录。只返回当前权限可见项 |
| `category_list.schemeId`、`category_options.schemeId` | string 正十进制 ID；`"101"` | 必填；从体系查询复制 | null/空白/数字/非法 ID 拒绝 | 查询一个分类体系；选项中的 `selectable=false` 表示当前体系或祖先停用 |
| `category_create.body.schemeId` | string 正十进制 ID；`"101"` | 必填 | null/空白/数字/非法 ID 拒绝 | 必须来自 `category_schemes`；只能在启用体系中新建 |
| `category_create.body.parentId` | string 正十进制 ID或null；`"102"` | 可选；省略或 null 表示根节点 | MCP 中空白字符串和数字拒绝；null 明确为根 | 如为子级，父级须来自同体系 `category_list`，且启用并未超过深度限制 |
| `category_create.body.code` | string；`"FABRIC-0001"` | 可选；自动规则开启时可省略或留空；关闭后必填 | null/空白等于未填写；需手工码时服务端拒绝 | 从页面/REST `next-code` 可取建议；可编辑；如未修改原样回传 `autoGeneratedCode`，服务端锁内重分配 |
| `category_create.body.autoGeneratedCode` | string；`"FABRIC-0001"` | 可选 | null/空白等于无建议 | 只用来判定用户是否改过建议，不是正式编码字段 |
| `category_create.body.name` | string；`"面料"` | 必填 | null/空白拒绝；最多80字符 | 同一父节点下名称不区分大小写唯一 |
| `category_create.body.sortOrder` | integer；`10` | 可选；省略默认0 | null/小数/数字字符串拒绝；范围0–999999 | 同级显示顺序 |
| `category_create.body.status` | string；`"0"` | 可选；省略默认 `"0"` | null/空白/数字拒绝；只允许 `"0"`/`"1"` | 启用/停用；不能启用于停用祖先下 |
| `category_create.body.remark` | string；`"采购分类"` | 可选；省略为空 | null/空白清空；仅文本 | 最多500字符 |
| `category_update.id`、`category_scheme_update.id`、两类 `*_delete.id` | string 正十进制 ID；`"102"` | 必填；从对应列表复制 | null/空白/数字/非法 ID 拒绝 | 节点与体系 ID 不能互换 |
| `category_update.body` | object；含 `schemeId/parentId/code/name/sortOrder/status/remark` | 七个键全必填；根级要显式 `parentId:null` | null/空对象/缺键/未知键拒绝 | 完整替换节点字段；不支持补丁。`schemeId` 必须与旧值一致；父级变化是移动操作，须展示前后路径及子树影响 |
| `category_update.body.schemeId`、`parentId` | string 正十进制 ID；`"101"` / string或null | 两键均必填；顶层 ID 来自同一体系 | `schemeId` null/空白拒绝；`parentId:null` 表示移动到根；空白/数字拒绝 | 移动不可跨体系、成环或超过最大深度 |
| `category_update.body.code`、`name` | string；`"FABRIC-0001"` / `"面料"` | 两键必填，且非空 | null/空白拒绝 | 更新时编码必须回填当前稳定编码；名称同父级唯一 |
| `category_update.body.sortOrder`、`status`、`remark` | integer / string / string；`10` / `"0"` / `"说明"` | 三键必填 | sortOrder null/非整数拒绝；status null/空白拒绝且只接受字符串0/1；remark null/空白清空 | 更新全字段最终态；状态变化影响业务新选择，备注最多500字符 |
| `category_scheme_create.body` | object；见示例 | `code`、`name` 必填；其他字段可省略走默认 | null/空对象拒绝；未知字段拒绝 | 新建独立业务分类体系；无幂等键，超时先按编码查证 |
| `category_scheme_create.body.code`、`name` | string；`"material"` / `"物料分类"` | 均必填、非空 | null/空白拒绝；编码最多40字符，名称最多80字符 | 编码创建后不可改；名称全局不区分大小写唯一 |
| `category_scheme_create.body.maxDepth`、`sortOrder` | integer；`5` / `0` | 可选；省略各默认5/0 | null/小数/数字字符串拒绝；maxDepth 1–20、sortOrder 0–999999 | 限制此体系最大层级；节点已超过目标深度时不能降低 |
| `category_scheme_create.body.status`、`remark` | string；`"0"` / `"业务分类"` | status 可选默认0；remark 可选默认空 | status null/空白拒绝，只能字符串0/1；remark null/空白清空 | 停用体系阻止该树新业务引用；remark 最多500字符 |
| `category_scheme_update.body` | object；含 `code/name/maxDepth/sortOrder/status/remark` | 六个键全必填 | null/空对象/缺键/未知键拒绝 | 完整替换体系字段；编码必须回填当前稳定编码；降深度不得使现有树超限 |
| `category_scheme_update.body.code`、`name` | string；`"material"` / `"物料分类"` | 必填、非空 | null/空白拒绝 | code 必须与现有值一致；name 最多80字符且不重复 |
| `category_scheme_update.body.maxDepth`、`sortOrder` | integer；`5` / `0` | 必填 | null/小数/数字字符串拒绝；范围同新增 | 降低最大深度需保持所有现存节点合法 |
| `category_scheme_update.body.status`、`remark` | string；`"1"` / `"停用待整理"` | 必填 | status 仅字符串0/1；remark null/空白清空 | 停用影响此体系下所有分类的新业务选择；remark 最多500字符 |

所有分类写权限分别为 `system:category:add/edit/remove`；查询管理列表需 `system:category:list`，业务选项需员工登录。删除体系是物理删除，需无分类节点及无外部引用；删除节点是逻辑删除，仅允许无下级且无业务引用叶节点。

## 分类引用与人员权限接入状态（2026-11-20）

人员分类权限的基础设置和人员配置入口已实现并通过用户验收；接口见[人员分类权限 API](人员分类权限API.md)。分类类型和节点业务选项仍按当前调用者的人员分类范围过滤。业务默认分类参数及采购、库存、食堂、设备等尚未接入模块，必须按实际实施状态逐项核对，不能从基础授权验收推断为全部完成。统一规则见[分类引用、人员分类权限与业务默认定位契约](../地基/分类引用与人员分类权限.md)。

# 仓库管理 API / MCP 契约

> 功能英文名：`warehouse`；数据表：`inv_warehouse`；用户验收：2026-11-05 通过。
> REST：已实现。MCP：仓库 CRUD、状态、编码规则及只读工具均已接入 `/mcp`；CSV/批量工具未注册。后端构建并重启成功；本轮未做认证 MCP 客户端工具发现烟测。
> 契约依据：`WarehouseController`、`SysConfigController` 与前端实际调用。

## 1. 通用约定

- MCP 与 REST 均以发起员工自己的 Sa-Token 会话执行；MCP `/mcp` 同样要求有效 token、匹配的 `clientid`，并遵守 token 的客户端访问范围。不得用管理员 token 代办。
- MCP 参数和 URL 中的 ID 按十进制字符串传递。REST JSON 中安全整数 ID 序列化为数字，超出 JavaScript 安全整数范围时序列化为字符串。统一 REST 响应为 `{"code":200,"msg":"操作成功","data":...}`；业务失败为 `code=500`、`data=null`、`msg` 描述原因。
- 权限不足返回 `403`；登录或客户端标识无效返回 `401`。写入动作没有幂等键；请求超时先查询确认结果，不盲目重试。
- 仓库类型是 `sys_tag_relation` 中 `module_key="warehouse_master"` 的标签关联，不是仓库主表枚举。
- 入库定位层级：`0`仓库、`1`库区、`2`货架、`3`货位。自动编码建议允许员工编辑；只有未编辑建议值时，后端保存时才在事务锁内重新取号。

## 3. REST 接口

### 查询仓库列表 — `GET /system/warehouse/list`

可选查询参数：`keyword`（编码、名称、区域或建筑名称）、`status`（`0`启用/`1`停用）、`tagId`（仓库类型标签 ID）。返回仓库编码/名称、建筑、楼层、区域、负责人、入库定位层级、状态、备注及 `tag_names`。

成功示例：

```json
{"code":200,"msg":"操作成功","data":[{"warehouse_id":1001,"warehouse_code":"WH0001","warehouse_name":"一号仓","building_id":2001,"building_name":"一号厂房","floor_name":"1层","area_name":"东侧","manager_user_id":3001,"manager_name":"张三","inbound_location_level":2,"status":"0","remark":"","tag_names":"原料仓"}]}
```

机器契约：幂等只读；无副作用；前置为已登录且有 `inventory:warehouse:list`；无需审批。

### 表单选项 — `GET /system/warehouse/options`

无参数。返回 `buildings`（在用建筑及楼层信息）和 `managers`（在用人员）。机器契约：幂等只读；无副作用；前置为已登录；无需审批；无独立权限码。

### 下一个仓库编码建议 — `GET /system/warehouse/next-code`

无参数。返回 `data` 中的字符串编码建议；自动编码关闭时返回业务错误。机器契约：幂等只读；无副作用；前置为 `inventory:warehouse:add`；无需审批。

### 仓库详情 — `GET /system/warehouse/{id}`

路径参数 `id` 为仓库 ID。返回主档、`tagIds` 与关联标签 `tagOptions`。机器契约：幂等只读；无副作用；前置为记录存在且有 `inventory:warehouse:query`；无需审批。

### 新增仓库 — `POST /system/warehouse`

请求体：

```json
{
  "warehouseCode":"WH0001",
  "autoGeneratedCode":"WH0001",
  "warehouseName":"一号仓",
  "buildingId":"2001",
  "floorName":"1层",
  "areaName":"东侧",
  "managerUserId":"3001",
  "inboundLocationLevel":2,
  "status":"0",
  "remark":"",
  "tagIds":["4001"]
}
```

`warehouseCode` 可填用户编辑后的编码；`autoGeneratedCode` 应携带展示给用户的原始建议，后端据此判断是否仍可重新取号。建筑、负责人可为空；`tagIds` 可为空数组。

机器契约：非幂等，重复请求可能新增重复业务记录；副作用为新增仓库、标签关联及业务审计；前置为 `inventory:warehouse:add`、有效唯一编码、名称、有效引用及标签；无需审批，智能体执行前必须取得员工确认。

成功返回示例：`{"code":200,"msg":"操作成功","data":"WH0001"}`。

### 修改仓库 — `PUT /system/warehouse`

请求字段与新增相同，另需 `warehouseId`。必须提交完整主档和最终标签集合；仓库下已有布局时不可修改仓库编码。

机器契约：档案目标状态幂等，但会更新审计时间并写业务审计；副作用为更新主档和替换标签关联；前置为记录存在、`inventory:warehouse:edit` 及全部字段和引用有效；无需审批，执行前确认。

### 启停仓库 — `PUT /system/warehouse/{id}/status`

请求体：`{"status":"0"}`（启用）或 `{"status":"1"}`（停用）。机器契约：状态幂等；副作用为修改状态及业务审计；前置为记录存在且有 `inventory:warehouse:edit`；无需审批，执行前确认。停用不删除档案。

### 删除仓库 — `DELETE /system/warehouse/{id}`

机器契约：非幂等；副作用为逻辑删除仓库、清除类型标签关联并写审计；前置为 `inventory:warehouse:remove` 且仓库下没有任何未删除的库区/货架/货位；无需审批，删除前展示仓库身份并取得确认。已有布局时后端拒绝删除，建议停用。

### 修改仓库自动编码规则 — `POST /system/config/warehouse-code-rule`

请求体：`{"enabled":true,"prefix":"WH","digits":4}`。`prefix` 为 1–12 位字母或数字，`digits` 为 1–10 的整数。

机器契约：相同规则值幂等；副作用为写入系统参数 `inventory.warehouse.codeRule`、审计并清除参数缓存；前置为 `system:config:edit`；无需审批，但智能体必须展示完整新旧规则并等待员工确认。该配置由系统参数管理维护，不属于仓库档案权限。

## 4. MCP 安全与错误

工具直接复用仓库 Controller 的查询逻辑，并在 MCP 方法入口显式调用 Sa-Token 权限检查；直接 Java 调用不会触发 Controller 上的 MVC 注解。MCP Servlet Filter 校验员工登录、`clientid` 与客户端访问范围。

常见业务错误包括仓库不存在或已删除、编码重复、建筑/负责人已停用、楼层超出建筑范围、仓库仍有布局档案、自动编码关闭或规则无效。错误响应以服务端 `msg` 为准，不要自动换编码或绕过引用校验。

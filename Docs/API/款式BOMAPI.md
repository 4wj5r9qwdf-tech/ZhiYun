# 款式 BOM API

一期已于 2026-11-13 通过用户验收。路径前缀为 `/rd/style-bom`。请求使用当前员工身份，ID 使用正十进制字符串以避免 bigint 精度丢失。查询需要 `rd:bom:list`，生成建议单号、保存和发布还需要 `rd:bom:edit`。

| 方法及相对路径 | 用途 |
| --- | --- |
| GET /styles、/style-categories | 查询可用款式和分类 |
| GET /list | 按 keyword、status、mode、styleId 筛选 |
| GET /list/{styleId} | 查询指定款式的版本 |
| GET /context/{styleId} | 查询子款、有效颜色尺码、套装规格、用途及建议版本号 |
| GET /next-code | 取得可编辑的建议单号 |
| GET /{id} | 读取单据、完整规则和 revision |
| GET /material/{id}/colors | 查询可用物料颜色 |
| POST / | 保存草稿或发布，返回 BOM ID |
| GET /{id}/coverage | 核对有效颜色尺码的用料覆盖 |
| GET /{id}/preview | 用量试算，传 count；单款按适用规格传 colorId、sizeId，套装传 setSpecId |

保存体包含 styleId、bomCode、version、preparerId、remark、rules、release。新建可带 autoGeneratedCode 和 suggestedVersion，编辑传 id 与最新 revision。rules 为最终完整集合，最多 1000 条，包含 childId、slotId、slot、usageType、colorId、sizeId、materialId、materialVariantId、materialColorId、usageUnitId、usage、conversionFactor、omitted 和 remark。单款明细的 childId 使用款式 ID，整套共用用料的 childId 和颜色尺码留空。用量使用十进制文本。发布前执行规格覆盖校验，发布后只读。

单规格及批量填写共用单据层 CSV 导入导出，使用款号、成衣色码、物料编码、物料规格编码、颜色和单位名称。导入先确认替换草稿用料，保存时统一走以上接口及审计。

MCP 工具包括 `style_bom_list`、`style_bom_detail`、`style_bom_coverage`、`style_bom_preview`、`style_bom_save`，沿用同一业务授权和审计。所有必填 ID 必须是正十进制数字字符串；可选套装规格、颜色和尺码 ID 可以省略或传空串，传入时同样必须为正十进制 ID。空对象不能作为保存请求。

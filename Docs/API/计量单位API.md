# 计量单位 API 与 MCP 契约

> 版本：v1
> 更新日期：2026-11-05
> 说明：2026-11-05 用户验收通过；已完成接口验证与 MCP 发现/读写及低权限拒绝验证。数据表 `base_unit`，功能键 `unit`。

## 一、认证与接口

使用员工本人会话 `Authorization: Bearer <token>` 及项目 `clientid`。统一响应 `code/msg/data`，成功200，权限拒绝403、未登录401，业务错误500并返回中文原因。ID 始终使用十进制字符串；数量与系数使用普通十进制字符串，不通过JS浮点处理。

| 方法/路径 | 用途 | 权限 | 幂等/副作用/前置/审批 |
|---|---|---|---|
| GET `/system/unit/list` | 管理目录全量查询，客户端完整筛选分页 | `system:unit:list` | 幂等、无写副作用、已登录且有权限、无需审批 |
| GET `/system/unit/options` | 业务单位选择，含停用项及 `selectable` | 已登录 | 幂等、无写副作用、登录、无需审批；不可选项只用于历史显示 |
| GET `/system/unit/convert` | 固定换算；参数fromId、toId、quantity均必填字符串 | 已登录 | 幂等、无持久化副作用、双方及参照启用且共同参照、无需审批 |
| POST `/system/unit` | 新增单位 | `system:unit:add` | 非幂等、写单位及审计、编码名称唯一及参照有效、无审批但智能体须先取得员工确认 |
| PUT `/system/unit/{id}` | 完整更新/启停单位 | `system:unit:edit` | 目标值幂等但更新审计时间、编码名称唯一及换算语义保护、无审批但须确认 |
| DELETE `/system/unit/{id}` | 逻辑删除无引用单位 | `system:unit:remove` | 重复删除返回不存在、无子换算单位及业务外键引用、写删除及审计、须确认 |

## 二、写入参数与返回

| 字段 | 类型/必填/默认 | 中文说明 / English meaning |
|---|---|---|
| code | string，必填，最多40 | 单位业务编码，字母数字开头，允许字母数字及`_.-` / Editable unit code |
| name | string，必填，最多80 | 单位名称 / Unit name |
| symbol | string，可选，默认空，最多20 | 显示符号 / Display symbol |
| dimension | string，必填 | length长度、mass质量、area面积、volume体积、time时间、count计数、other其他 / Measurement dimension |
| decimalPlaces | integer，可选，默认3，0–8 | 该单位数量展示精度；作为换算目标时也是结果精度 / Unit display precision and target precision when converting |
| baseUnitId | string或null，可选 | 同维度独立参照单位ID；空表示本单位是独立参照 / Optional reference unit ID |
| factor | decimal string，可选，默认1 | 方向固定为“1个本单位 = factor × 参照单位”；正数，最多18位整数12位小数，独立单位必须1 / Exact conversion ratio from this unit to its reference |
| sortOrder | integer，可选，默认0，0–999999 | 排序 / Display order |
| status | string，可选，默认0 | 0启用、1停用 / Lifecycle status |
| remark | string，可选，默认空，最多500 | 备注 / Business notes |

独立单位请求：

```json
{"code":"M","name":"米","symbol":"m","dimension":"length","decimalPlaces":3,"baseUnitId":null,"factor":"1","sortOrder":0,"status":"0","remark":"长度参照单位"}
```

新增成功：`{"code":200,"msg":"操作成功","data":"101"}`，该ID是示例，后续调用用实际返回值。

厘米示例（`baseUnitId` 替换成真实米单位ID）。因为当前单位是厘米、参照单位是米，填的是 `1厘米 = 0.01米`，系数为 `0.01`，不能因反向换算“1米=100厘米”而误填 `100`：

```json
{"code":"CM","name":"厘米","symbol":"cm","dimension":"length","decimalPlaces":3,"baseUnitId":"101","factor":"0.01","sortOrder":1,"status":"0","remark":"1厘米等于0.01米"}
```

列表/选项的 `data` 是对象数组，字段为上述写字段加 `id`。`baseUnitId` 可null，系数始终字符串，选项另带 `selectable:boolean`。

```json
{"code":200,"msg":"操作成功","data":[{"id":"101","code":"M","name":"米","symbol":"m","dimension":"length","decimalPlaces":3,"baseUnitId":null,"factor":"1.000000000000","sortOrder":0,"status":"0","remark":"长度参照单位","selectable":true}]}
```

换算成功数据：`{"quantity":"1.235","fromId":"102","toId":"101","rounding":"HALF_UP"}`。公式：输入数量×源单位系数÷目标单位系数，按目标单位的小数位数采用 HALF_UP（四舍五入）；独立单位自身系数为1。输入非负，最多30位整数和12位小数，不接受科学计数法。

换算接口中 `fromId` 是待换算单位，`quantity` 是该单位下的数量，`toId` 是目标单位。例如 `100 厘米 → 米` 的结果为1米（受目标单位精度影响）。接口按固定换算契约校验两单位同根、启用且计量维度一致；不属于同一固定参照根时拒绝换算。

管理页面新增时可选择库存单位或辅助单位；单独新增辅助单位时选择已有库存单位并继承其计量维度。新增库存单位可同时添加多行辅助单位；编辑库存单位时可带出已有辅助单位、修改或新增，逐行调用原有新增和更新接口。也可选择同维度已有单位批量设置换算关系；后端引用保护仍然生效。系数方向为“1个辅助单位 = 系数 × 库存单位”。多行保存不是原子批量事务：成功行锁定，失败行保留错误并可修正重试；列表显示系数时只去掉尾部补零，不改变存储精度。

### 数量精度契约（后续业务必须遵守）

- **时长业务单独处理**：工时、耗时等时长在业务页面使用一个字段直接显示为“1小时23分58秒”，不把十进制小时显示为小时和分钟；时长计算以整数秒为基准，按 1小时=3600秒、1分钟=60秒精确换算，并保留超过24小时的累计小时数。不得通过近似的分钟/小时小数系数或小时的小数位数舍入后再计算。涉及秒以下精度、计薪取整规则或历史数据迁移时，在对应功能中单独确定。当前单位功能尚未实现时长控件或工时业务。
- 工时和耗时的显示、加减及累计不依赖计量单位档案的小数位数和换算系数；通用数量场景仍使用各自单位契约。整数秒 `s` 的显示按整数除法计算：小时 `s / 3600`，分钟 `(s % 3600) / 60`，秒 `s % 60`；例如 `5038` 秒为“1小时23分58秒”，累计 `98100` 秒为“27小时15分00秒”。业务应验证非负、溢出及分钟秒数范围，避免使用一天内时间类型存储累计时长。
- 若依据开始和结束时间计算时长，应使用明确时区的时间点计算实际间隔，跨日和时区切换不得依赖展示文字相减；休息、重叠、跨班、缺卡、调整和工资取整属于业务口径，须在对应功能确定后实现。以秒为基准不自动决定这些业务规则；从小数小时或历史数据转换时须明确舍入与迁移策略。
- `decimalPlaces` 是单位档案上的数量展示精度，并且是固定换算的目标精度；它不是所有业务表的数据库精度定义，也不会自动替代各业务接口的输入校验。
- 管理页面中时间维度的小数位数只读；新增时间单位由页面填写8位作为通用十进制换算精度，编辑已有时间单位保留原值，CSV导入为空时默认8位、提供值时保留。此设置不用于工时或时长的精确计算；API 的字段及缺省行为保持原契约。
- 库存、物料、BOM、收发存及单据功能必须读取所选单位的 `decimalPlaces`，以十进制字符串/Java `BigDecimal` 计算，禁止 JavaScript `number`、Java `float/double` 或固定两位小数处理数量。
- 每个业务功能都要明确记录输入精度校验、数据库存储精度、展示格式及舍入发生节点。中间计算保留足够精度，只在明确的业务边界按规则舍入；不得静默截断或提前舍入。
- 若业务需要比单位展示精度更高的内部库存精度，必须在对应功能契约中分别说明“录入/显示精度”和“内部存储/计算精度”，不能直接把展示精度当作存储精度。
- 单位被业务引用后，单位小数位数不可变更。若未来需要不同精度，应新增单位并明确历史记录、库存余额及换算迁移方式。

## 三、业务错误与引用边界

- “批量设置换算系数”选择库存单位后，显示该单位的全部已关联辅助单位及当前系数（包括停用项）；只提交修改过的系数、新关联的单位或标记移除的绑定。移除绑定将单位转为独立库存单位（`baseUnitId=null`、`factor=1`），仍通过更新接口检查引用保护，失败行可重试或撤销。
- 编辑库存单位时可标记移除已有辅助单位；保存时更新该单位的 `baseUnitId=null`、`factor=1`，保留其原档案信息，使其成为独立库存单位。修改前仍须通过已有业务引用及下级单位保护；多行逐项保存，失败行可撤销或重试。
- 不同参照根即使维度相同也不能换算；件、箱、卷独立建档，不自动假定比例。重量长度和每箱件数等物料专属换算后续由对应业务维护。
- 不能以自身或已有换算单位作为参照；编码/名称冲突、系数非正、根系数非1、无效精度、参照停用均拒绝。
- 存在换算子单位或外部业务外键引用后，不可改变维度、精度、参照、系数；可以维护显示信息。
- 根单位仍有启用子单位时不可停用；被引用时不可删除。停用保留历史显示，后续业务保存必须复核可选性。
- 示例错误：`{"code":500,"msg":"单位没有共同固定换算参照，不能换算；包装或物料专属换算应由业务维护","data":null}`。
- 逐条CSV导入复用POST；无专用批量原子事务。无幂等键，超时先查编码确认结果，再决定重试。

## 四、MCP 与审计

工具：`unit_list`、`unit_options`、`unit_convert`、`unit_create`、`unit_update`、`unit_delete`。分别映射上述接口；更新/删除额外接收 `id:string`，换算接收 `fromId/toId/quantity:string`，新增/更新接收 `body:object`（字段见上表）。

服务端显式检查同等员工权限；新增、修改、删除、状态及换算关系变化记录中文动作、单位身份和实际前后值。智能体写入前展示完整目标/变化并确认；不借用超管权限。源码在 `FoundationMcpTools`；16个本批工具已发现；单位新增、更新、删除及公共查询已实际调用，低权限写入拒绝已验证。

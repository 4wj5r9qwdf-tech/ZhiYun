## 三、必须遵守的铁律（违反 = 打回）
1. **除代码/命令外全部用简体中文**；所有文档文件名用中文。
2. **文档内、代码注释内引用一律项目内相对路径**，禁带本地盘符（`D:\`/`C:\`/`/home/`）；Git 提交不带本地绝对路径。
3. **能开关/权限/自填属性表达的，一律不写死**（各模块强控点都进 `sys_switch`/角色权限/配置，不硬编码）。
4. **不重复造轮子**：通用逻辑抽公共层；有成熟库/开源组件解决的不手写；复制粘贴超过一次即视为重复造轮子。
5. **英文命名（表/字段/枚举值）先查词库既定口径**，没有才新增并回填 `服装加工厂专业名词词库.json`；禁拼音缩写/机翻。
6. **功能名不许擅自定**：新功能先跟用户探讨确认功能名、写进《功能命名清单》，再开工；数据库表名必须与功能名严格对应。
7. **先验证、后写智能体契约**（节奏铁律，见下）。
8. **敏感信息（key/密码/手机号/生产凭据）一律不进 Git**；`.env` 进 `.gitignore`，仓库只提 `.env.example` 占位。
9. **开工前最终核对（强制）**：智能体把该功能的**具体实现方法、涉及字段/表、单据流转、边界与例外、影响面**逐条列给用户，**核对完、用户点头才动代码**（不许"想到什么做什么"）。对应 `开发规范.md` 节奏铁律第 1.5 步。

## 四、协作流程（每个功能严格按此，不跳步）
| 步 | 动作 | 谁确认 |
|---|---|---|
 1 | 需求核对 + 定方案 + 更新需求/规划文档 | 用户拍板 |
| 2 | 开发 + 测试（全量测试绿） | 开发自查 |
| 3 | **用户验证"没问题"** | **用户** |
| 4 | 验证通过后**同批次**补齐：API 文档 + MCP 工具 + Skill | 开发 + 过《API文档规范》 |
| 5 | 收尾：DDL 合入 `sql/主建表.sql` + 清理临时文件 + 版本记录 + 词库回填 | 发版时 |
- **第 3 步用户没验收，第 4 步的 API/MCP/Skill 一律不写**（没验证的契约会带病上线）。
- DDL 开发期可分模块零散写，**功能验证通过后必须合并进 `sql/主建表.sql`（唯一权威建表入口）**，零散文件归档删除。
- 临时文件/一次性脚本用完即清，发版前自查无残留。

## 五、红线（碰了直接停，等用户定夺）
- **不擅自定功能名**、不擅自改名/拆分/合并功能（改功能名走《功能命名清单》重新确认）。
- **不给智能体开万能/超管代执行口子**：智能体每次写操作以发起员工本人身份执行、校验、留痕，可执行动作=该员工角色权限过滤后的工具集，无权限动作不可见。
- **不往文档/代码/Git 塞本地盘符、真实 key/凭据**。
- **不动"没让它动的模块"**：接一个任务只改对应模块 + 该合的地基，不顺手重构别处。
- **数据源/预警条件走结构化白名单**（表+字段+操作符+值，参数化），不存自由 SQL 文本（安全优先）。

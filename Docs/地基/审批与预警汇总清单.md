## 一、审批对象清单（谁的动作要送审批）

> 定稿原则（已定）：统一审批引擎 + 各模块挂回调；审批**节点可自定义**（几级/谁审/按类型金额分链），不写死；不存在小额免审（报销类明确无免审）。

| 模块 | 审批对象 | 备注（开关/条件） |
|---|---|---|
| 人员管理 | 离职（签核） | 保留审批 |
| 人员管理 | 调组/调车间 | 一期不审批，后期补（开关） |
| 宿舍 | 钥匙补领（收费） | 行政/宿管发起，账到财务 |
| 宿舍 | 物品损坏赔偿 | 定责到人，账到财务 |
| 食堂 | 包间预留 | 一期先登记不审批（开关） |
| 物业资产 | 报修工单 | 小修免审/大修送审（开关） |
| 物业资产 | 资产盘点差异 | 走审批 |
| 物业资产 | 资产报废 | 走审批 + 财务 |
| 财务采购 | 采购申请单（4 类） | 下单前审批（默认都审，节点可配） |
| 财务采购 | 报销单 | **无免审**，全走审批；节点按"类型+金额段"可配 |
| 车辆 | 花钱的单（加油/保养/违法处理） | 走财务报销审批（车辆出单据→财务引用） |

**待定**：物业"资产报废残值/盘点差异"的审批级别；车辆"领用"是否审批（倾向只登记，花钱的才审）；食堂包间预留要不要审。

| 宿舍 | 物品损坏待处理 | 退房触发 | 宿管/定责人 |
| 食堂 | 未报备/漏报统计 | 每天 15:00 | 未报备人+食堂 |

### 四-0、审批引擎形态（已定：Warm-Flow 国产轻量引擎 + 钉钉式节点自定义）
- **选型：Warm-Flow**（国产轻量审批流引擎，GitHub），**仿钉钉模式**。理由：轻（贴合"单体部署、几百人"）、节点自定义、有现成开源，避免自研审批流（踩"不重复造轮子"）。
- 审批引擎 = **节点可自定义**（对标钉钉）：一条审批链 = 一串节点（每节点：审批人/角色、条件、并行会签/或签）；节点增删/调序/改审批人 = 配置，不改代码；按"对象类型 + 金额/条件"走不同审批链。
- 钉钉能力要覆盖：指定审批人（人/角色/上级/部门）、会签/或签、条件分支（金额>X 走某链）、转交、加签、撤回、代理代审。
- **Warm-Flow 怎么接**（集成方式，等技术栈定后细化）：
  - 各模块"可审批对象"（见上表 11 条）注册进 Warm-Flow 的流程定义
  - 审批流定义/节点配置存 Warm-Flow 自己的存储；ERP 业务只调它"发起/通过/驳回/转交"
  - 审批结果回调回业务模块（走《开发规范》/审批引擎"回调注册"那套，不硬编码）
- 预警 仍走 统一预警规则表（本清单第二节），不并入 Warm-Flow（预警是"数据条件触发提醒"，跟审批流是两回事）。

### 四-1、预警/催办 落地方式（Warm-Flow 边界结论）

> 结论：Warm-Flow 管"审批流"（人对人审批），**不是一站式预警中心**。预警/催办/业务提醒 靠 **ERP 自己的"统一预警规则表 + 定时任务 + 一套通知通道"**，Warm-Flow 只负责审批超时那一小段。

**三类提醒，分开做（别都塞 Warm-Flow）：**

| 类型 | 谁负责 | 说明 |
|---|---|---|
| **审批"超时自动动作"**（卡住了自动通过/退回） | Warm-Flow 原生（1.8.5+ 超时自动审批） | 节点配超时小时数 + 超时后"自动通过/退回"，兜底防流程死卡 |
| **审批"催办提醒"**（到 4h 催一次、再 4h 再催） | **ERP 定时任务**（扫 `warm_flow_task` 待办，create_time 超阈值的 → 发通知） | Warm-Flow 没内置重复催办，自己用定时任务补；调用通知通道 |
| **业务预警**（交期风险/库存低于安全线/证件到期/社保核对超期/宿舍待退房…） | **ERP 各模块 Service + 独立定时任务**（查满足条件的单据 → 调统一通知方法） | Warm-Flow 不管业务数据；全走本清单第二节的"统一预警规则表" |

**通知通道（复用，不各模块各写）：**
- 参考 RuoYi-Vue-Plus 的 `WorkflowGlobalListener` / `IFlwCommonService` 实现：
  - **站内信**（SSE 实时推送）— 默认
  - **邮件**（SMTP）
  - **短信**（按需接服务商，一期可留 TODO）
- 各模块预警/催办 触发时统一调一个 `sendMessage(渠道, 对象, 内容)` 方法，**通道集中封装一处**（踩"不重复造轮子"）。
- 渠道选型（站内/企微/钉钉/短信 各要哪几个）= 本清单第四节"成套定稿"要拍的一项。

**与钉钉的差距（自知，不硬上）**：钉钉那种"按工作日/重复 10 次/排除非工作时段"的精细催办，Warm-Flow 没内置；要精细就业务层定时任务自己扫。一期先做"到点催一次/可配次数"，够用了不上复杂策略。

**对技术栈的约束（重要）**：Warm-Flow 是 Java 引擎、参考实现 RuoYi-Vue-Plus 也是 Java/Spring 系 → **选 Warm-Flow ≈ 技术栈往 Java/Spring 靠**。这与知识库那套"往 Python 推（Chroma/LM Studio）"有张力，**定技术栈时必须一起定**（Java 栈：Warm-Flow+RuoYi 顺；Python 栈：审批得换 Python 系等价物或单独起个 Java 小服务跑 Warm-Flow）。

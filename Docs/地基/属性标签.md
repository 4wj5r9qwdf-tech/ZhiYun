# 属性标签（地基，全模块通用）

> 版本：v1.4
> 更新日期：2026-11-08
> 说明：全模块通用的"可扩展属性"机制。业务模块不预置，模块第一次通过业务功能添加标签时自动登记归属；后续统一在标签管理中维护，不各造各的枚举。

---

## 一、核心模型

**标签 = 动态功能归属 + 功能内分组 + 自由标签名**。导航模块和业务功能是两层归属；分组归属于具体功能，标签名仍由用户灵活维护。

```
标签记录 = [导航模块 module] + [功能命名空间 module_key] + [分组 group_id] + [手填标签名 tag_name]
         = 研发 + 款式档案 + 适用人群 + 童装
```

- **功能归属**：每个业务功能固定传入稳定的 `module_key` 和功能显示名 `module_name`；导航模块由前端功能目录映射，用户不选择、不填写归属前缀。
- **标签名**：自由文本，随手加（想加"独卫""无烟""陪护"都行，不用维护大字典）。
- **标签分组**：属于具体功能，同一名称的分组可在不同功能独立存在。每个功能动态建立“默认分组”；未指定分组的新标签和已有未分组标签都进入默认分组，用户之后可调整。
- **同名规则**：同一功能、同一分组内标签名不区分大小写去重；不同分组允许使用同名标签，筛选和报表保留分组语义。

## 二、命名空间（业务功能动态登记）

- 已有功能允许按业务需求预置标签分类和部分常用标签；其余功能仍可在首次使用时动态登记。初始化内容由项目维护并写入主建表，用户可继续新增自定义分类和标签。
- 某业务功能首次输入新标签时，`TagSelect` 将该功能的 `module_key`、`module_name` 和标签名一起提交；服务端在同一事务中幂等登记功能归属、默认分组和标签档案。业务组件未指定分组时一律进入默认分组。
- `module_key` 由功能代码提供且保持稳定（如 `customer_master`、`prod_sample`）；`module_name` 是功能显示名（如“客户档案”“样衣”）。导航模块与功能的映射来自前端统一功能目录。同一功能后续传入新的显示名时同步更新目录名称。
- 标签管理树按“导航模块 → 功能 → 分组”呈现；功能和分组来自真实登记数据。手动新增标签仅针对已有功能及其分组。已纳入初始化的功能可预置分类，其余功能继续动态登记。
- `module_key` 只允许小写英文字母开头，后续可含小写字母、数字和下划线，最长 50 位；同功能同分组内标签名不区分大小写去重，不同功能或分组可使用同名标签。

## 三、存储与查询（不跨功能）

- 标签目录存入 `sys_tag_module`、`sys_tag_group`、`sys_tag`；`sys_tag_module.module_key` 代表功能，不是导航模块。导航模块由功能目录映射；左侧树完整呈现“导航模块 → 功能 → 分组”。业务记录关系存入 `sys_tag_relation`，以 `module_key + record_id + tag_id` 标识。
- 每个功能都有“默认分组”；既有未分组标签迁入默认组时必须保留 `tag_id` 和业务关联。默认分组不可删除或重命名；自定义分组仅在无标签时可以删除。
- **查询永远带功能命名空间 `module_key`**，标签选择值使用稳定 `tag_id`，同名标签不会跨功能串用。
- 标签只在它所属功能内生效、内筛、内统计，**不跨功能共用**。

## 四、自由文本 + 常用词提示（防同义不同词）

- 标签名自由输入（非锁死枚举）。
- 在业务功能中提交新标签后，系统自动将其纳入该功能“默认分组”，供后续提示、筛选和复用；按“module_key + group_id + 标签名”去重，不重复创建相同标签。
- 管理员可以把已有标签标记为常用，业务组件将其作为**"常用标签"下拉提示**（点一下填入，不是限制，手敲别的照样行）。下列是可由业务维护的示例，具体预置内容以主建表初始化清单为准：
  - 宿舍常用词：双人 / 夫妻 / 独卫 / 无烟
  - 食堂常用词：荤素档 / 自助 / 清真
  - 车辆常用词：通勤班车 / 公务
- 常用词是"提示不是限制"，日常用词筛得准，特殊情况自由写。
- **目的**：全自由的最大坑是"双人/双人间/2人"同义不同词筛不到一起，常用词提示把这个坑填掉，又保留自由。

## 五、什么用标签、什么不用标签（红线）

- **属性用标签**：描述"它是什么样"的可扩展属性（双人/夫妻/独卫/清真/通勤…）→ 标签
- **结构/状态用固定字段**："它有几个/什么状态"这类骨架（床位数、空/有人/锁定、金额、日期）→ **必须固定字段，不做进标签**
  - 理由：标签是给筛选/展示的描述、可多可少；结构/状态是业务骨架（入住退房、查询、计算都靠它），模糊成标签会查不动、算不了。

## 六、各模块落地对照（引用本地基，不重造）

标签管理左侧树固定按“导航模块 → 功能 → 分组”呈现。导航模块节点只负责展开；点击功能时右侧显示该功能所有分组的标签，点击分组时只显示该功能、该分组的标签。汇总查看时表格明确显示功能名称和分组名称。手动新增标签只能选择已有功能和该功能的分组；从功能或分组节点新增时自动带出对应功能和分组。业务选择器按分组展示选项。编辑标签可在同一功能内调整分组，但不能迁移功能归属，避免破坏已有业务关联。

业务组件选项值使用 `tag_id`，而不是标签名称；业务记录保存时以 `module_key + record_id + tag_id` 写入 `sys_tag_relation`。标签档案接口返回规范标签记录，包含 `tag_id`、`module_key`、`module_name`、`group_id`、`group_name`、`tag_name` 等字段。`module_name` 是功能名称，导航模块由功能目录映射。标签目录自动收录不等于已经建立具体业务记录关联，关联仍由对应业务保存流程完成。

下表是规划中的标签应用场景，不表示这些模块或标签会被系统预置；模块出现后仍由实际业务人员录入标签。

| 模块 | 标签归属显示名 | 用标签放什么 | 固定字段（不做进标签） |
|---|---|---|---|
| 宿舍 | 宿舍房间 | 双人/夫妻/独卫/无烟… | 房间号/楼层/床位数/床位/状态 |
| 食堂 | 食堂 | 荤素档/自助/清真… | 餐档名/档口/单价/状态 |
| 车辆 | 车辆 | 通勤班车/公务… | 车牌/车型/驾照人/状态 |
| 物品 | 物品 | 可流通/固定/易损… | 物品名/所在房间/数量/状态 |
| 客户档案 | 客户档案 | 品牌方/贸易商等客户类型提示；可自由新增 | 客户名称/编号/状态 |
| 人员信息 | 人员信息 | 员工可扩展的分类属性 | 工号/姓名/岗位/状态 |

**规则：任何新功能要"可扩展属性"，先查本文件；使用统一标签组件，功能归属默认动态登记，不预置空功能或标签，不自建枚举、不另起一套。明确的业务初始提示按上文例外在对应功能初始化，并保留自由新增能力。**

## 七、已确认的业务初始化例外

- **仓库管理**：用户要求仓库至少覆盖成品仓、面料仓、辅料仓、消耗品仓、设备仓，并为一车间的样衣配置样衣仓。初始化这六个常用类型标签；仓库实体仍由用户按实际车间/楼层/区域建立，标签仍可自由新增。

分类与标签统一入口分别复用；正式分类的数据授权遵守人员分类范围，标签不得绕过分类权限。统一依据见[分类引用、人员分类权限与业务默认定位契约](分类引用与人员分类权限.md)。


## AI 与沙盘相关标签规划（2026-11-19，待专项设计）

继续采用现有功能命名空间、功能内分组和标签关系，不另建平行 AI 标签库。每种基础档案设计时同步梳理分组、适用对象、维护责任人、可见范围、来源和更新规则。人员可按家庭情况、工序工艺、服装类型、设备经验、培训认证和工作时间偏好等分组，具体分类与标签由实际业务配置。

班组可记录工艺和品类特长，设备可记录适用工序和材料，供应商及外协厂可记录供货或加工特征，款式和物料可记录技术及使用特点。标签支持检索与匹配；技能等级、数量、实际状态、时间、产能和价格等以对应结构化业务记录为准。

拟扩展标签来源、证据、审核、有效期和历史能力时先核对现有模型并形成专项设计。AI 可以提出候选标签，正式生效、更新和撤销遵循业务审核。家庭照护等敏感内容由本人自主申报并限制访问，排程优先读取经授权的可用时间，不用标签推断个人情况。

## 面向 AI 与订单沙盘的标签体系完善（2026-11-19，规划）

### 结构与适用范围

织云标签中心作为 ERP 公共能力使用。业务语义为“功能 → 功能内标签分类 → 具体标签”；现有界面还包含上层导航模块。功能以稳定的 `module_key` 区分，分类对应现有标签分组，同名标签在不同功能或分组保留各自含义。业务记录通过标签关系关联，不把所有功能的标签混成一个没有归属的目录。

现有代码已有功能、分组、标签及关系维护能力。下表是后续梳理和实施的业务目录，不代表分类已配置，也不自动预置标签；用户可继续增删调整。新增功能沿用动态登记和功能内管理规则。

| 功能或对象 | 标签分类方向 | 典型用途与边界 |
|---|---|---|
| 人员信息 | 技能、工序熟练度、服装类型经验、工作能力、工作时间与排班约束、请假与出勤状态、家庭情况自主申报 | 查找候选工人。实际等级、某日可用性、请假和任务以业务记录为准 |
| 班组管理 | 工序能力、产品类型、技能覆盖、生产效率、支援能力 | 识别候选班组，实际技能组合及时间窗需由人员、设备和任务计算 |
| 设备管理 | 设备类型、适用工序、面料、产品及设备能力 | 辅助匹配，设备参数、状态、维修日历和占用单独核验 |
| 车间与产线 | 工序能力、产品生产能力、产能等级、生产限制 | 发现可能的生产场地与产线，实际产能和冲突按日期计算 |
| 工艺管理 | 工艺类型、难度、特殊工艺、外协工艺 | 识别工艺特征，是否必须外协由正式能力和规则判断 |
| 工厂能力 | 工厂具备或不具备的加工工艺 | 对接正式能力档案，结合状态和产能，避免仅用标签判断 |
| 供应商管理 | 物料供应能力、物料品类、交付能力 | 辅助筛选，数量、报价、到货及实际档期从业务数据读取 |
| 外协厂管理 | 加工工艺、产品加工、质量、产能、交付与合作评价 | 匹配候选外协厂，结合实际产能、交期、质量和运输 |
| 款式档案 | 产品特征、工艺难度、特殊要求、质量风险 | 关联款式及版本，实际工艺路线和 BOM 分开维护 |
| 物料档案 | 材料特征、适用工艺、采购属性、储存要求 | 分类筛选，规格、单位、损耗和可用量使用正式字段 |
| 仓库管理 | 仓储条件、物料适用范围、安全与特殊存储要求 | 辅助匹配，实际库容、库位、库存状态和占用由仓储记录确定 |

人员家庭情况与工作可用性分开。家庭信息由本人自主申报并限制查看；如周末照顾孩子，可在授权范围记录工作时间偏好。某个周末的可用状态结合正式排班、审批请假、已分配任务和本人确认，未确定标记“待确认”。标签不能代替请假审批，也不能推断员工家庭情况。

### 能力识别与沙盘调用

订单进入沙盘后，先按款式版本和正式工艺路线拆出需要的工序，再按对象所属功能及标签分类查询员工、班组、设备、工厂和外协厂的候选能力。标签只产生候选或提示，随后读取有权限的结构化能力、日历、状态及已分配任务。

工厂能力至少区分“明确不具备”“具备但当前产能不足”“具备且存在可用产能”“具备但当前不可用”“资料不足待核实”。需要印花或水洗时，只有正式资料和规则明确工厂不具备该工艺才判断必须外协；能力未知应报告缺失。厂内产能不足时比较延后、可授权加班、跨组支援和外协等方案，并说明假设及审批条件。外协匹配结合工艺、质量、产能时间窗、价格、运输和交期，形成候选，不能只凭标签自动下单。

跨组支援先筛选员工和班组的工序、产品及设备经验，再验证技能证据、可出勤时间、任务冲突和原班组最低保障；比较调入与调出对全部受影响订单的结果。全程使用同一订单场景与时间快照。

### 标签属性与 AI 建议生命周期

后续专项设计需区分**标签定义**与**对象上的标签关联**。定义侧评估功能、分类、名称、系统/自定义类型、说明及允许使用范围；关联侧评估对象、来源、证据、提出人、确认状态、审核人、生效/失效时间和变更历史。可信程度如“待确认、已确认”，应与算法置信度分开定义。来源可包括人工、系统规则、业务记录及 AI 建议。数量、效率、交期和产能不以标签替代。

AI 可基于授权的报工、有效工时、产量、质量、返工率、工序难度、培训和最近使用时间提出新增、调整或失效建议，并说明统计区间、依据和局限；不按完成次数单独认定熟练等级。设备、班组、供应商和外协能力建议同理。关键技能认定、权限和排产资格在规则校验或有权业务负责人确认后生效。待确认、过期、撤销或冲突标签不得悄悄作为确定性能力使用；沙盘记录采用的状态和数据版本。

### 待专项确认与验收

1. 各业务功能的标签分组清单、维护人、可见范围、敏感信息授权、系统标签生命周期及批量变更规则。
2. 标签与工序、技能等级、设备和外协能力主数据的关联方式，同义词及跨功能映射由受控业务关系维护，不能按名称自动等同。
3. 工厂能力的肯定、否定、未知及冲突处理，标签失效或业务证据过期时的提示与复核。
4. AI 建议的数据窗口、质量门槛、规则校验、审核责任、撤回及审计。标签是否影响排产资格需单独确定。
5. 验收覆盖同名标签分组隔离、权限过滤、标签与业务数据不一致、过期和冲突、周末待确认、跨组支援及外协能力缺失。分别验证目录登记、API、MCP 工具发现和实际授权调用。


## 现有功能初始化与后续新增（2026-11-19）

首批初始化覆盖人员信息、物料档案、款式档案、客户档案、仓库管理、尺码及尺码组。分类和常用标签按功能隔离，完整清单见 sql/标签分类初始化_20261119.sql，并已合入 sql/主建表.sql。初始化不会给任何员工或其他业务对象自动打标签。若已有同功能同名标签，保留原标签及其分组，不自动迁移关联、不覆盖状态；因此现有标签可能仍在默认分组，需由有权人员按实际业务整理。

人员信息和物料档案当前尚需完成业务页面与标签关联接入，目录预置不代表对应功能已支持选择、授权或智能体调用。后续新增功能设计时同步确认分类、常用标签、功能标识及权限，作为该功能初始化 SQL 的一部分合入主建表；重复执行不得覆盖客户自定义数据。

# 属性标签（地基，全模块通用）

> 版本：v1（定稿）
> 更新日期：2026-10-23
> 说明：全模块通用的"可扩展属性"机制。任何模块需要"给一条记录贴若干属性"（房间的双人/夫妻、餐档的荤素/清真、车辆的通勤/公务…）时，统一用这套，**不各造各的枚举**。与《开发规范》"不重复造轮子"配套。

---

## 一、核心模型

**标签 = 模块前缀 + 自由标签名**，前缀跟模块走、系统自动带，填标签的人**只填"标签名"，不填前缀**。

```
完整标签 = [模块前缀（系统自动带）] + [手填的标签名（自由文本）]
         = 宿舍.  +  双人
```

- **前缀（命名空间）**：跟模块绑定，固定。宿舍模块的标签天生是 `宿舍.`，食堂的天生是 `食堂.`，**填标签时不填、也不能填前缀**。
- **标签名**：自由文本，随手加（想加"独卫""无烟""陪护"都行，不用维护大字典）。

## 二、命名空间（模块 ↔ 前缀）

- 一张**"标签命名空间"表**：模块 → 前缀（如 宿舍=`宿舍`、食堂=`食堂`、车辆=`车辆`、物品=`物品`）。
- **建模块时定一次，平时不动**（只有新增模块才加一行）。
- 前缀命名用**中文模块名**（跟项目"文档/功能名用中文"的取向一致），代码层存模块标识、展示层存中文前缀，映射固定。

## 三、存储与查询（不跨模块）

- 每条记录（房间/餐档/车辆…）挂一组标签，存成：
  - 方式 A（推荐）：标签表 `record_id + module + tag`（三列），一记录多标签
  - 方式 B：一列 JSON 数组（模块内标签集）
- **查询永远带模块前缀**：筛宿舍房间 `WHERE module='宿舍' AND tag=…`，**天然不会把食堂的标签串进来**。
- 标签只在它所属模块内生效、内筛、内统计，**不跨模块共用**。

## 四、自由文本 + 常用词提示（防同义不同词）

- 标签名自由输入（非锁死枚举）。
- 每个模块给一份**"常用标签"下拉提示**（点一下填入，不是限制，手敲别的照样行）：
  - 宿舍常用词：双人 / 夫妻 / 独卫 / 无烟
  - 食堂常用词：荤素档 / 自助 / 清真
  - 车辆常用词：通勤班车 / 公务
- 常用词是"提示不是限制"，日常用词筛得准，特殊情况自由写。
- **目的**：全自由的最大坑是"双人/双人间/2人"同义不同词筛不到一起，常用词提示把这个坑填掉，又保留自由。

## 五、什么用标签、什么不用标签（红线）

- **属性用标签**：描述"它是什么样"的可扩展属性（双人/夫妻/独卫/清真/通勤…）→ 标签
- **结构/状态用固定字段**："它有几个/什么状态"这类骨架（床位数、空/有人/锁定、金额、日期）→ **必须固定字段，不做进标签**
  - 理由：标签是给筛选/展示的描述、可多可少；结构/状态是业务骨架（入住退房、查询、计算都靠它），模糊成标签会查不动、算不了。

## 六、各模块落地对照（引用本地基，不重造）

| 模块 | 前缀 | 用标签放什么 | 固定字段（不做进标签） |
|---|---|---|---|
| 宿舍 | 宿舍 | 双人/夫妻/独卫/无烟… | 房间号/楼层/床位数/床位/状态 |
| 食堂 | 食堂 | 荤素档/自助/清真… | 餐档名/档口/单价/状态 |
| 车辆 | 车辆 | 通勤班车/公务… | 车牌/车型/驾照人/状态 |
| 物品 | 物品 | 可流通/固定/易损… | 物品名/所在房间/数量/状态 |

**规则：任何新模块要"可扩展属性"，先查本文件，套"模块前缀 + 自由标签 + 常用词提示"，不自建枚举、不另起一套。**

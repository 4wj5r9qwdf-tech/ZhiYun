# 分类引用、人员分类权限与业务默认定位契约

> 确认日期：2026-11-06。状态：人员分类权限基础设置已于 2026-11-20 用户验收通过；业务默认定位及未接入业务的分类过滤仍按模块逐步实施。
> 本文是本主题的统一依据。人员分类权限基础设置验收不代表所有业务模块、业务默认参数、批量授权和授权范围预览均已完成。

## 一、统一入口与职责

分类类型和各级分类统一在分类管理维护；标签统一在标签管理维护。采购、出入库等公共业务复用基础资料，不按食堂、设备、办公用品分别重复建设采购系统或分类目录。

| 能力 | 职责 |
|---|---|
| 分类管理 | 管理类型、分类树及基础资料归属 |
| 人员信息中的分类设置 | 限制本人能看到的分类及下属基础资料，配置入口在人员信息，不放在角色中 |
| 业务参数 | 提供默认分类类型或分类及其下基础资料的展示定位，不限制可选范围 |
| 角色及组织数据权限 | 管理功能操作权限及既有公司、组织等数据范围 |
| 公共选择器 | 在有效授权范围内展示分类、搜索资料、跨分类选择 |

分类表示物品归属；标签表示可扩展属性。库存管理方式、资产身份、业务状态、审批和记账规则使用明确字段与流程，不从分类名称或标签推断。业务用途与明细分类分别保存：食堂采购可以同时采购食材、办公用品和设备，后续处理依据具体资料的管理方式。

## 二、人员分类授权

人员身份关联稳定员工ID，不按姓名、工号文本或岗位名称绑定。授权由具有人员分类权限配置权限的管理员维护，人员自助资料编辑不得修改自己的授权。

人员分类授权分为全部可见、指定范围和全部不可见三档。人员未单独设置时默认全部分类可见，仍须符合公司、组织和功能权限。保存全部可见时清除人员单独授权。指定范围至少选择一项。

### 已验收的人员设置范围（2026-11-20）

- 人员信息中可配置全部可见、指定范围和全部不可见；配置入口使用独立权限 `system:person:categoryScope`，由角色单独授予或撤销。
- 指定范围按分类类型和分类树勾选，父级操作带出子级，子级可单独调整；页面提供无权提示，已接入业务在服务端执行分类过滤。
- 以上为基础人员分类权限设置验收范围。批量设置、复制其他人员授权、有效范围预览，以及各业务自己的默认分类参数和未接入业务过滤不在本次验收结论中。

指定范围支持勾选整个分类类型、分类分支或具体节点。选择分支时明确“包含下级”，授权覆盖当前与未来新增下级及其基础资料；仅授权节点本身时不得隐含授权其后代。只为显示路径出现的祖先节点不代表获得该祖先下其他资料的权限。

同一人员的正向分类授权取并集；再与既有公司、组织、资料自身数据权限取交集，并校验功能权限。多岗位、多角色的权限并集不能扩大人员分类授权。超管例外沿用现有权限体系且必须明确显示；智能体不得借用超管身份执行。

支持批量设置、从另一人员复制、查看有效范围。复制为当次授权快照，不建立隐含跟随关系。应用前展示目标人员、原范围、新范围及覆盖方式；不得默默覆盖原授权。权限维护本身受管理范围限制，不能给无权管理的人员配置或授出自己无权分配的范围。

## 三、业务参数和默认展示

| 条件 | 页面行为 |
|---|---|
| 没有配置默认分类 | 展示人员权限范围内全部分类及下属基础资料 |
| 默认分类有效且本人有权限 | 定位该分类，展示其下资料，仍可切换到其他授权分类 |
| 默认分类无权限、已停用或失效 | 提示默认定位不可用，回到授权范围内全部分类 |
| 人员无任何可访问分类 | 显示权限受限说明，不展示普通空数据状态 |

默认定位不等于自动选中某物品、填写采购数量或加入单据。默认参数变化不得覆盖用户已主动选择的分类、资料或明细。新增采购选择默认覆盖所有类型，再按人员权限过滤；不得根据采购用途把其他已授权类型排除。业务默认分类不是分类白名单，也不是权限配置。

## 四、分类与基础资料跨模块引用

业务配置和授权使用稳定分类类型ID、分类节点ID；数字编码、名称用于展示，不能通过名称模糊匹配、编码前缀推断权限或在各页面写死01、03等编码。现有按schemeCode查找类型的选择器是已有能力，实施本契约时需接入公共授权和默认配置，不能当作已经完成本契约。

基础资料保存明确分类归属。采购明细引用真实资料身份；物料、设备等来自不同实体时必须保留资料种类和稳定ID，不能把不同表中相同数字ID视作同一物品。分类ID不能代替物品ID。接口传输大整数ID使用字符串。

物料、办公用品、食堂物资等跨采购、库存、领用功能共享基础资料。设备资产保留一机一码及资产流程；设备分类不等于设备仓标签。款式分类供款式档案使用；食堂物资与菜品属于不同对象，需要分类时明确各自用途。截图中的类型名称、编码仅为当前业务录入，不自动改名或作为系统预置映射。

受分类权限保护的基础资料新建时必须选择有效分类；历史未分类资料进入有管理权限的整理入口，不通过“未分类”绕过权限。多分类归属如后续确有需求，需明确授权命中规则，不能用任一辅助标签扩大可见范围。

## 五、选择页面与防呆文案

公共选择器提供分类类型、分类树、编码/名称/规格搜索和已选资料区。搜索支持当前分类与授权范围内全部，并清楚显示搜索范围。切换分类、搜索、分页不丢已选项；已选项展示名称、编码、规格、分类和资料种类，支持移除，重复选择提示或定位已有项。一张单据支持不同分类明细。

| 场景 | 统一提示与处理 |
|---|---|
| 正常展示 | 当前仅展示您有权查看的分类及基础资料。如未找到所需内容，请联系管理员核对分类权限。 |
| 搜索无结果 | 在您有权查看的范围内未找到匹配资料。请检查搜索条件；如确认资料已录入，请联系管理员核对分类权限。提供清空筛选。 |
| 没有任何授权范围 | 您尚未获得分类及基础资料的查看权限，请联系管理员配置。 |
| 有权限的分类下无可见资料 | 当前分类下暂无可查看的基础资料。有新增权限时提供新增入口。 |
| 默认分类不可访问 | 当前业务配置的默认分类不可用，已展示您有权查看的全部分类。不得泄露未授权分类名称。 |
| 权限变化 | 您的分类权限已发生变化，请刷新可选资料。提交时指出已不可用的当前选项。 |
| 加载失败 | 加载失败，请重试。不得伪装成无数据或无权限。 |

“全部分类”“全部范围”均明确指权限范围内全部。无权限分类名称、物品、数量、搜索命中存在性不得泄露；不可通过“系统存在某物品但无权限”提示暴露受限资料。直接访问未授权或不存在的资料，使用不泄露存在性的统一不可访问提示。

## 六、服务端统一执行与变更生效

公共权限能力统一覆盖分类树、基础资料列表、详情、编码直查、模糊搜索、数量统计、分页总数、导出、导入、新增修改、业务引用保存、API、MCP和智能体。先按权限过滤再计算统计与分页，不能前端隐藏后仍返回未授权原始数据。

保存时重新校验本人权限、分类归属、类型/祖先/节点有效性及资料可用性；不能信任前端传来的分类ID或缓存选项。打开弹窗后收权或停用，提交必须拒绝失效的新引用，并保留其余草稿供用户修正。

权限缓存按人员隔离，资料查询缓存不得跨人员串用。授权、分类移动、资料改分类后及时失效相关缓存；退出登录和切换人员清理旧选项。批量与异步导出执行时也必须校验执行身份和有效权限。

分类移动、资料改分类会改变可见人群；操作前提示影响，服务端校验维护权限，保存后按新归属生效。权限修改与资料引用并发时，实施中必须明确事务/版本校验方式，避免以过期授权落库。

## 七、历史单据和跨人员协作

基础资料选择权限不等于单据查看权限。已获单据查看权限的人员按单据规则查看完整明细与合计，不因分类限制静默隐藏明细、篡改合计或让审核人审核不完整内容；单据查看不授予打开实时基础资料详情、新选该物品或导出完整档案的权限。

历史资料名称、规格等按单据快照规则保留。分类停用、收权不得静默删除或改写已存在单据。编辑旧单据保留历史引用；新增、替换、复制单据和再次引用须重新校验当前权限。旧明细数量、价格等修改仍遵守单据编辑权限和状态规则，不能以保留历史引用绕过业务校验。

发起人、采购员、仓管、审核人分别使用各自身份及对应操作权限。单据在人员间流转不复制发起人的分类授权；接收人可处理哪些动作由单据流程明确规定，不能给其临时冒用发起人权限。混合分类单据须保证授权查看和审核时内容完整。

## 八、审计与实施顺序

记录操作者、目标人员、操作时间、授权模式、分类ID及可读名称快照、包含下级标志、变更前后值、复制来源、批量逐项结果。分类移动、资料改分类、业务默认参数修改也记录前后值；拒绝访问日志供授权管理员排查，不向普通用户泄露资料。

人员授权模型、服务端范围解析和人员配置入口已完成并通过用户验收。后续实施顺序：各业务的默认分类参数与公共资料选择器一并交付；采购、库存、设备等按开工顺序接入；API、Skill、MCP和验收同步。实际表名、接口字段、权限码及迁移脚本在实施任务中定稿。不得仅完成前端筛选就标记权限落地。

首个实际使用分类选择的业务开工时，在「参数设置 → 业务默认分类」增加设置项，并与该业务选择器一并验收。如果采购先开工，首项就是「采购选品」。后续业务接入时在同一入口增加设置项。验收覆盖留空时展示本人全部授权范围、默认定位、切换授权分类及默认分类不可用时回退。

## 九、跨模块验收清单

- 无默认参数显示全部授权分类；有默认时可切换其他授权类型；无权默认正确回退。
- 三种人员配置状态区分，未设置回显全部可见；指定范围空值不变全部；超管及普通人员行为明确。
- 类型、分支、节点授权及未来下级生效正确；祖先路径不扩大授权。
- 人员分类范围与公司/组织范围交集生效；角色叠加不越过分类限制。
- 搜索、详情、统计、导出、导入、API、MCP、智能体不能绕过；缓存不串人。
- 无权限、无数据、无结果、加载失败四种状态文案正确，不泄露受限存在性。
- 混合类型采购、跨分类/跨页勾选、重复提示、资料种类和ID区分正确。
- 权限变更、停用、分类移动、资料改分类及并发提交正确生效并留痕。
- 历史单据完整可见、快照保留；实时档案、新引用、复制单据仍校验当前权限。
- 批量授权、复制、有效范围预览和审计可追溯；普通人员不能自我授权。

人员分类权限配置通过角色功能权限“人员信息 → 分类权限设置”单独授予（`system:person:categoryScope`），授权人员只能维护其人员数据范围内的普通人员；非超管不得修改本人的分类权限，变更记录业务审计。新增权限登记后须由管理员分配给相应角色。

# 员工ID 与工号规则（地基，全系统通用）

> 版本：v1（定稿）
> 更新日期：2026-10-23
> 说明：本规则是全系统的主键/查询/历史记录基准，任何模块涉及"人"的数据一律遵守。与《开发规范》《权限与组织树》配套。

---

## 一、两个标识各管一摊（定死）

| 标识 | 属性 | 用途 |
|---|---|---|
| **员工ID** | 建号定死、终身不变、对外不展示、系统内部生成 | **唯一稳定主键**，所有跨模块外键挂它 |
| **工号** | 六位数字、随调组/调车间/调部门**变更**、离职释放、可回收复用 | 登录名 + 当前可读编码；**不存进业务表当外键** |

## 二、工号是"号码段资源"，不是"人的标签"

- 工号按**车间/组号段管理**（号段划分规则后期定，一期手填 + 唯一性校验）。
- 调组/离职 → 原工号**释放回号段池**，可被同段新入职者复用。
- 因此工号会随人变、会复用、**不能作为稳定追溯依据**。

## 三、历史记录规则（红线）

1. **操作流水类记录（报工、打卡、审批动作、宿舍入住等）只存 `员工ID`，绝不存工号**（存当时的、现在的都别存——工号会复用，存了会误导）。
2. **单据类记录（工资单、发货单、外协单等"已交付、印出去就定格"的单据）冗余存一份"当次工号快照"**（打印时定格），其余仍挂员工ID。
   - 判据：该记录会不会被"打印/交付/对账"引用旧号 → 会则存快照，不会则只存ID。
3. **查询/报表展示工号**：一律用 `员工ID → 当前工号+姓名` 实时反查（走下方集中壳），显示"当前态"；单据展示用"当次快照"。

## 四、集中套壳（当前态查询专用）

- 登录、查在职员工 = "当前工号 → 员工ID"，由集中的**人员访问层**统一实现，业务代码**禁止裸 SQL 用"工号"做条件**。
- 壳只查**当前工号**，**不解析历史工号**（历史追溯靠"员工ID + 单据快照"，不靠工号反查）。
- session 存员工ID（不存工号）：登录后调组改工号不影响登录态。

## 五、号段池管理（一期手动，后期自动化）

- 每车间/组维护号段池：已用 / 空闲 / 保留。
- 离职/调组 → 工号标"空闲"进池；新入职 → 从对应段领一个空闲号（防重号）。
- 一期：手填工号 + 系统校验唯一；"工号自动生成规则"属后期。

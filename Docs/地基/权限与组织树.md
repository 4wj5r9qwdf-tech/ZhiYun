## 一、定位与三要素模型（定死，别混塞）

| 要素 | 承载什么 | 载体 | 变更粒度 |
|---|---|---|---|
| **岗位** | 默认值发生器（新建员工时带出默认角色的取值器），不是权限本体 | sys_post（岗位字典）+ 岗位-默认角色关联 | 新建员工时定，一般不动 |
| **角色** | **权限本体**（功能权限 + 数据范围规则） | sys_role（角色字典）+ 角色-功能权限关联 + 角色-数据范围规则 | 管理端配，改=换配置不改代码 |
| **组织树** | **数据范围**（这个人能看/操作哪个范围的数据） | org_node（组织节点树，含部门/车间/组/办公楼） | 建厂/调组时定，挂员工ID |

**一句话**：**岗位是取值器、角色是权限本体、组织树是数据范围**。任何模块要问"这个人能不能干这个事、能看到哪些数据"，一律查这一套，不各造各的。

### 1.1 权限计算公式（一人多岗多角色，取并集）

某员工的最终权限 = (主岗默认角色 ∪ 兼岗默认角色 ∪ 手工叠加角色) 的功能权限并集 + 该员工挂的那 1 个组织节点所对应的数据范围。

- **一人主岗 1 个 + 可叠加 N 个角色 + 挂 1 个组织节点**（定死，与《系统需求规划.md》模块清单地基栏、《岗位与角色清单.md》表头模型一致）。
- 岗位、组织节点的变更走《地基/员工ID与工号》的调组/调岗流程（挂审批或直接改，按各模块规则）；角色叠加/收回在管理端配，即时生效。

## 二、组织树（数据范围的物理载体）

### 2.1 结构（按厂实况建，不写死层级深度）
- 组织节点类型：**公司 → 部门/办公楼 → 车间 → 小组**（厂实况：三车间 + 行政楼 + 办公楼，体现进组织树）。
- 员工**只挂一个组织节点**（主属）；兼岗/跨组协作不另开节点（避免数据范围打架，与《模块-人员管理.md》一人多职位节一致）。
- 节点可自建/停用/移动，支持树形层级；一个节点下可挂多个员工。

### 2.2 数据范围规则（角色的数据范围挂这里，不是写死在代码）
| 范围类型 | 语义 | 典型角色 |
|---|---|---|
| 本组织节点 | 只看自己挂的节点 | 一线工人、组长 |
| 本节点 + 所有子节点 | 看本节点及下属全部节点 | 车间主任、部门经理 |
| 指定节点集合 | 看若干指定节点（跨部门协作） | 总监、计划部跨车间排产 |
| 全厂 | 看所有节点 | 厂长/副厂长、超管、财务 |
| 本条线/本线体 | 看同一条产线（缝制/后整车间内细分） | 拉长、线内质检 |
| 本记录创建人 | 只看自己创建/经手的记录 | 报工人看自己的报工 |

- **范围规则存配置，不写死代码**：每个角色挂一条数据范围规则（类型 + 可选的指定节点集合），查询时由统一数据权限层按"员工ID → 组织节点 → 角色数据范围"过滤。
- **同一个人多角色取并集**（能看的范围合并，不是交集）；跨范围冲突时按"并集"看，不出现"有权限看不见"的怪现象。

### 2.3 三车间/行政楼/办公楼进组织树的落点（对应厂实况）
| 组织树节点 | 类型 | 说明 |
|---|---|---|
| 行政楼 | 部门/办公楼 | 行政、人事、财务、后勤（宿管、食堂、清洁、保安） |
| 办公楼 | 部门/办公楼 | 业务、跟单、计划、技术（版房、工艺、IE） |
| 一车间 / 二车间 / 三车间 | 车间 | 裁剪、缝制、后整、质检（按厂实况可合并/拆分车间粒度） |
| 各车间下的小组 | 小组 | 裁剪组、缝制组、后整组、质检组、包装组（小组数量不限，自建） |

## 三、岗位与默认角色（岗位带出角色，角色承载权限）

### 3.1 岗位字典
- 权威源：《服装加工厂岗位列表.md》（26 类分组、197 岗位/职务）。
- 岗位字典表 sys_post：岗位编码 / 岗位中文名 / 岗位英文名 / 所属组织节点类型（可选）/ 是否启用 / 备注。
- **一个岗位可挂多个默认角色**（如"生产主管"挂"生产管理"+"排产操作"；"质检员"挂"质检操作"+"质检判定"）。

### 3.2 岗位 → 默认角色映射（运行时配置）
- 本文只定义映射原则，不维护岗位逐项映射示例；岗位分类、角色候选及待确认岗位粒度统一见《岗位与角色清单.md》。
- 该清单是配置参考，不是系统预置数据或已生效权限；实际岗位、角色与关联关系由超管按工厂组织情况在管理端配置。
- 权限映射的权威依据仍是本文件的一、二、三、五节；岗位候选清单不得改变权限模型、数据范围规则或敏感数据边界。
- **一个员工可挂多个岗位**（主岗 + 兼岗），每个岗位各带各的默认角色，**最终权限 = 所有岗位对应角色的并集**（与《模块-人员管理.md》一人多职位节一致）。
- 临时工 = 岗位“临时工”，跟正式工同表，权限走岗位差异配置（社保/宿舍/计酬差异），不单独建权限体系（与《模块-人员管理.md》二、临时工节一致）。

### 3.3 角色承载功能权限（细到功能卡片/操作按钮）
- 每个角色挂若干**功能权限码**（对应《前端规范.md》角色过滤节的"权限码"）：权限码 = 模块 → 二级分类 → 功能卡片 → 操作按钮（如"生产管理/订单/订单列表/新增订单"）。
- 权限码存 sys_permission 表（编码/名称/所属模块/所属功能/类型[菜单/按钮/接口]/启用），前端按权限码过滤显示，后端按权限码拦截接口（与《API文档规范.md》权限要求字段、《开发规范.md》安全性第 4 条一致）。
- **无权限的模块/卡片/按钮直接不显示**（前端过滤）+ **接口直接 403**（后端拦截），双保险。

### 3.4 敏感数据（2026-10-24 拍板：单独授权，不吃并集）
**背景**：《开发规范.md》安全性第 1 条要求"敏感数据（身份证/手机号/工资/密码）脱敏展示、按权限可见"，但原表述未定义"什么算敏感、谁可见"。本节定死。

#### 3.4.1 敏感数据三类（全仓实际会出现的字段）
| 类别 | 字段 | 出现位置 | 建议可见角色（超管配角色时参考） |
|---|---|---|---|
| 自然人隐私 | 身份证号、手机号、银行卡号/发放银行、紧急联系人/住址、健康证/病假记录 | 模块-人员管理 二、档案 + 五、社保（预留列） | HR、财务（报税/社保/发薪）、本人直属主管（仅手机号） |
| 钱相关 | 工资明细/计件工资、社保缴纳/补助金额 | 生产流程规划 15.15.12；模块-人员管理 五、社保 | 财务、本人（只看自己） |
| 账号凭据 | 密码、API Key/生产凭据 | 系统级 | 永不返回前端；凭据只进 `.env` 不进 Git |

#### 3.4.2 机制：一个权限点 + 后端统一脱敏（不搞字段级配置表）
- 系统内置**一个**权限点：**`查看敏感人事数据`**（sys_permission 表一条记录，类型=按钮/接口）。
- **勾了** = 能看身份证/手机号/银行卡/工资金额**明文**。
- **没勾** = 这些字段**后端统一脱敏**（返回 `***`），前端不显示明文。
- **默认只有超管勾它**；其他角色由超管后期在管理端按需勾选（符合"不预置业务角色"原则——系统只给这个**权限点**，勾不勾由超管定）。
- **并集规则对敏感字段不生效**：一个人多角色时，敏感字段**只看有没有角色勾了 `查看敏感人事数据`**（勾了就看明文），不因"并集了某个带敏感权限的角色"就顺带能看。
- 超管天然能看全部（超管不受本机制限制，同 一、权限计算公式的"超管例外"）。

#### 3.4.3 特例不走敏感字段，走数据范围/模块权限
- **商业敏感**（采购单价、供应商结算方式）→ **不走敏感字段机制**；车间/生产角色**压根不给"采购"模块的权限码**（模块级拦截），比字段级控制更简单直接。
- **审批人看金额**（报销/付款审批）→ **不走敏感字段机制**；审批链天然需要看金额，走审批节点的数据范围（审批人看得到他审的那单）。
- 一句话：**敏感字段机制只管"自然人隐私 + 工资金额"这两类**，其他敏感场景一律用"模块权限/数据范围"解决，不滥用敏感字段。

## 四、认证与登录（对接技术栈）

- **认证**：Spring Security + JWT/会话（技术栈见《开发规范.md》零、）；登录名 = 工号（当前态），session 存**员工ID**（不存工号，调组改工号不影响登录态，与《地基/员工ID与工号》第四节一致）。
- **超管账号（2026-10-24 拍板：系统内置）**：首启自动创建一个"超级管理员"账号（不受组织树/岗位/角色限制，全厂全模块可看可操作）；密码走初始化流程（首登强制改）；超管的主要职责 = **配角色、配权限、管组织树/岗位**。**除超管外，系统不预置任何其他账号/角色**。
- **密码**：加盐哈希存库（BCrypt/scrypt），不存明文；密码修改/重置走统一入口，重置走邮箱/站内信（预留）。
- **多端**：PC 后台、uni-app 小程序/安卓/鸿蒙，同一套 JWT 体系；不同端可配不同权限码视图（PC 管理全量、移动端只开报工/看板等轻操作）。

## 五、权限红线（同《开发规范.md》十一、功能开发节奏铁律"红线"，此处再钉一次）

1. **不给智能体开万能/超管代执行口子**（与《内嵌智能体规范.md》第四节一致）：智能体每次操作以发起员工本人身份执行、校验、留痕，可执行动作 = 该员工角色权限过滤后的工具集，无权限动作不可见/不可执行。
2. **权限/数据范围走配置表，不写死代码**（同《开发规范.md》"能开关/权限/自填属性表达的，一律不写死"）：加角色/改角色/换数据范围 = 改配置表，不改代码。
3. **敏感操作留痕**：改权限、改角色、改组织节点、切公司、删数据全程留痕（谁/何时/改了什么），软删不物理删（同《开发规范.md》安全性第 5 条）。
4. **数据源/预警条件走结构化白名单**（同《开发规范.md》十一、红线）：不存自由 SQL 文本；权限过滤在统一数据权限层做，不散落各模块拼 SQL。

## 六、公司切换权限（对接《前端规范.md》A.2）

- 公司切换作为操作项挂进本地基的权限模型（角色权限码 sys_company_switch），哪个角色/哪个人能切，按角色权限配；默认给超管，管理员可加给"厂长"等任意角色（验厂场景）。**不硬编码"只超管"，不写死名单**（与《前端规范.md》A.2 一致）。
- 谁切了公司留痕（同 五、第 3 条）。

## 七、与地基/其他模块的接口

| 对接方 | 接口 |
|---|---|
| 地基/员工ID与工号 | 登录名=工号（当前态）、session=员工ID；调组改工号不影响登录；历史数据靠员工ID可查 |
| 地基/审批与预警 | 入离职/调组走审批（《模块-人员管理.md》三、）；权限变更留痕走统一预警/日志 |
| 地基/属性标签 | 角色/岗位/组织节点可挂属性标签（如 岗位.临时工、角色.只读），自由文本+常用词提示 |
| 各业务模块 | 报工/质检/返修/财务/采购/订单等操作的权限校验、数据范围过滤，全部走本地基；模块不自建角色 |
| 内嵌智能体规范 | 智能体工具集 = 该员工角色权限过滤后的 MCP 工具集（第四节）；读操作按数据范围过滤 |
| 前端规范 | 角色过滤（权限码）；公司切换权限挂本地基（A.2） |
| API文档规范 | 每个接口"权限要求"字段引用本地基的角色/权限码口径 |

## 八、已拍板 / 后期配置时定

### 8.1 已拍板（2026-10-24 定稿核心）
1. **超管账号**：**系统内置**一个"超级管理员"账号（不受组织树/岗位/角色限制，全厂全模块）；首启自动创建，密码走初始化流程首登强制改；超管职责=配角色/配权限/管组织树岗位。**除超管外不预置任何账号/角色。**
2. **不预置业务角色**：系统只提供权限体系（表 + 管理端界面 + 校验机制），**角色数据全空**，由超管在管理端运行时添加；三、3.2 映射表降级为"参考示例"。
3. **数据范围默认规则**：一线工=本组/本线、组长=本组、车间主任=本车间、经理=本部门、厂长/超管=全厂；QC 与财务=全厂对应域。**默认按此，无例外**；超管后期可在角色里覆盖。
4. **敏感数据机制**（详见 3.4）：内置**一个**权限点 `查看敏感人事数据`；勾了=看明文，没勾=后端统一脱敏 `***`；**并集规则对敏感字段不生效**（只看有没有角色勾该权限点）；超管天然全看。商业敏感（采购价/供应商）/审批人看金额**不走敏感字段**，走模块权限/数据范围。

### 8.2 后期配置时定（不阻塞地基定稿，超管配权限时按需决定）
1. **公司切换默认给谁**：默认超管；是否同时默认给“厂长/行政总监”等角色（验厂场景常见），超管后期在角色里加。
2. **端权限差异**：PC 后台 vs uni-app 移动端，是否有“移动端只开报工/看板/审批，不开管理配置”这类硬差异（还是全角色按同一套权限码，移动端只是视图窄），超管后期配角色时定。

岗位映射与岗位粒度问题统一维护在《岗位与角色清单.md》，避免在权限地基重复维护。数据范围默认规则已在 8.1 第 3 条拍板，不再列为待确认项。

# 审批与预警（地基，全系统横切）

> 版本：v1（定稿）
> 更新日期：2026-10-23
> 说明：全系统"审批 + 预警/提醒 + 强控开关"的横切地基。各模块**不自建**审批/预警/通知，一律走本地基。原料来自 `地基/审批与预警汇总清单.md`（11 审批对象 + 16 预警项 + 11 开关），技术栈已在《开发规范》零、定稿（Warm-Flow + XXL-Job + RuoYi 通知底座），本文件把"原料 + 选型"成套定成实现方案。与《开发规范》"不重复造轮子""能开关的不写死"一致。

---

## 一、三套横切能力，边界定死（别混塞）

| 能力 | 引擎/载体 | 管什么 | 不管什么 |
|---|---|---|---|
| 审批（人对人流程） | **Warm-Flow**（仿钉钉节点自定义） | 单据发起、节点流转、会签/或签、转交/加签/撤回/代理、审批结果回调 | 业务数据预警、定时提醒 |
| 预警/催办（数据条件触发） | **ERP 统一预警规则表 + XXL-Job 定时任务** | 证件到期、交期风险、宿舍待退房、食堂漏报、审批催办… | 审批流转本身 |
| 强控开关 | **统一开关表（sys_switch）** | 强卡/校验/收费/计入工资 等"是/否"控点 | 审批/预警逻辑 |

- 三类**各走各的表与机制**，但在"通知"上汇合：都调同一个统一通知通道（见 五、），不各写各的。
- 审批"超时自动动作"（卡住自动通过/退回）归 Warm-Flow 原生；"超时催办提醒"归预警（XXL-Job 扫 `warm_flow_task`），Warm-Flow 只兜底动作、不管提醒。

## 二、审批引擎（Warm-Flow 原生集成）

### 2.1 形态
一条审批链 = 一串节点（每节点：审批人/角色/上级/部门、条件、并行会签或或签）。**节点增删/调序/改审批人 = 配置，不改代码**。按"对象类型 + 金额/条件"走不同审批链（条件分支路由）。

### 2.2 各模块怎么接（注册回调，不硬编码）
1. 各模块把"可审批对象"（见 三、11 条）注册进 Warm-Flow 的**流程定义**：`业务对象类型 → 流程定义 + 发起人 + 触发字段`。
2. 业务只调统一门面：`发起 / 通过 / 驳回 / 转交 / 撤回 / 代理`，**不直接碰 Warm-Flow API**（收一层 Facade，防各模块乱接）。
3. 审批结果**回调**回业务模块：走"回调注册表"（对象类型 → 回调 handler），Warm-Flow 完成事件 → 查注册表 → 调对应模块 handler。handler 做业务落地（改单据状态、联动库存/工资/财务）。
4. 审批流定义、节点配置、待办实例全存 **Warm-Flow 自己的表**（`warm_flow_*`），ERP 业务表**只存"当前审批实例 id + 审批状态"**，不镜像审批流结构。

### 2.3 钉钉能力覆盖清单（验收标准）
指定审批人（人/角色/上级/部门）✓、会签/或签 ✓、条件分支（金额>X 走某链）✓、转交 ✓、加签 ✓、撤回 ✓、代理代审 ✓。以上缺一即视为接法不达标。

## 三、审批对象清单（逐条定：默认审批级别/开关）

> 原则：统一引擎 + 节点可自定义 + **无小额免审**（报销类明确全审）。下表"开关/条件"列即强控点，全落 `sys_switch`，不写死。

| 模块 | 审批对象 | 默认（可配） | 开关/条件 |
|---|---|---|---|
| 人员管理 | 离职签核 | 审 | 保留审批 |
| 人员管理 | 调组/调车间 | **一期不审** | 开关"调组是否挂审批"=关（后期开） |
| 宿舍 | 钥匙补领（收费） | 审 | 行政/宿管发起，账到财务 |
| 宿舍 | 物品损坏赔偿 | 审 | 定责到人，账到财务 |
| 食堂 | 包间预留 | **一期登记不审** | 开关"包间预留是否审批"=关 |
| 物业资产 | 报修工单 | 小修免审/大修审 | 开关"报修送审阈值"（按金额） |
| 物业资产 | 资产盘点差异 | 审 | 差异超阈值才送审（阈值可配） |
| 物业资产 | 资产报废 | 审 + 财务 | 机修发起，审批节点自定义，残值走财务 |
| 财务采购 | 采购申请单（4类：生产物料/设备资产/行政耗材/个人报销） | 下单前全审 | 节点按"类型+金额段"可配 |
| 财务采购 | 报销单 | **无免审，全审** | 节点按"类型+金额段"可配；买东西挂申请单，加油直报 |
| 车辆 | 花钱的单（加油/保养/违法） | 走财务报销审 | 车辆出单据→财务引用单据走报销流程 |

**已拍板的待定点（本轮定）**：
- 物业"资产报废/盘点差异"审批级别：走财务审批链（残值、账到财务），节点自定义，不预设几级。
- 车辆"领用"：**只登记、不审批**；花钱的才走财务报销审批。
- 食堂"包间预留"：一期登记不审批（开关默认关，要开改开关即可，不改代码）。

## 四、统一预警规则表（一张表，加预警=插记录不改代码）

### 4.1 表结构（字段定死，落 PG）
`alert_rule`（预警规则表）一行 = 一条预警：
| 字段 | 含义 |
|---|---|
| `module` | 所属模块（前缀口径同属性标签） |
| `alert_code` | 预警编码（唯一，词库口径） |
| `condition_table` | 被查表名（白名单，从已注册业务表里选，不自由填） |
| `condition_field` | 被查字段（白名单，限定该表允许的列，不自由填） |
| `condition_op` | 操作符（`<` `<=` `>` `>=` `=` `!=` `BETWEEN` `IS_NULL`，枚举） |
| `condition_value` | 阈值/参数值（参数化绑定，不拼 SQL） |
| `condition_extra` | 附加条件 JSON（如 `{"field":"status","op":"=","value":"active"}`，字段同样走白名单） |
| `threshold` / `threshold_unit` | 阈值 + 单位（天/金额/次数…），**系统给默认值，支持设置项改** |
| `frequency` | 触发频率（每天/每小时/仅首次/间隔N天） |
| `notify_targets` | 通知对象（岗位/角色/指定人，可多选） |
| `channels` | 渠道（站内/邮件/短信，多选，见 五、） |
| `confirmable` / `silent` / `escalate` | 可确认 / 可静默 / 可升级（升级=再超阈值找上级） |
| `enabled` | 开关（对应 sys_switch，不写死） |

> 加一条预警 = 往这张表**插一行**（配置界面或初始化脚本），不改代码。这是"不重复造轮子 + 不写死"的落点。

### 4.2 预警项清单（逐条落规则表，默认阈值可改）

| 模块 | 预警项 | 默认阈值（可改） | 提醒对象 |
|---|---|---|---|
| 人员管理 | 证件到期（健康证/电工证） | 到期前 30 天 | 人事/对应主管 |
| 人员管理 | 社保核对超期 | 核对日 90 天未复核 | 人事/财务 |
| 宿舍 | 选"住宿"待分配床位 | 当天触发 | 宿管/行政（可指定岗位/人） |
| 宿舍 | 离职待退房 | 当天触发 | 宿管/行政 |
| 宿舍 | 钥匙丢失待补领 | 当天触发 | 宿管/行政 |
| 宿舍 | 物品损坏待处理 | 退房触发 | 宿管/定责人 |
| 食堂 | 未报备/漏报统计 | 每天 15:00 | 未报备人+食堂 |
| 食堂 | 消杀超期（开关开时） | 按消杀周期 | 食堂/行政 |
| 车辆 | 审车到期 | 年检前 N 天（N 可配） | 司机/行政 |
| 车辆 | 维保到期 | 按维保周期 | 司机/行政 |
| 物业资产 | 消防设施检查/维保到期 | 维保前 N 天 | 行政/物业 |
| 物业资产 | 资产维保到期 | 维保前 N 天 | 资产管理员 |
| 物业资产 | 水电表异常 | 用量超阈值 | 物业/行政 |
| 生产 | 交期风险（预测>交期） | 缺口 >0 天 | 跟单员+业务主管 |
| 生产 | 节点完成日期偏差 | 偏差 >X 天 | 计划员/车间主任/跟单 |
| 生产 | 组内前序延误传递 | 组可用日期后移 | 跟单员 |
| 审批 | **审批催办**（待办超时） | 到 N 小时催一次（次数可配） | 当前节点审批人 |

### 4.2.1 数据条件（结构化配置，安全优先，不存自由 SQL 文本）
预警条件**一律用"表+字段+操作符+值"结构化配置**，不存自由 SQL 表达式文本（防注入、可审计、好做白名单）：
1. **表/字段白名单**：`alert_rule` 引用的是"已注册业务表 + 允许列"（一张 `alert_field_whitelist` 白名单表，建表时登记哪些表哪些列可被预警查），条件只能从白名单里选，自由填的表名/列名一律拒绝。
2. **查询由程序拼、值参数化**：触发器按 `表+字段+操作符+值` 生成查询，值全走预编译参数绑定，**绝不把配置值拼进 SQL 字符串**。
3. **复杂条件走 `condition_extra` JSON**：同样限白名单列 + 固定操作符枚举，不支持"任意 SQL 片段"。
4. 需要真正复杂逻辑的预警（如生产"交期风险=预测完成日>交期日"这种跨表计算），**不进通用规则表**，单独写一个"预警任务"（注册到 XXL-Job 的具名任务，内部可写代码级逻辑），输出仍走同一 `sendMessage` + `alert_hit` 去重。即：**简单阈值类走规则表（配置化），复杂计算类走具名任务（代码化）**，两条路、不混。

### 4.3 触发机制（XXL-Job）
1. **业务预警（阈值类）**：XXL-Job 定时（默认每小时，可调）遍历 `alert_rule` 中 `enabled=1` 的行 → 按 `condition_*`（表+字段+操作符+值，全参数化）查业务库 → 命中的调统一 `sendMessage`。幂等：同一单据同一预警项去重（`alert_hit` 表记命中，防刷屏）。
2. **审批催办**：单独任务扫 `warm_flow_task` 待办（`create_time` 超 `alert_rule` 里"审批催办"阈值）→ 调 `sendMessage` 催当前审批人。
3. 食堂漏报（每天 15:00）这类**定点触发**用 XXL-Job 的 cron 定点任务，不进"每小时遍历"。

## 五、统一通知通道（集中封装一处，不各模块各写）

- 统一门面 `sendMessage(channels, targets, content, ref)`：内部按 `channels` 分发，**全系统只有这一处**。
- 渠道（参考 RuoYi-Vue-Plus `WorkflowGlobalListener` / `IFlwCommonService` 复用，不重造）：
  - **站内信（SSE 实时推送，ERP 消息中心）— 一期默认必开**
  - **邮件（SMTP）— 一期可选开**
  - **企业微信 / 钉钉 — 二期按需接**（厂内已有钉钉考勤，后期复用钉钉机器人通道）
  - **短信 — 二期按需接服务商，一期留 TODO**
- 智能体侧可"主动推给相关员工对话界面"（复用同一 `sendMessage`，渠道=站内）。
- **渠道选型（本轮定）**：一期 = 站内信（默认）+ 邮件（可选）；企微/钉钉/短信 = 二期。渠道开关落 `sys_switch`。

## 六、强控开关表（sys_switch，"能开关的不写死"落点）

全系统 11 个强控点统一进一张 `sys_switch` 表（`key + 默认值 + 说明 + 所属模块`），代码里**只读开关表、不写死**：

| 位置 | 开关 | 默认 |
|---|---|---|
| 生产 后整 | 工序继承 强卡/仅提示 | 强卡 |
| 生产 外协 | 收货差异 强校验/弱校验 | 强校验 |
| 生产 返修 | 返修是否计入工资 | 关 |
| 生产 样衣 | 大货裁剪锁在样衣确认之后 | 锁 |
| 人员 | 调组是否挂审批 | 不挂 |
| 宿舍 | 收费（默认免费） | 关 |
| 食堂 | 用工性质（自营/外包） | 待定（开账号发工资看它） |
| 食堂 | 漏报是否罚 | 关 |
| 食堂 | 清洁/消杀强管控 | 关（可登记不强制） |
| 车辆 | 花钱单据是否逐笔报销 | 是 |
| 物业 | 报修小修免审/大修送审 | 开关 |

- 加新开关 = 往 `sys_switch` 插一行（改默认值=改数据），不改代码。
- 每个开关在代码里的读取走统一 `SwitchService.get(key)`，禁止 `if (true)` 这种写死。

## 七、落地节奏（对应开发规范 技术栈）
1. **先落 `sys_switch` + `alert_rule` + `alert_hit` + `alert_field_whitelist` 四张地基表**（DDL 单独提交），默认值按本文 三/四/六 表初始化；白名单表先登记各模块"可被预警查的表+列"。
2. **接 Warm-Flow Facade + 回调注册表**：11 个审批对象逐个注册（先接 1 个跑通"发起→流转→回调落地"，再铺其余）。
3. **统一 `sendMessage` + 站内信 SSE**（复用 RuoYi 通知底座）：先站内信，邮件可选开。
4. **XXL-Job 两个任务**：业务预警遍历 + 审批催办；食堂 15:00 漏报定点任务。
5. **企微/钉钉/短信渠道 = 二期**，一期在 `alert_rule.channels` 里预留但默认不启用。

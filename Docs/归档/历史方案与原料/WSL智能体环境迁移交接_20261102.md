## 一、迁移目标

- Codex 智能体运行环境：WSL Ubuntu。
- 项目唯一工作区：`/home/it/ZhiYun`，位于 WSL Linux 文件系统。
- Windows `D:\ZhiYun`：迁移期旧工作副本。确认未提交内容处理完毕后，不再用于日常开发。
- 不再采用 Windows 编辑后复制到 WSL 的工作方式；WSL 工作区直接承担编辑、构建和运行。

**只把 Codex 的智能体运行环境选为 WSL，不等于项目工作区自动搬到了 Linux 文件系统。** 打开项目后必须检查真实仓库根路径；`/mnt/d/ZhiYun` 仍是 Windows 盘挂载路径，不是本次目标工作区。

## 二、切换前的阻断检查

截至本次盘点，两份工作副本的分支和提交位置相同，但都存在未提交改动：

- Windows：`D:\ZhiYun`
- WSL：`/home/it/ZhiYun`
- 两边分支：`main`
- 两边 HEAD：`441008a6301c8c23041397a21a24f14e42211960`
- 两边均有文档、前端、SQL 等已修改文件和未跟踪文件；完整文件列表尚未逐项核对，且 `AGENTS.md`、`README.md` 内容已确认存在差异。

因此切换前后都必须保留现有改动：

1. 在两边分别记录 `git status --short`，确认未提交改动归属；不运行 `git reset`、`git clean`，不强制覆盖文件。
2. 对需要继续的改动，以文件和 Git diff 为依据合并到 `/home/it/ZhiYun`；不要假定两份目录是实时同步的。
3. `Zone.Identifier` 等未跟踪文件先识别来源和用途，再决定是否清理；不得批量删除。
4. 变更归属未厘清前，暂停新功能修改，避免两份副本继续产生分叉。

## 三、Codex 切换与工作区确认

1. 在 Codex 设置中将“智能体环境”切换为“适用于 Linux 的 Windows 子系统”，即在 WSL 中运行智能体。
2. 在 Codex 中打开 WSL 项目目录 `/home/it/ZhiYun`。不要仅凭设置选项推断当前项目已切到 WSL 文件系统。
3. 在新工作区执行以下只读检查，确认环境和仓库根：

   ```bash
   uname -s
   pwd
   realpath "$(git rev-parse --show-toplevel)"
   git branch --show-current
   git status --short
   ```

   仓库根预期为 `/home/it/ZhiYun`。若显示 `/mnt/d/ZhiYun` 或 Windows 路径，先切换工作区再编辑。

4. 检查工具链和服务状态：

   ```bash
   java -version
   ./RuoYi-Vue-Plus/mvnw -version
   node --version
   pnpm --version
   bash scripts/status.sh
   ```

5. 不要把 Windows 用户目录下整个 Codex 配置、会话缓存或凭据目录复制到 WSL。只有确认某个项目级指令、技能或工具确实缺失后，才单独迁移并核对 Linux 路径。

## 四、开发运行约定

- 开工先读根目录 `AGENTS.md`；按任务只读对应规范、模块文档和相关代码，不扫描整个项目、依赖目录或构建缓存。
- 源码、SQL、文档只在 `/home/it/ZhiYun` 修改；不再从 `D:\ZhiYun` 覆盖同步。
- WSL 的 `.env`、PostgreSQL 数据、MinIO 文件、日志和构建缓存留在 WSL，绝不复制到 Windows 或提交 Git。
- 前端 Vite HMR 通常无需重启。后端目前是打包 JAR 运行、没有 Spring DevTools；只有后端改动时才构建，并在必要时只重启后端。
- `bash scripts/stop.sh` 会停止前后端，不用于只重启一个服务。用户不要求时不主动打开浏览器验收。
- 当前工作区有大量未提交改动；先核对文件归属，不自动提交、推送、切分支或整理无关改动。

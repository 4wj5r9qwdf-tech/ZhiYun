# API 文档规范（面向智能体接入）

> 版本：v1.1
> 更新日期：2026-11-21
> 说明：本文档规定 REST API、MCP 工具和智能体 Skill 的共同字段语义、示例和运行状态记录规则。REST 已实现不代表 MCP 已注册；MCP 已注册不代表运行时已发现或完成真实调用。与《开发规范.md》《功能命名清单.md》《生产流程规划.md》配套使用。

---

## 一、定位与原则

1. **服务对象是智能体**：API 文档要让"一个不读懂页面、只能看 JSON 契约的模型"能独立理解业务动作。人读是次要的；若 MCP 运行时尚未接入，必须明确标记不可调用。
2. **与现有 Web 页面路由分开**：面向智能体的 API 是"动词式能力接口"（查询库存、开裁剪单、报工），字段为"机器调用"设计（参数清晰、返回结构化、幂等可控），**不复用** Jinja2 页面渲染时那些"给人看"的端点。
3. **按《功能命名清单》的模块分组**：一个功能一组 API，组名=功能中文名+英文名（如"裁剪构成单 cut_order"）。
4. **文档与代码同源**：文档以实际路由和接口实测为依据。路由自动抽取脚本尚未落地前，在功能验收时人工核对代码与实测结果，避免纯凭记忆维护。
5. **REST、MCP 与 Skill 使用同一字段语义**：功能 API 分组文档是字段类型、空值、默认值、校验和副作用的权威说明；MCP 描述与 `inputSchema` 表达可调用结构，Skill 只编排步骤并引用该字段契约，不得自行改变其语义。发现不一致时先修正代码或确认后的业务契约，再同步三处。

## 二、每个 API 必须写的字段（固定模板）

每个接口按下面结构记录，缺字段的接口视为**未达标，智能体不可用**：

### 基本契约
| 字段 | 说明 |
|---|---|
| 功能分组 | 属于哪个功能（对应《功能命名清单》） |
| 方法 + 路径 | 如 `POST /api/v1/cut_order/create` |
| 一句话说明 | 这个接口做什么（中文） |
| 读/写类型 | **只读**（query）或 **写**（mutation）——必填，智能体据此判断副作用 |

### 请求参数
| 字段 | 说明 |
|---|---|
| 字段路径 | 使用 JSON 路径标明顶层、嵌套对象及数组元素，例如 `filter.status`、`rules[].usage` |
| 类型与格式 | JSON 类型、ID 表示、日期/时间格式、精度和单位；枚举列出全部允许值 |
| 必填与默认 | 说明必填/可选、服务端默认值以及新增、补丁、全量替换等提交模式 |
| 空值语义 | 逐字段说明省略、`null`、空白字符串、空数组和空对象分别是接受、拒绝、使用默认、清除还是无筛选；不适用的值明确标为不可传 |
| 校验约束 | 长度、数值范围、小数位数、集合数量、唯一性、引用来源以及跨字段约束 |
| 使用说明 | 字段业务用途、读取来源、与其他字段的互斥/依赖关系和服务端副作用 |
| 示例值 | 每个字段给出一个符合类型和约束的合成示例值；敏感信息不得使用真实样本 |
| 嵌套结构 | 含对象/数组的参数必须递归列出内部字段；仅写“JSON 对象”或“同新增”而未链接可定位的字段表视为不完整 |
| 示例请求 | 提供语法有效的 JSON。按不同提交语义补充最小新增、完整修改/补丁、空集合清除及发布等适用示例；示例需覆盖所有字段，说明示例 ID 如何从前序查询替换 |

每个请求字段至少使用以下字段矩阵列；一个字段不能合并进“其他参数”。不适用的输入形态也写“拒绝/不适用”，不得留白：

| 字段路径 | JSON 类型/格式/示例值 | 必填条件与省略结果 | `null` / 空白 / 空集合结果 | 用途、来源、默认、校验与副作用 |
|---|---|---|---|---|
| 示例：`filter.status` | string；示例：`"active"` | 可选；省略表示不按状态筛选 | `null` 拒绝；空白拒绝；数组/对象不适用 | 格式示意；真实规则必须按对应实现填写 |

响应字段使用对应矩阵，至少列出字段路径、JSON 类型/格式/示例、是否可能为 `null`、空数组/空对象的含义、业务用途/单位/枚举和读取来源。通用包装字段可引用统一响应定义；业务对象、嵌套对象及数组元素必须逐字段列出。

#### 省略、`null`、空白和空集合的统一规则

每个请求字段都必须归入下表中的明确语义。不要把“可选”当作空值规则，也不要根据 Java 类型、SQL 可空性或界面控件推测 API 行为。

| 输入形态 | 文档要求 |
|---|---|
| 省略 | 写明字段是否可省略、省略后采用哪个默认/补丁行为；必填字段省略后的业务错误也要说明 |
| `null` | 默认视为非法输入；若该字段允许 `null`，必须逐字段写明其结果，不能仅因 Java 字段可空就推定可传 |
| 空白字符串 `""` / 纯空格 | 默认非法或不接受；若与省略等价、代表清空或有其他含义，须明确列出。`trim` 后处理也必须说明 |
| 空数组 `[]` | 明确是合法空集合、清除全部关联、没有筛选值还是拒绝；全量替换操作必须特别给出清空示例及影响 |
| 空对象 `{}` | 明确是否为有效请求；补丁更新可声明“无变更”，完整更新/新增通常应列出缺字段错误或明确语义 |

通用默认是：可选字段用**省略**表达未提供；除非字段文档明示，否则不要传 `null`、空白字符串、空数组或空对象。具体字段如覆盖通用默认，API 参数表必须逐字段说明；MCP 工具描述/参数注释及 Skill 不得与其冲突。

### 返回
| 字段 | 说明 |
|---|---|
| 成功返回示例 | 完整 JSON，含所有字段（哪怕值为 null 也要列出） |
| 错误返回 | 每种可预期错误的错误码 + 触发条件 + 示例 |
| 返回字段说明 | 递归列出返回对象的字段路径、类型、是否可能为 `null`、空值/空集合代表的含义、格式/单位、使用方式和合成示例；通用分页/响应包装可引用统一结构，但不得省略业务对象字段 |

### MCP 工具契约

| 项目 | 要求 |
|---|---|
| 工具说明 | 用一句话说清业务对象和动作；写工具说明调用前读取什么、向员工展示什么、影响范围及确认要求，并列出权限和重要副作用 |
| 参数 schema | `inputSchema` 中每个顶层参数的 required/type 必须与实现一致。参数注释说明业务用途和格式；可选参数说明省略行为。所有字段的空值细节由同名 API 字段表完整定义。对象/数组内部所有可调用字段也按字段矩阵递归登记，写清是否允许 `null` |
| 对象/数组入参 | 优先使用有类型的 DTO/record 生成嵌套 schema。若现有工具使用 `Map<String,Object>`，描述必须列明可接受键，并在 API 字段表展开每个嵌套字段；不得把不校验的自由对象说成 schema 已约束 |
| 工具示例 | API 分组文档或对应 Skill 提供与 `tools/list` 名称及参数结构一致的 `arguments` 示例。示例字段、大小写、数组与包装层须可映射到真实 `inputSchema` |
| 权限与范围 | 标明 MCP 权限码、当前员工身份、人员/分类等数据范围；权限过滤后的未发现工具不能据此判定后端未实现 |

### Skill 编写契约

1. Skill 顶部写清名称、触发场景、明确不处理的相邻范围，以及所依赖的 API 分组文档和 MCP 工具。
2. 每种业务动作按“先读并定位 → 校验数据范围与前置条件 → 展示目标/字段/影响 → 本次确认 → 调用 → 复核结果”描述；不允许 Skill 跳过 API 契约中的校验或步骤。
3. 给出可复制的 MCP `arguments` 示例：有写工具时覆盖至少一个查询和一个写动作；只读或尚无写工具的功能提供查询示例并明确标注写能力缺口。如新增、补丁、全量替换、清空、审批发布语义不同，分别提供示例或链接到 API 分组文档中对应的完整 JSON 示例。示例需能映射至 API 字段矩阵中的每个输入字段；有条件必填/可空字段在示例旁说明替换条件。所有字段说明和空值行为以 API 分组文档为准并链接，不在 Skill 内创设第二套规则。
4. 覆盖典型失败处理、查询为空的权限含义、部分成功/超时后的复核方式，以及不可自动重试或禁止绕过的边界。

### 机器契约（智能体专用，强制）
| 字段 | 说明 |
|---|---|
| 幂等性 | 该接口**重复调用**是否产生副作用。写操作必须声明：支持幂等键（哪个字段）/ 不支持（重试会重复扣库存等风险） |
| 副作用 | 调用后会改变哪些数据/触发哪些联动（如"生成打码单""扣减布卷库存"） |
| 前置条件 | 调用前必须满足什么（如"该实裁单已确认""物料已入库"） |
| 是否需审批 | 该动作是否挂在审批流上（对应审批引擎回调） |
| 权限要求 | 该动作需要哪个角色/权限码才能执行（对应 sys_role 权限模型）；智能体按发起员工权限过滤，无权限则不可见/不可执行 |

## 三、文档组织（文件结构，随技术栈落地）

> **目录约定（2026-10-26 定，2026-11-04 更新）：API 文档进 `Docs/API/`；功能验收后在 `Docs/Skills/<功能名>/SKILL.md` 提供智能体 Skill。**

1. **总索引**：`Docs/API/API文档.md`（总纲）——所有功能分组清单 + 每个接口一行速查（方法/路径/说明/读写），供智能体先定位再细看。
2. **分组文档**：每个功能一份，放 `Docs/API/` 下，文件名 = 功能中文名 + `API`，如 `Docs/API/建筑档案API.md`。组内按"只读接口在前、写接口在后"排列。
3. **示例请求体统一放可运行代码块**（语言标注），智能体可直接复制执行验证。

## 四、与智能体接入方式的关系（SDK / API / Skill / MCP）

| 手段 | 在 ERP 场景的作用 | 是否建设 |
|---|---|---|
| **MCP** | 智能体发现/调用 ERP 能力的协议入口，把能力暴露为工具；智能体不直接碰后端 Web 路由 | 每个已验收功能都记录工具映射与接入状态；运行时实现可分批接入 |
| **面向动作的 API** | 能力原子（查询/开单/报工），字段为机器调用设计，与 Web 页面 API 分开 | 每个已验收功能记录现有 REST 路由及 agent API 状态；不足时标明待建设 |
| **Skill** | 一个完整业务动作的多步编排，按确定步骤调用能力 | 每个已验收功能都交付 Skill；依赖工具未接入时标注草案/不可执行 |
| **SDK** | 调大模型那段（OpenAI 兼容 `/v1/chat/completions`）的封装，不碰 ERP 业务 | **基本不需要**，除非绑定某家 Agent 框架 |

**目标架构：智能体接管 ERP 时，可由 MCP（发现/调用）+ 面向动作的 API（能力原子）+ Skill（业务动作编排）协作；这描述目标形态，不表示所有 ERP 功能当前都必须建设这套能力。** SDK 不作为默认建设项，除非选定框架确有需要。具体批次按用户确认范围实施。

## 五、落地节奏

1. 新增或修改任何 REST/API、MCP 参数或 Skill 时，本规范立即生效；没有字段语义表、示例或状态标注的契约不得宣称已交付给智能体使用。
2. 迁移既有契约按风险分批，不虚构当前文档已符合：第一批检查写操作、审批、删除、全量替换、权限/数据范围和嵌套 `Map`；第二批检查其他新增/修改及查询筛选字段；第三批统一其余只读字段、返回对象字段和 Skill 示例。
3. 每批以 API 分组文档为源逐项核对服务端校验、MCP 注解和运行时 `inputSchema`，再同步 Skill 的调用顺序与示例；冲突未核清的字段标为待核，不允许模型猜测。
4. 人工在骨架上补“机器契约”四字段（幂等/副作用/前置/审批），并补全字段矩阵；脚本可抽取路由和 schema，但不能自动推断业务空值语义、数据范围或确认步骤。
5. 参数/字段英文名一律以《术语词库索引.md》既定词为准，不自造；释义列可直接取词库释义做底稿。
6. 每次验收检查三者一致：API 字段表、MCP `tools/list` 的 name/description/inputSchema、对应 Skill 的示例与步骤。变更后执行静态契约检查；用户验收后再做已授权的运行时发现、权限和真实调用验证。

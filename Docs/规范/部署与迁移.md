# 部署与迁移

> 版本：v1（目标环境与迁移边界）
> 更新日期：2026-11-24
> 说明：记录织云 ERP 面向 WSL 测试环境和后续 Ubuntu 实体服务器的部署原则。生产级部署步骤、备份参数及恢复演练尚待实际环境确认后补全。

---

## 一、目标环境

- 当前测试：WSL Ubuntu，源码目录 `/home/it/ZhiYun`。
- 后续测试/部署目标：本地 Ubuntu 实体服务器，具体版本、硬件、网络和域名待确认。
- 源码在 WSL `/home/it/ZhiYun` 中开发、构建和测试，并从 WSL 推送 GitHub；Windows `D:\ZhiYun` 是迁移期副本，目前主要保留文档等内容。WSL 不是实体服务器的生产替代，实体 Ubuntu 仍需独立部署和数据迁移。

## 二、仓库可确认的服务组成

- 后端：Java 21、Maven 多模块 Spring Boot 应用；本地开发使用 `RuoYi-Vue-Plus/ruoyi-admin`。
- 前端：Vue 3、TypeScript、Vite；开发服务端口由项目配置/脚本确定。
- 数据库：项目目标数据库为 PostgreSQL，开发配置指向 `zhizhun_erp`。生产 profile 和通用 Compose 模板中存在上游其他数据库的示例配置，属于待清理的配置残留，不代表织云 ERP 使用其他数据库；在清理配置前不得据此部署。
- Redis：开发配置提供本机 Redis 连接入口。
- MinIO：`scripts/start.sh` 会处理 `zhizhun-files` 与 `zhizhun-private` 桶权限；容器与数据持久化依赖部署配置。
- 其他服务（任务、监控、AI 等）是否启用，按实际部署范围确认，不因仓库有 Docker 配置就默认全部上线。

## 三、配置与持久化原则

1. 每台环境独立维护 `.env`，只从 `.env.example` 取得变量名；不得复制或提交其他环境的凭据文件。
2. Spring Boot Admin 及已接入的监控客户端复用 `SUPER_ADMIN_USERNAME`、`SUPER_ADMIN_PASSWORD` 做 HTTP Basic 认证；Compose 启动时必须将这两个环境变量传入相关服务。监控台仍需独立登录，生产启用前应限制监控端口的网络访问。
3. PostgreSQL 数据目录、MinIO 对象数据、Redis 持久化数据和日志需与容器生命周期分离；具体宿主目录和保留周期部署前确定。
4. 公开桶仅存允许公开访问的内容；合同、证件、工资等敏感文件必须留在私有桶并通过鉴权访问。
5. 测试库与正式数据隔离。迁移或恢复前核对目标地址、数据库名、备份时间和操作影响范围。
6. 迁移到 Ubuntu 实体服务器时，优先部署与 WSL 相同的源码提交和 Linux 工具版本；不要把 WSL 数据目录直接复制成服务器数据目录。

## 四、当前尚待补齐

- Ubuntu 版本、硬件资源、域名/HTTPS、网络与防火墙端口表。
- PostgreSQL 目标版本、扩展（含 pgvector）安装方式、初始化及迁移顺序。
- 清理 `application-prod.yml` 与 Compose 模板中的上游数据库示例，生产 profile 改为 PostgreSQL，并与 `.env.example` 的配置变量统一。
- Redis、MinIO、应用服务的正式 Compose/服务管理配置及版本锁定。
- 数据库与对象存储的备份频率、保留策略、加密、恢复步骤及恢复演练。
- 发布、回滚、日志轮转、健康检查和更新窗口流程。

在以上事项确认和演练前，本文件仅作迁移边界说明，不作为生产部署操作手册。

### SnailAI 文件与知识库迁移提示

SnailAI 聊天文件及知识草稿功能依赖源码、后台静态资源和 PostgreSQL 表结构；开发库中已执行的 DDL 不会自动进入其他数据库。部署时需核对并依次执行 `sql/SnailAI聊天文件归属_20261118.sql`、`sql/SnailAI知识草稿_20261118.sql`，确认 PostgreSQL 的 `vector` 扩展已安装并启用。应在目标环境验证文件上传、权限隔离、知识草稿确认、向量化与检索。

Docling 需要单独部署并配置地址及认证。开发容器 `zhiyun-docling-dev` 和本机密钥文件属于开发环境，不能直接作为生产配置。文件工具桥接目前只允许本机回环访问；两个进程必须读取同一份私有签名密钥，跨容器或跨主机需先完成服务身份认证及加密通信改造。不要把 `.env`、密钥、上传文件、数据库数据、运行日志或构建缓存提交到 Git。

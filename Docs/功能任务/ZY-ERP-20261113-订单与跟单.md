# 功能规划：客户订单与跟单

> 版本：v1 业务方案
> 更新日期：2026-11-13
> 状态：首批功能已实现，待页面验收
> 业务基线：《生产流程规划.md》第一节、《开发路线图.md》阶段 2

## 一、目标与业务边界

建立服装代加工厂从客户下单到物料需求计划的业务入口。订单记录客户实际订购的款式、套装配套、颜色尺码数量和 PO；系统引用已验收的款式档案与 BOM 计算计划用料，为后续客供到料、自采申请、收货入库、排产和发货提供统一来源。

- **客户订单**是本厂承接客户需求的内部业务主单，使用系统内部订单号。
- **PO**是客户提供的 Purchase Order 原始采购单，客户 PO 原号与系统内部订单号分别保存，不能互相替代。
- 一张客户订单可包含多个 PO；每个 PO 可包含多个款式明细，每个款式明细可有多组颜色尺码数量。一个 PO 可以分多个交付批次；交付批次单独记录日期、目的地及本次各色码数量分配，不复制或伪造客户 PO 号。
- 套装档案和套装规格定义允许的子款配套；订单 PO 明细选择套装规格及套数，展开保存当次实际子款、颜色、尺码组合快照。单款则直接填写款号、颜色、尺码和数量。
- 本期先实现客户订单、PO、审核、订单物料计划及后续单据入口。到料计划、采购申请、物料收货、库存批次、生产任务、裁剪、发货分别作为后续功能，不把库存入账伪装成订单保存动作。
- 订单设置默认供料，PO 可继承或单独设置；“客供＋自采”表示允许两种入库来源，实际客供或自采在每次收货入库时确定，同一物料可分不同来源入库。

## 二、主单字段

| 字段 | 必填 | 规则与说明 |
|---|---:|---|
| 系统订单号 | 是 | 自动带出可编辑建议；唯一校验；创建后作为内部主单号，不用客户 PO 号代替 |
| 客户 | 是 | 选择启用客户；保存客户名称快照，历史订单不随客户改名而变 |
| 客户联系人 | 否 | 从客户联系人中选择，可补充本单联系人快照与联系方式 |
| 客户订单日期 | 是 | 客户订单/合同确认日期 |
| 业务员 | 是 | 当前账号具有业务员职责时默认带出；仅可选择具有业务员职责的在职人员 |
| 跟单员 | 是 | 负责订单推进；仅可选择具有跟单员职责的在职人员；可与业务员相同 |
| 归属公司 | 是 | 引用公司/品牌档案；开单后锁定，用于单据抬头与财务主体 |
| 客户合同号/订单参考号 | 否 | 客户侧主订单/合同的外部编号；与 PO 编号区分 |
| 币种 | 按报价启用时必填 | 沿用财务统一币种；订单金额按明细价格汇总，不能由前端传总额作为权威值 |
| 预计目的地 | 否 | 订单级默认值，可由 PO 单独覆盖；引用国家/地区并保留名称及地址快照 |
| 备注 | 否 | 订单级说明 |
| 附件 | 否 | 合同、订单文件等多附件，走私有文件鉴权；附件操作留审计 |
| 订单默认供料 | 订单录入 | 显示订单设置的客供、自采或客供＋自采，不依赖算料；PO 可继承或单独设置，列表提示展示各 PO 的实际设置 |
| 订单状态 | 系统维护 | 草稿、待审核、已审核、执行中、部分交付、已完成、已取消等；状态变化受权限与流程控制 |
| 制单人/制单时间/修改人/修改时间 | 系统维护 | 仅展示，不由用户编辑 |

**报价与金额建议**：加工单价属于客户订单明细的商业条款，不属于物料 BOM。若本期启用报价，按订单明细保存币种、计价单位、加工单价、折扣/附加费及金额；订单应收的实际核销仍归财务模块。若暂不启用报价，订单仍须保存币种/金额的扩展接口，但列表不展示空金额列。

## 三、PO 与订单明细

### 3.1 PO 字段

| 字段 | 必填 | 规则与说明 |
|---|---:|---|
| 客户 PO 号 | 是 | 客户原始 PO 编号；建议按“客户 + PO 号”查重，允许不同客户使用相同编号 |
| PO 日期 | 是 | 客户该批 PO 日期 |
| PO 状态 | 系统维护 | 草稿、待审核、已审核、执行中、部分交付、已完成、已取消 |
| 默认要求交期 | 单批时必填 | 本 PO 的默认交期；如拆多个交付批次，以批次交期为准 |
| 默认目的地 | 按客户/订单配置 | 继承订单预计目的地，可覆盖；具体批次可再覆盖并保存目的地快照 |
| PO 备注 | 否 | 本 PO 的特殊包装、唛头、交付说明等 |
| PO 附件 | 否 | PO 文件及本批资料，可多文件上传 |
| 订购总件数/套数 | 系统计算 | 从明细汇总；套装保留套数和展开后的子款件数 |
| 已分配交付/未分配交付数量 | 系统计算 | 对照交付批次分配；订单阶段不可手填 |
| 已交付数量/未交数量 | 系统计算 | 从后续发货单汇总；订单阶段不可手填 |

PO 不是内部生产任务单。订单审核后可按 PO 生成生产任务；生产任务的排产、车间和小组指派在生产计划功能实现。

### 3.2 款式明细字段

- 行号、款式（单款或套装）、客户款号/本厂款号、款式名称、缩略图、款式档案 ID 快照。
- 套装行：套装规格、订购套数、每套子款组成；分别保存子款颜色和尺码，允许上衣 M、裤子 L 等不同配码；锁定当次配套快照。由套装类型决定后续合并生产或分开生产。
- 单款行：颜色、尺码、订购数量；可按尺码组快速铺开后逐格编辑数量。
- 价格字段（启用报价时）：计价单位、加工单价、折扣/附加费、行金额；金额以服务端十进制定点计算。
- 备注、客户行号/客户款号、行附件（仅在客户需要按行提供资料时）。
- 每行的数量必须大于零；颜色/尺码必须属于款式当前有效规格；套装所有必需子款组合必须完整。

### 3.3 PO 与交付批次规则

- 一个系统订单可建多个 PO；PO 之间允许不同默认交期、目的地、款式组合和数量。
- 每个 PO 下配置一个或多个交付批次。批次字段包括内部批次序号、计划交付日期、目的地/收货地址、各款式颜色尺码分配数量、备注、交付状态。只有一个批次时可由 PO 默认交期和目的地带出。
- 所有交付批次分配数量之和不得超过 PO 对应款式色码订购数量；未分配数量显式提示。后续发货单引用交付批次并扣减剩余可交数量。
- 一个 PO 下可有多个款式行；同一款式可拆成多行，但同一 PO 内重复的款式/颜色/尺码组合应提示合并，除非客户行号或价格条款不同且用户明确保留分行。
- 同一客户 PO 因交期、目的地或数量拆分时，仍是同一 PO 下多个交付批次；只有客户确实下发了新的 PO 编号时才新增 PO。
- 订单审核后，修改 PO 数量、交期、目的地、套装配套或 BOM 关联时，必须显示变更影响摘要；已排产、已收料、已领料或已发货部分不能被静默覆盖，走订单变更并保留前后值。

## 四、订单物料计划

订单审核前可预览用料，客户订单可在 BOM 尚未完成时先提交和审核；BOM 就绪后再在已审核订单中算料。只有全部用料完整时才保存正式需求快照；可明确发起重新算料，保存新结果前保留原快照；已有有效需求计划时阻止直接重算，防止覆盖计划调整。订单列表显示未算料、已算料和 BOM 更新等状态并提供算料入口。独立需求计划单的重生成、审批和下游变更处理仍待实现。每行至少记录：来源 PO/订单明细、款式/套装子款、颜色尺码、BOM 版本、物料档案与规格、物料颜色、物料单位、单件用量、订单计划件数、损耗/加放依据、计划需求量、供料方式、客户归属、要求到料日期、已到数量、未到数量。

- 需求量根据订单色码数量 × 对应 BOM 用量计算；套装按当次 PO 配套快照展开后按子款色码汇总。
- 客供＋自采为允许范围，不预设物料均为客供；实际入库来源决定采购订单、应付与财务关联，客供和自采的数量均应保留来源及核算信息。
- 物料档案的多规格物料按 BOM 已选规格分别计算；单位换算使用物料/BOM 中确认的系数，十进制计算并在展示/业务边界按单位精度规则处理。
- BOM 暂无可用版本或用料不完整不阻止订单提交与审核；审核后算料时定位缺失并阻止保存不完整的用料快照。订单本身的套装配套、颜色尺码和数量仍须有效。
- 库存账接入后，才计算可用库存抵扣、按客户归属/供料来源匹配批次、短缺量及建议采购/催料量。库存账尚未完成时，只展示 BOM 计划需求，不得显示虚构“可用库存/缺料”数值。
- 需求超出 BOM 计划时，调整必须填写原因并记录原值、新值、人员、时间；不得直接改写款式 BOM 历史版本。

## 五、状态与防呆

1. 草稿可编辑、删除；提交审核后锁定普通编辑。
2. 审核通过进入执行；修改关键字段用“订单变更”，重走必要审核，并保留审核前后快照。
3. 部分发货后不允许将订单数量改到低于已发数量；部分收货/领料后，物料需求调整需给出已到、已领、差异和后续处理提示。
4. 取消订单需说明原因；存在已收物料/已领物料/已生产/已发货时不允许直接取消，转入业务处理或主管授权的关闭流程。
5. PO 号重复、无效/停用客户、无权限款式分类、无效色码、缺少套装配套、数量为零/负数或交期缺失时，在页面和服务端拦截并给出具体定位；无可用 BOM 仅阻止保存完整用料快照，不阻止订单审核。
6. 分类可见范围沿用人员分类权限；无权时明确显示“无该分类访问权限”，不得表现成“没有款式/物料”。业务参数可给默认分类，但不能越过人员权限。
7. 订单号自动生成仅作为可编辑建议；保存时由服务端并发安全校验，手填仍可用且需查重。
8. 所有新增、修改、删除、提交、审核、取消、变更、附件和数量调整记录详细业务审计，含对象、操作者、动作、结果、变更字段及前后值；敏感信息脱敏。
9. 单据责任人须具备人员档案中对应的业务职责；职责仅控制责任人候选与服务端引用校验，不授予订单操作权限。订单可见、编辑、审核、取消仍由订单权限与订单数据范围决定。

## 六、页面与操作设计

### 6.1 订单列表

订单列表一行一张系统客户订单，不把 PO 行重复摊平造成订单重复计数。进入订单详情后再查看 PO 与款式明细。

**筛选区**：系统订单号、客户、客户 PO 号、客户款号/本厂款号、业务员、跟单员、订单状态、订单默认供料及 PO 供料安排、订单日期范围、计划交付日期范围、目的地。常用项默认展示，其余放展开筛选；每项字段名常显，清空后恢复为空，不擅自锁定单一客户/分类。

**操作栏**：新增、查询、重置；按权限显示导入/导出和列设置。订单数据导入需提供可读模板与预览校验，不要求客户填写数据库 ID。

**建议默认列**（按重要程度）：系统订单号、客户、PO 数/PO 号摘要、款式/款数、订购数量、订单默认供料、业务员、跟单员、订单日期、最近交期、目的地、订单状态、生产进度、交付进度、操作。金额仅在启用报价时展示。创建人/创建时间/修改时间进入列设置，不占据默认业务列。

**行操作**：查看、编辑（仅草稿/权限允许时）、提交审核、复制订单、取消/关闭。启用停用开关不适用于订单，状态按业务流程展示；删除只允许未提交且无任何下游引用的草稿。提交审核、取消、关闭均说明影响并确认。

列表沿用 `SystemTemplate.vue`、`StandardListLayout.vue`：查询、重置位于新增之后；表格撑满剩余高度；列宽自适应且有合理最小宽度；默认列设置/拖拽列序、统一表格边框和行悬停高亮；窄屏可横向滚动，列设置按当前用户保存。

### 6.2 新增/编辑订单

订单是复杂业务单据，使用功能区全屏工作页，不使用拥挤的小弹窗。顶部固定单据操作栏，内容区独立滚动，底部/顶部至少一个固定保存区；离开有未保存提醒。

**页面分区**：

1. **订单基本信息**：订单号、客户、客户联系人、订单日期、业务员、跟单员、归属公司、客户合同号、币种、预计目的地、备注。按字段语义选择控件，不把字段名塞进输入框导致选择后看不出字段含义。
2. **PO 与交付批次**：以 PO 卡片/页签展示客户 PO 号、日期、默认交期、默认目的地和附件；PO 下维护一条或多条交付批次，逐批设定交期、目的地及各色码交付数量。清楚显示 PO 订购、已分配、已交付和未交数量。
3. **款式与配码明细**：先选款式/套装，选择器使用分类树 + 可搜索款式列表 + 勾选确认弹窗；选择完成回到单据，不跳走单独选择页面。单款使用尺码组快速建行，支持逐个颜色尺码填写数量、批量复制/清空、键盘 Enter/Tab 移动；套装使用套装规格配套表分别选择子款色码并填套数，系统实时展示展开后的子款件数。
4. **物料计划预览**：按 PO/款式/子款汇总 BOM 需求，支持展开查看颜色尺码、物料规格、单位、需求量和供料范围；混合供料不在订单试算阶段强制拆分来源数量。
5. **附件与变更摘要**：订单/PO/行级附件分开展示；编辑审核后订单显示本次变更及影响，不覆盖原始审核快照。

**保存操作**：草稿保存、提交审核、取消。草稿保存后留在当前订单页并提示成功，不自动返回列表；提交审核前先完成全单校验并显示问题清单。审核操作由有权限人员在详情页或待办完成，不通过编辑表单伪造审核。

### 6.3 订单详情

详情页只读展示订单头、PO、配码明细、物料计划、审核/变更时间线和附件；每个 PO 可单独查看交期/目的地/款式色码。后续到料计划、采购申请、收货、生产任务和发货通过关联单据入口进入，并显示单据状态与数量汇总。

## 七、验收主场景

| 场景 | 预期 |
|---|---|
| 单款订单按尺码组铺开颜色尺码 | 数量矩阵清楚，汇总件数准确，空数量不产生零值订单行 |
| 一个订单含多个 PO，交期/目的地不同 | PO 独立保存并显示，主单汇总不重复计数 |
| 套装规格中子款使用不同尺码/颜色 | 按订单配套快照展开，子款计划件数与原套数均可回查 |
| 同款不同色码使用 BOM 不同物料规格 | 计划需求按 BOM 版本和规格分别计算，不串规格 |
| 客供与自采混合 | 订单及继承 PO 的需求显示“客供＋自采”；入库时确定实际来源，同一物料可按两种来源分批入库 |
| BOM 缺失/款式权限不足/色码失效 | BOM 缺失允许订单审核但阻止保存完整用料快照；款式权限不足或色码失效阻止订单提交并定位问题 |
| 订单审核后修改数量/交期 | 走变更流程，显示下游影响并留下完整前后值 |
| 已有收料/领料/生产/发货时取消或减量 | 按已发生数量阻断不合理操作并提示可执行处理路径 |
| 列表筛选、列设置、权限与审计 | 模板行为一致，服务端校验权限，业务动作有完整审计 |

## 八、实施拆分建议

1. 订单字段及 PO/配码数据契约、客户订单列表和详情/草稿新增编辑。
2. 审核流程、订单变更与审计。
3. 订单引用款式/BOM、套装规格配套快照、物料计划计算。
4. 订单相关到料计划、轻量采购申请、收货入库和库存批次，打通订单需求到库存的闭环。

首期验收以“订单录入、多个 PO、款式/套装配码、审核、BOM 计划需求可解释”为准；库存抵扣及实际到料数量在库存台账完成后验收，不提前伪造。

## 九、评审时需要确认的业务点

以下为本方案明确标出的业务决策，不阻碍字段/接口/UI 的常规实现准备：

1. PO 与交付批次的边界：本方案建议“一张客户订单可含多个客户 PO；一个 PO 可有多个交付批次”，交付批次分配到 PO 的款式色码数量。请确认是否符合实际客户下单单据。
2. 本期是否启用加工单价/币种/订单金额；若不启用，是否只暂缓展示，但仍预留后续财务引用。
3. 订单审核是否复用统一审批流配置，还是业务主管固定审核；优先建议复用统一审批能力并配置默认审批人。
4. 订单是否允许在无已发布 BOM 时保存草稿；建议允许保存草稿，但禁止审核和生成正式物料计划，并明确标记缺少 BOM。
5. 首期订单导入是否纳入；建议先完成人工订单闭环和导出，导入待模板字段稳定后实施，避免 PO/套装复杂配码导入失败难以修复。

## 十、首批实现记录

2026-11-14 新增订单模块的客户订单入口及开发库迁移 `sql/客户订单_20261114.sql`。草稿支持多 PO、款式与套装规格、交付数量分配。提交冻结配套，BOM 可在订单审核后补充并保存用料快照。录入时以客供为初始建议，订单和 PO 可设为客供、自采或客供＋自采；混合模式的实际来源在收货入库时确定。审核权限独立分配，具备审核权限的人员可查看全部客户订单。普通用户仅可访问本人制单、负责销售或跟单的订单。

首批采用提交、审核通过、退回、取消的单据流转。统一审批、已审核单据的业务变更、附件与商业条款、导入导出、国家地区档案联动和下游单据仍待接入。当前使用已建档套装规格录单，订单内临时改配套仍待实现。

客户订单支持反提交和反审核：待审核订单可由具备制单权限且有订单访问范围的人员反提交为草稿，清除提交时的物料计划快照，再次提交时重新计算；已审核订单可由具备审核权限的人员反审核为待审核，保留物料计划快照。两项操作均检查版本并记录操作审计。当前订单尚未接入入库、生产等下游单据；这些功能上线时，必须在反审核的同一事务内检查有效下游引用，并与下游创建使用一致的订单锁，存在执行记录时禁止反审核并提示处理下游单据。

## 2026-11-14：物料需求计划与生产任务单扩展（待实现）

- 订单录入时支持按已发布 BOM 试算，保留订单、PO、订单规格、子款、BOM 版本、物料、颜色、物料规格、供料方式及库存单位用量来源。物料配置多个采购单位时展示可用的换算参考；固定系数使用物料自己的换算，按实际计量的单位须注明无法自动推算，不能虚构卷数或使用全局系数覆盖物料系数。采购数量、入库实测值允许人工调整，历史单据保留换算快照。
- 客户订单审核通过时，同一事务幂等生成物料需求计划草稿及按 PO 组织的生产任务草稿；关联订单及订单版本，重复回调或重复审核不重复生成。需求计划按供料方式和物料、颜色、规格、库存单位保留明细来源，计划人员可修改计划数量并记录原需求、调整量和原因。不能跨客户、供料方式或物料规格无依据合并。
- 生产任务保留 PO、款式、套装类型及颜色尺码数量：合并生产的套装以套装为执行对象并保留子款配套；分开生产的套装按子款分别形成执行明细，同时保留套装来源与每套数量。计划人员可编辑任务数量及排产安排并留痕，不能反向改写客户订购量。
- 客户订单、需求计划和生产任务通过统一 Warm-Flow 审批门面接入各自可配置审批流，审批实例与业务状态保持一致；提交/撤回/通过/驳回、反审核和重复回调都须做权限、版本、事务与幂等处理。当前订单审核仍是业务状态操作，统一审批中心和上述两类单据尚未接入。
- 订单反审核需在同一事务检查需求计划、生产任务和其下游引用。只有未提交、未发生执行的派生草稿可以按受控规则撤销；已提交、已审核或已执行的派生单据须先处理，禁止静默覆盖或删除人工调整。派生单据审核后由后续采购、收货、裁剪及排产使用，避免草稿提前驱动库存或生产。

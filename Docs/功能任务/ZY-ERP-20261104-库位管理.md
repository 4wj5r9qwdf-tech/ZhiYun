## 一、业务目标与范围

- 要解决的问题：为每个仓库建立可实际使用且可扩展到 AGV 的仓内位置档案，支持区域、货架、货位三级定位；允许企业按仓库选择入库时必须记录到哪一级，既不强制所有业务录入货位，也不丢失精确到货位的能力。
- 目标用户/角色：仓库管理员、库存负责人、系统管理员；后续库存收货、领退料、样衣入库和 AGV 服务复用本功能的位置数据。
- 本次包含：
  - 一个“库位管理”功能入口和一个页面，页面内选择仓库、展示位置树、查看筛选结果并新增/编辑/停用/删除位置。
  - 维护区域、货架、货位三级父子关系；位置编码在同仓库内唯一，支持名称、状态和备注。
  - 仓库档案配置“入库定位层级”：仓库级、区域级、货架级、货位级。该设置定义入库单必须填写的最深位置层级；位置档案层级始终完整可建，不因开关而隐藏货位。
  - AGV 基础兼容字段：稳定位置编码、父级位置、位置层级、AGV 可达标记、位置用途/限制、容量上限及计量单位预留、占用/锁定状态及状态更新时间预留、外部设备位置映射码预留。首期不接 AGV、不自动改变占用状态、不做自动寻址和路径规划。
  - 后端校验父子层级、同仓库归属、编码重复、停用/删除引用关系及位置层级；停用或删除父级时保护其有效子级和后续业务引用。
  - 业务审计及中文接口错误。
- 本次不包含：库存余额和库存移动事务、入库/出库单、盘点、容器/周转箱、AGV 任务调度、地图坐标/路径规划、设备通信协议、自动占位或自动分配货位。
- 前置条件与依赖：仓库管理已验收；复用现有人员权限、业务审计；库存单据后续通过稳定库位 ID 记录明细位置。

## 二、需求与实现确认

- 页面布局：一个页面完成全部位置维护。顶部筛选仓库及位置关键字/状态；左侧为区域→货架→货位树，支持展开/收起和按层级新增；右侧为当前节点及子级表格、筛选和操作；新增/编辑使用统一弹窗。没有选中仓库时提示先选择，不显示空白页。
- 数据层级：
  - 区域：仓库的直接子级；
  - 货架：区域的直接子级；
  - 货位：货架的直接子级；
  - 每个节点必须且只能属于一个仓库；父节点必须属于同一仓库且层级紧邻；不允许跨仓库移动位置。
- 入库定位层级：仓库字段 `inbound_location_level` 取值 `0/1/2/3`，分别表示仓库/区域/货架/货位。`0` 表示无需选择库内位置；`1` 至 `3` 表示入库必须指定对应层级及其上级链路。此配置仅定义必填深度，后续单据仍可自愿录入更深位置。库位功能先维护此配置，真正收货单上线时再调用同一规则校验。
- AGV 兼容规则：
  - 位置编码作为稳定人工码和对外映射依据，数据库主键不承担外部设备编码职责；本期禁止静默修改已被业务引用的位置编码。
  - 每个货位可独立标记是否允许 AGV 到达；区域/货架的限制可作为子级默认值，货位可覆盖。
  - 容量上限和容量单位按位置记录，容量占用量由未来库存/容器事务计算，本期不维护伪库存。
  - 状态预留可表示可用、占用、锁定、维护中、在途；本期档案只允许管理人员将位置设为可用、停用或维护中，动态占用/锁定/在途由未来库存和 AGV 事务维护。
  - 外部位置映射码、坐标/地图等未来字段可空；坐标、路径、设备状态不在首期增加无明确坐标系的数据列。
- 异常、边界和重复操作：重复编码拒绝；货架不能挂区域以外层级、货位不能挂非货架；停用位置不得用于新入库；父级停用前须先停用/迁移其子级；存在库存或业务单据引用的位置不允许物理删除，采用停用保留历史；编辑仓库并提高入库定位深度时，必须先存在至少一个该层级的可用位置；新仓库允许按默认层级先建档，以便先创建位置树。
- 权限与数据范围：列表/树读取、新增、编辑、状态修改和删除使用独立权限点；选项接口要求登录；不擅自修改角色默认授权，超管按现行规则拥有权限。
- 关联模块/单据：仓库管理、后续物料档案与库存批次、客供/自采收货、通用领退料、样衣入库及 AGV 配送任务。
- 用户确认人及日期：用户于 2026-11-04 确认区域、货架、货位均需建设；入库不固定强制选择货位，使用开关控制入库定位层级；库位管理可集中在一个界面完成；本任务是按该确认编制的实施任务。
- 实现方案确认记录：位置实体采用单表自关联树；仓库保留入库定位层级配置；业务单据通过 location_id 外键/引用保存具体位置，不把名称路径当作唯一关联；首期页面以仓库为边界管理三级树。

## 三、技术契约

### 数据库

- 涉及表/字段：
  - `inv_warehouse_location`：`location_id`、`warehouse_id`、`parent_location_id`、`location_code`、`location_name`、`location_level`、`agv_reachable`、`capacity_limit`、`capacity_unit`、`location_status`、`external_location_code`、`remark`、标准审计及逻辑删除字段。
  - `inv_warehouse.inbound_location_level`：入库定位必填深度（0仓库、1区域、2货架、3货位），默认 2（货架级，符合当前至少货架定位规则）；用户可在仓库管理中设置。
  - 状态日志首期复用业务审计，不单独建立未经业务使用验证的 AGV 状态流水；实际库存移动历史由后续单据负责。
- 约束与索引：同仓库未删除位置编码唯一（大小写不敏感）；按仓库、父级、层级和状态索引；父级与仓库一致、层级紧邻由事务服务校验；外部映射码按非空值约束仓库内唯一。
- DDL 负责人：Codex。
- 迁移文件与执行顺序：`sql/库位管理_20261105.sql`，先确认仓库表存在，再幂等升级仓库层级配置和创建位置表、索引、中文注释、权限点；执行后验证开发库结构。功能验收后按开发规范并入 `sql/主建表.sql`。
- 回滚/补偿方式：开发阶段新增空表和可空仓库配置字段；不删除业务数据。撤销入口不影响已有仓库档案；位置进入业务引用后仅停用，不物理回滚删除。

### API

| 方法/路径 | 用途 | 请求/响应契约 | 权限 |
|---|---|---|---|
| GET `/system/warehouse-location/tree` | 按仓库读取三级位置树 | `warehouseId`；返回树节点及层级、状态、AGV 可达性和容量属性 | `inventory:location:list` |
| GET `/system/warehouse-location/list` | 查询当前仓库/父级下位置列表 | `warehouseId`、可选 `parentId`、`level`、`keyword`、`status` | `inventory:location:list` |
| GET `/system/warehouse-location/options` | 页面所需在用仓库及定位层级配置 | 返回仓库 ID/编码/名称、`inboundLocationLevel` | 登录 |
| GET `/system/warehouse-location/{id}` | 位置详情 | 返回位置字段及父级展示信息 | `inventory:location:query` |
| POST `/system/warehouse-location` | 新增位置 | 仓库、父级、层级、位置编码/名称、AGV 可达性、容量限制、状态、备注 | `inventory:location:add` |
| PUT `/system/warehouse-location` | 修改位置 | 位置 ID 与可编辑字段；禁止跨仓移动和破坏层级 | `inventory:location:edit` |
| PUT `/system/warehouse-location/{id}/status` | 启用/停用/维护状态 | 状态；保护动态占用状态不被人工覆盖 | `inventory:location:edit` |
| DELETE `/system/warehouse-location/{id}` | 逻辑删除空且未被引用的位置 | 被子级或业务单据引用时拒绝并提示改为停用 | `inventory:location:remove` |
| POST/PUT `/system/warehouse` | 新增或修改仓库档案时保存 `inboundLocationLevel` | 0–3；作为后续入库单据最小定位深度，本期不校验尚未建档的位置 | `inventory:warehouse:add/edit` |

所有写操作要求登录并记录业务审计；查询仅返回未删除档案；跨仓操作和非法层级由服务端拒绝。

### 页面与配置

- 页面/路由：库存 → 库位管理；`/stock/locations`。仓库档案编辑页增加“入库定位层级”设置及说明。
- 页面模式：单页左右分栏，仓库筛选 + 位置树 + 节点表格/详情弹窗；区域、货架、货位无需跳转独立页面。
- 文件存储/消息/定时任务：无。

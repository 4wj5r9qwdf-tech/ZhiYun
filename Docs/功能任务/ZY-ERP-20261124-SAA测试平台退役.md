## 一、结论与决策依据

### SAA 是否已经“无人维护”

截至 2026-11-24，**不能据公开资料断言 Spring AI Alibaba（SAA）已经正式停止维护或无人维护**：上游仓库没有正式 Archived/EOL 声明，相关 issue 到 2026-10-09 仍有协作者参与讨论。能确认的是其发布与治理存在实质不确定性：上游 Releases 页面显示最新稳定版 `v1.1.2.2` 于 2026-03-10 发布；针对 Spring AI 2.0 的 `#4717` 议题仍为 Open，虽然 2026-06-25 曾发布 `v2.0.0-M1.1` 预览版，但在 2026-08-25，前 PMC/Committer 公开表示发版拖延、考虑脱离阿里改名并自行维护。2026-10-09，SAA 协作者称 ARGI 是从 SAA 分叉并将作为长期项目维护。整体证据显示 SAA 后续正式版节奏、维护归属和治理安排不明确，且核心维护者路线已经分化；**这不等于官方已宣布废弃或代码库完全无人维护**。

- 上游稳定版及 2.0 预览版时间：[Spring AI Alibaba Releases](https://github.com/alibaba/spring-ai-alibaba/releases)
- Spring AI 2.0 支持议题和维护者评论：[Issue #4717](https://github.com/alibaba/spring-ai-alibaba/issues/4717)
- 上游源码仓库：[alibaba/spring-ai-alibaba](https://github.com/alibaba/spring-ai-alibaba)

### AgentScope Java 与 ARGI 的关系

- **AgentScope Java**：阿里维护的另一条 Java Agent 框架路线，不是 SAA 的新仓库兼容版。官方 Releases 页面在 2026-11-14 发布 `v2.0.5` 维护版，并有 2.1.0 Beta 预览，近期维护信号较明确；但仍须针对织云的 Spring AI 2.0 / Spring Boot 4、MCP、身份授权、审计和部署做 POC。[官方仓库与版本](https://github.com/agentscope-ai/agentscope-java/releases)
- **ARGI**：由 SAA 前维护者推动的独立社区项目，公开讨论称其基于 SAA 2.x 分支发展；不属于阿里官方项目。其仓库介绍 Spring AI adapters，只能说明有 Spring AI 接入适配，不能推定与 SAA 的 Maven 坐标、Java API、Agent Studio、管理端、Skill 或本地数据兼容。[ARGI 仓库](https://github.com/agentic-ai-java/argi)
- 因此，本次退役只移除织云拉取并运行的 **SAA Agent Studio 独立试验平台**；保留 ERP 主工程使用的通用 Spring AI 依赖，也没有把 ARGI 或 AgentScope Java 自动迁入项目。

## 二、本地平台状态与范围

- 本地 SAA 源码固定在上游提交 `17e26ff6fe951d605771c1845229ca3edb043634`，曾通过 PostgreSQL 适配补丁作为独立 Agent Studio 运行。
- 它与 SnailAI 并行试验，但尚未接入 ERP 员工身份、业务 MCP 或 ERP API；独立登录、真实模型对话、Skill/MCP、文件处理和同场景对比均未完成验收。因此已有启动成功、补丁构建通过等记录只表示开发环境试运行，不代表完成框架选型或业务接入。
- 移除：SAA Git 子模块及本地 Git 缓存、补丁/部署目录、专用适配和启停/状态脚本、项目服务链路、ERP 前端入口与路由、开发库专用菜单与角色授权、专用中间件镜像、运行目录和 SAA 日志。
- 保留：独立 PostgreSQL 数据库 `spring_ai_alibaba_admin`。删除的 `.runtime/spring-ai-alibaba/` 包含源码工作区、Nacos/Elasticsearch/RocketMQ 测试状态、测试密钥和日志；它是本地可重建的测试运行数据，本次根据用户追问一并清除。
- 保留：ERP 后端通用 Spring AI 依赖及 SnailAI 接入代码，不改业务 MCP、员工助手数据或其他框架服务。

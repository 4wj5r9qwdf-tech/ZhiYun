## 一、业务目标与范围

- 要解决的问题：在库存模块建立仓库主档，区分仓库用途标签，并记录所属建筑、楼层、区域及负责人。
- 目标用户/角色：仓库管理员、库存负责人、系统管理员。
- 本次包含：仓库新增/查询/编辑/软删除/启停；仓库类型复用通用标签并初始化成品仓、面料仓、辅料仓、消耗品仓、设备仓、样衣仓六项常用提示（仍可自由新增）；所属建筑和负责人选择；楼层选项依据建筑档案的楼层信息生成；库存模块卡片和页面入口。
- 本次不包含：库位树、物料档案、库存数量/批次、收货、领料、退料及 AGV 调度。
- 前置条件与依赖：已存在的组织架构、建筑档案、人员信息、标签管理和统一业务审计。

## 二、需求与实现确认

- 输入与操作：填写仓库编码、名称、类型标签、所属建筑、所在楼层/区域、负责人、状态和备注；楼层由建筑档案的楼层数生成并在服务端校验。
- 输出与状态变化：列表显示仓库及位置、类型和状态；停用仓库不得作为新业务仓库；删除为逻辑删除。
- 异常、边界和重复操作：仓库编码不区分大小写查重；必填编码/名称；重复删除或编辑不存在记录返回中文错误；标签必须属于仓库管理标签空间；楼层不能超出所属建筑档案的楼层数。
- 权限与数据范围：列表、详情、新增、编辑/启停、删除分别校验权限；选项接口要求登录；不改变现有角色默认授权。
- 关联模块/单据：建筑档案、人员信息、通用标签。
- 用户确认人及日期：2026-11-04，用户确认按已评审规划开始实施，允许使用中补充。
- 实现方案确认记录：采用 `inv_warehouse` 存仓库主档，类型保存在 `sys_tag_relation`；不将仓库作为组织节点或建筑类型。
- 命名与注释核对：功能名“仓库管理”及表名前缀 `warehouse` 与功能命名清单一致；仓库业务字段英文口径登记在术语词库 v1.9；表、字段、索引和主键序列均提供中文业务注释，后端接口和校验辅助函数提供 JavaDoc。

### API

| 方法/路径 | 用途 | 请求/响应契约 | 权限 | 负责人 |
|---|---|---|---|---|
| GET `/system/warehouse/list` | 仓库列表 | 可按关键字、状态、标签筛选 | `inventory:warehouse:list` | Codex |
| GET `/system/warehouse/options` | 表单选项 | 返回在用建筑（含楼层信息）和人员 | 登录 | Codex |
| GET `/system/warehouse/{id}` | 仓库详情 | 主档字段及关联标签 | `inventory:warehouse:query` | Codex |
| POST `/system/warehouse` | 新增仓库 | 主档字段及 `tagIds` | `inventory:warehouse:add` | Codex |
| PUT `/system/warehouse` | 编辑仓库 | `warehouseId`、主档字段及 `tagIds` | `inventory:warehouse:edit` | Codex |
| PUT `/system/warehouse/{id}/status` | 启停仓库 | `status`：0启用/1停用 | `inventory:warehouse:edit` | Codex |
| DELETE `/system/warehouse/{id}` | 逻辑删除 | 仓库ID | `inventory:warehouse:remove` | Codex |

所有写接口要求登录；新增/编辑/启停/删除写业务审计日志。写接口幂等性、副作用、前置条件和审批要求将在验收时按 API 文档规范登记。

# 物料需求计划功能任务

版本：1.0
更新日期：2026-11-17
说明：定义客户订单审核后的物料需求计划单、算料快照、计划调整、汇总查看和审批边界。

## 一、目标与业务边界

物料需求计划（MRP）承接已审核客户订单中的 PO、款式/套装配套、色码数量和已发布款式 BOM 用料快照，为计划人员核对和调整物料需求提供单据入口。该单据是计划依据，不是采购订单、收货单或库存流水；计划调整不反写客户订单、款式档案或 BOM。

客户订单审核通过时，同一事务幂等生成一张草稿需求计划。计划按客户订单保留多个 PO 的来源明细；尚未保存完整算料的订单仍可生成“待算料”计划，但不能提交审批。历史上已审核、尚无计划的订单可从需求计划功能补生成。

## 二、计划单头字段

| 字段 | 说明 | 来源/规则 |
|---|---|---|
| 需求计划单号 | 唯一业务编号 | 系统生成，列表与审批引用 |
| 来源客户订单 | 客户订单编号及穿透入口 | 来源快照，不可编辑 |
| 来源订单修订号 | 生成时订单修订号 | 识别计划依据，不反写订单 |
| 客户 | 客户名称快照 | 来源订单 |
| 订单日期/归属公司 | 订单背景信息 | 来源订单 |
| 客户 PO | 计划下属 PO 集合 | 每个需求明细保留 PO 号、交期和供料安排 |
| 计划状态 | 草稿、审批中、已审核、已取消 | 工作流结果或有权人员的直接审核结果 |
| 算料状态 | 待算料、已完成、需核对 | 只有完整算料快照可以提交审批 |
| 制单人/计划员 | 当前账号及后续调整人 | 系统记录；权限由物料需求计划功能权限控制 |
| 创建/修改时间 | 时间戳 | 系统记录 |
| 调整原因/审核意见 | 最近一次业务说明 | 计划数量调整必填原因；流程意见由审批引擎保存 |

## 三、物料需求明细字段

每行是一项来源 PO/款式色码/BOM 物料用量，保存生成时的文字快照，不能因基础资料后来改名、停用而改变历史计划。

| 字段 | 说明 |
|---|---|
| 来源 PO 与 PO 交期 | 保留多 PO 分批交货边界 |
| 客户款式/套装规格/子款 | 单款显示款式；套装按子款归属展开，并保留套装规格 |
| 款式颜色、尺码、订单数量 | 订单色码来源及数量；套装保留每套子款配套与件数 |
| BOM 版本、用料类型、部件/子款位置 | 追溯需求计算依据 |
| 物料分类、物料编码、物料名称 | 物料档案快照 |
| 物料规格编码/名称、物料颜色 | 多规格物料同一档案可出现多行；规格和颜色必须分别保存 |
| 库存单位、原始需求量 | 来自 BOM 的库存单位需求快照 |
| 计划需求量 | 计划人员可在草稿中调整；非负，变化必须填写原因 |
| 采购单位换算参考 | 保存物料档案中可采购单位、换算模式/系数和对应数量快照；按实际换算的单位显示“待实际换算”，不得虚构采购数量 |
| 供料方式 | 客供、自采、客供＋自采；混合方式表示收货来源可选择，不预拆客供/自采数量 |
| 调整原因 | 每次变更数量的前值、后值、操作人、时间及原因均保留 |

## 四、页面与操作

1. 物料需求计划位于“订单”模块。主列表按功能模板展示计划单号、来源订单、客户、PO、物料行数、算料状态、单据状态、制单人与时间；支持按单号/订单号/客户/PO/状态/算料状态筛选、列设置和列宽自适应。
2. 详情使用完整工作区。单据头展示订单及 PO 摘要，明细区有“按物料汇总”和“按订单色码明细”两种视图，并可按 PO、物料分类、物料、颜色、规格、供料方式筛选。
3. 汇总视图按物料档案、物料规格、物料颜色、库存单位及供料方式归组，同时保留可展开的 PO/款式色码来源；不同规格、颜色或供料方式不能合并丢失。
4. 明细视图按 PO、款式/子款、颜色尺码展示来源订单数量、BOM 原始需求、可编辑计划需求、库存单位、采购单位换算参考和调整原因。
5. 草稿支持保存调整、提交审批、取消；审批中只读；已审核只读。普通审核无已发布流程绑定时按单据审核权限直接办理；绑定流程时统一通过 Warm-Flow 办理。审批退回回到可编辑草稿并保留意见。
6. 已存在草稿的订单重新算料时：无人工调整的草稿可在同一事务同步当前完整订单算料快照；已人工调整或已提交/已审核计划必须先处理，禁止覆盖调整。取消的历史计划保留，重新生成新单号。
7. 无完整 BOM/色码快照时计划标记为待算料或待核对并阻止提交；页面提供返回来源订单算料的穿透入口。空结果必须与权限不足、资料失效和加载失败分别提示。

## 五、权限、审批与审计

- 独立菜单权限：列表/查看、计划编辑与补生成、审核、取消。服务端按操作逐项校验，前端仅负责展示。
- 物料分类人员范围必须服务端复核。计划包含用户无权查看的物料分类时，不静默过滤，明确提示管理员调整权限。
- 订单审核通过回调与计划创建处于同一事务；唯一约束和订单行锁确保重复审核/回调不重复建单。
- 审批业务类型为 `material_demand_plan`，与客户订单共享审批门面和业务实例关联表；未绑定流程时走物料需求计划审核权限。
- 已审核计划的反审核是独立审批事项 `material_demand_plan_unapprove`，必须单独绑定一条已发布流程；绑定不可解除，只能更换流程。反审核申请必须填写原因；审批中原计划保持已审核，审批退回或终止不改变状态。审批通过后计划回到可编辑草稿，清除原审核人/审核时间，但保留需求明细、计划调整历史及审批记录；是否取消计划由计划人员在之后另行操作。
- 保存、数量调整、提交、退回、审核、取消、同步/重新生成均写业务审计；数量调整单独保存前后值、原因、操作人和时间。
- 计划版本使用并发修订号。基于旧版本保存或重复提交必须拒绝并提示刷新。

## 六、实施与验收场景

1. 订单无算料快照审核后，自动有待算料计划；订单保存完整算料后，计划同步成可核对明细。
2. 一个订单多个 PO、同物料不同供料方式、不同规格/颜色不能被错误合并；汇总可展开追溯到 PO 和款式色码。
3. 套装计划保留套装规格与每个子款的实际色码、数量；单款多色多码各自可追溯。
4. 多规格物料相同档案的不同规格各有独立需求；采购单位固定换算显示参考数，按实际换算不推算卷数或包装数。
5. 草稿数量调整要求原因并保存前后值；旧版本并发更新失败；重新算料不能覆盖已调整计划。
6. 没有物料分类权限时整个明细返回明确权限提示，不显示成空计划。
7. 未绑定普通审批流程可由有审核权限人员处理；绑定流程后进入我的待办/我发起的/我的已办及铃铛通知，穿透打开需求计划。反审核必须绑定独立流程并展示申请原因；通过后回到草稿，退回或终止则继续保持已审核。
8. 菜单权限、API 权限、业务审计、开发 SQL 中文表/字段注释、API 文档及主 SQL 评估齐全。

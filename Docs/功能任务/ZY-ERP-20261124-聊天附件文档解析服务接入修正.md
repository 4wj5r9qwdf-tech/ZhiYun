## 一、问题和原因

- 用户反馈 SnailAI 智能体无法通过 `read_chat_document` 解析上传的 XLSX。
- 当前工具和解析器都允许 `.xlsx`；解析失败时 SnailAI 桥接层会把解析 I/O 或服务状态异常折叠成“读取失败，请检查文件格式或文档解析服务”。
- 开发 profile 默认禁用 Docling，且原框架控制台启动链路没有自动启动 Docling 容器。解析服务未运行时，错误提示看起来像格式不支持，实际需要先恢复 Docling 服务。

## 二、本次修改

- `scripts/start-framework-consoles.sh`：没有显式启用/禁用、远程地址或密钥文件配置时，启动受资源限制的本地 Docling 开发容器，并向 SnailAI 传入容器地址和密钥文件路径。显式 `SNAIL_AI_RAG_DOCLING_ENABLED=false` 保持关闭；用户提供远程配置时不覆盖。Docker 缺失、内存门槛不满足或容器启动失败时输出提示并继续启动 SnailJob/SnailAI。
- `.env.example`：移除默认写入的 `SNAIL_AI_RAG_DOCLING_ENABLED=false`，避免复制模板后无意关闭本地解析；保留显式关闭示例。
- `scripts/docling-dev.sh`：已有容器运行时先复用；只有首次创建或重启停止容器时才执行 3 GB 可用内存门槛。密钥文件缺失但容器仍存在时拒绝自动生成新密钥，避免容器与客户端认证不一致；状态和停止操作不读取或创建密钥。
- `scripts/status.sh`、`scripts/stop.sh`、`scripts/start.sh`：状态检查和完整停止/启动链路纳入本地 Docling 容器。
- `Docs/规范/开发环境与同步流程.md`：说明本地自动启动、显式配置优先级和状态检查范围。

## 三、验证结果与边界

- 运行开发环境的 Docling `/health` 认证请求返回 HTTP 200。
- 使用合成内存 XLSX 向 Docling 提交并轮询解析，任务成功，解析结果包含样例标记。它证明解析服务支持该类 XLSX 输入，不证明用户的原始工作簿内容正确，也不证明 ERP 会话中的模型已实际调用工具。
- Docling 启动后 SnailAI 已在运行环境重启；此前服务状态检查显示 SnailAI 管理端和 gRPC 端口在监听。
- 本次没有拿到用户上传的原始 XLSX，也没有在已登录 ERP 聊天中触发真实 `read_chat_document` 调用。当前升级工作区没有 `.env`，因此没有从该工作区启动服务。
- 脚本验证：`bash -n scripts/start.sh scripts/stop.sh scripts/status.sh scripts/docling-dev.sh scripts/start-framework-consoles.sh` 通过；`git diff --check` 通过。`bash scripts/docling-dev.sh start` 复用已运行容器成功，`status` 报告容器运行中。使用临时且不存在的用户配置目录验证密钥文件缺失保护：脚本拒绝启动且未生成替代密钥。`bash scripts/status.sh` 显示 ERP、SnailAI、Docling 和依赖服务均在运行。
- 完整启动脚本没有在本工作区执行：该隔离 worktree 没有 `.env`，避免为测试伪造数据库凭据或启动升级分支服务。真实聊天附件调用仍待用户使用原会话重试验收。

## 三、业务契约

- 输入与操作：升级后 ERP 员工使用现有账号、菜单权限、组织数据范围、审批、MCP 和 SnailAI 功能。
- 输出与状态变化：升级只改变经审查的框架源码、兼容依赖和必要数据库结构；不应改变已有 ERP 业务单据的含义及权限范围。
- 异常、边界和重复操作：依赖不兼容、迁移失败、审批状态无法映射、权限范围扩大或 MCP 运行时契约变化时，停止后续切换，保留原 6.0.0 检查点并修复或回退。
- 权限与数据范围：员工只能读取既定角色与组织数据范围内的资料。上游 6.0.0 有公开的部门用户列表数据权限问题；织云定制的 `/system/user/list/org/{orgId}` 必须验证并按已确认的组织范围规则保护。
- 删除策略与恢复方式：不删除现有业务数据；Warm-Flow 新增表及旧状态数据转换按迁移脚本执行，回退前先按迁移前备份恢复。
- 关联模块/单据及数据来源：用户/组织、流程定义与实例、ERP 审批单、MCP 工具、SnailAI 服务、代码生成器、数据权限拦截器。
- 对历史数据和下游流程的影响：Warm-Flow 2.1.1 迁移涉及流程表结构、历史状态值、字典/菜单和 `flow_event_wait`；必须用隔离的开发库副本验证现存实例读取、审批处理和状态显示。

# MCP 字段契约迁移

## 目标与字段规范

这轮按 JY 的要求统一 API 文档和 Skill 的字段规则。每个请求参数和 Map 嵌套字段都应明确写出：

- 字段路径、类型、示例值、是否必填、适用的 create/update/状态动作。
- 字段省略、JSON `null`、空白字符串、空数组、空对象分别如何处理；未明确允许时调用方不得自行传空值。
- 字段用途、来源、默认值、枚举或数值边界、关联校验、更新是补丁还是完整替换，以及数据影响。
- 一份可复制的真实 MCP `arguments` 示例；多个独立工具调用使用 JSON Lines，各工具 schema 必填参数保持与实际注解一致。

API 分组文档维护字段语义权威矩阵，功能 Skill 说明任务编排和前置依赖，并链接到该矩阵。MCP 注解中的描述应对应实际服务端约束；运行时 `inputSchema` 仍决定公开的顶层类型和必填字段。不得把 REST body 示例误写成 MCP `arguments`。

## 本轮代码修正

- 通用主数据、基础资料、人员、仓库、尺码、标签、款式、BOM、审批工具的自由 Map 参数改为显式字段白名单和类型/枚举/集合校验；对 ID 保留原始 JSON 类型，拒绝数值 ID，避免精度丢失。
- 写工具更新按业务实际区分完整替换与补丁。集合字段逐项落实“省略保留、`[]` 清空或无变更、显式 `null` 拒绝/允许”的语义，避免各资源行为含混。
- 款式生产模式拒绝不适用的单款颜色、尺码和排除组合输入，前端同步按模式省略这些字段。
- 物料需求计划 REST 明细请求在转换前检查 `itemId` 的 JSON 类型，接受十进制字符串并拒绝数字、无效或非正数 ID。请求 `items` 省略、`null` 或 `[]` 的无变更行为明确记录；当前没有对应 MCP/Skill 工具，不虚写为已接入。
- 公司和仓库档案的查询输出将数据库主键以字符串返回；仓库自动编码只把真正缺失值视为未提供，不把空白静默当作自动编码占位。
- SnailAI 只读分类改为精确工具名白名单。未知工具一律按写操作等待确认；工具名后缀不能单独构成只读证明。

## 写操作确认边界

经代码核对，MCP Server 工具本身不会弹出确认框。ERP 内嵌 SnailAI 的 `ObservedToolCallback` 在每个非只读 delegate 执行前发送一次性确认事件，并等待同一当前员工确认；拒绝、超时、错误员工和会话关闭都不能执行写 delegate。ERP 页面显示确认卡及工具参数。独立连接的 MCP 客户端不经过这个 ERP 页面包装器，必须自行实现人工确认。

每个具体写工具的调用说明仍须要求先读取当前对象和关联数据，再向员工展示对象、字段差异、影响范围及不可逆结果，取得本次确认后才执行。运行时确认卡能阻断调用，但不能替代智能体向员工说明业务影响。

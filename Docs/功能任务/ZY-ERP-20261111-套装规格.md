# 套装规格实施计划

状态：前后端已实现，开发库已迁移，用户于 2026-11-11 验收通过。

## 目标与界面

在款式档案的套装编辑页面，套装组成之后增加“套装规格”。用户先维护套装子款，再新增规格；每条规格填写套装配色、套装尺码及备注，并逐个子款选择有效颜色尺码组合。支持串色、不同子款尺码及均码，组成件数由套装组成带出。允许套装暂不配置规格。

## 数据与校验

规格由稳定 ID、套装 ID、配色名称、套装尺码名称、排序和备注组成；明细记录组成子款 ID、颜色 ID、尺码 ID 及每套件数。具体颜色尺码须属于子款已选且未排除的有效组合。提交时事务内校验子款完整、不可重复、无额外子款、规格名称组合不重复及分类访问权限；不能凭客户端结果授权。

## 组成变更与历史

改变组成或子款规格时，识别并提示受影响的套装规格；不得静默删除或改变配置，需由用户修正。历史引用使用订单确认时的组成、子款颜色尺码、件数快照，不随档案改动。订单、BOM、生产、吊挂和库存尚未接入时仅预留契约，不宣称已经联动。

## 实现记录

规格随款式在同一事务保存，沿用款式查看和编辑权限，变更纳入款式操作审计。配套件数直接读取当前套装组成，避免两处设置不一致。增删子款时需要同步规格明细；已被套装规格引用的子款颜色尺码须先解除或调整引用，再从单款档案移除。配置接口返回 `setSpecs`，旧客户端省略此字段时保留现有规格并检查组成一致性。

# 款式档案一期

状态：一期用户验收通过（2026-11-11）。入口为「研发 → 款式档案」。

## 业务归属

- 研发、样衣和生产订单共用 `rd_style.style_id`。允许先建款，再建样衣任务或订单。
- 样衣任务记录用途、轮次、尺码颜色数量以及所引用的技术资料版本。同款可有多轮、多件样衣。
- 款式技术资料和 BOM 后续按款式维护版本。已发布样衣任务保留所引用版本，封样记录关联确认的样衣和版本。大货工艺可从确认版本复制并记录来源，随后独立修改。
- 款号为唯一编号，全局不区分大小写唯一，创建后固定。客户档案仍单独关联且可空，便于自主研发；不再区分内部款号与客户款号。
- 分类复用公共多级分类和人员范围，页面可配置默认分类类型。季节使用不含年份的选项，历史值可保留。主图存现有私有桶，仅经款式授权接口预览。

## 一期验收范围

- 列表、查询、新增、保存并新增、查看/编辑、启停、删除和主图。
- 分类范围覆盖列表、查询选项、写入及主图访问。停用分类和客户可保留在既有款式中，禁止新引用。
- 研发菜单的列表、新增、编辑及启停、删除权限可分配。增删改和启停记录款式对象及业务字段变更。
- 增量 SQL 包括款式档案、规格与套装、附件三个脚本，已按依赖顺序并入主建表。REST 根路径为 `/rd/style`，MCP 与 API 契约见《API/款式档案API.md》。

## 一期交付

- 款式标签按「研发 → 款式档案 → 标签分组」维护。款式和子款分别保存多选标签，列表按标签筛选。启用的标签可新选，原有停用标签可保留。
- 单款可多选颜色、尺码，尺码组可追加当前启用的尺码。默认组合全部有效，保存单独排除的颜色尺码组合。
- 套装支持合并生产和分开生产。合并生产可记录同架要求。子款可选择已有单款，也可在套装表单中打开完整子款表单。子款单独保存，套装组成在套装保存后生效。
- 增量 SQL 依次执行标签分组、原款式档案及 `sql/款式规格与套装_20261109.sql`。新增与编辑的组合数据随款式保存，接口提供 `GET /rd/style/spec-options`、`GET /rd/style/{id}/configuration` 和 `GET /rd/style/{id}/tags`。
- 后续待补：款式来源、负责人和可编辑的自动款号建议。订单按生产方式校验子款能否独立下单，订单配色配码、实际衣架绑定及下游资料版本随相应功能交付。

## 款式分类定位

- 页面左侧按“分类类型 → 多级分类”展示当前人员可见的分类及定位所需祖先。选中节点时显示该节点及下级中有权查看的款式，重置时回到系统参数所设的默认类型。未配置时显示全部授权分类。
- 参数设置中的“款式默认分类类型”有值时，档案树、列表和新增分类选项只展示配置类型内有权查看的内容。留空时可从全部授权类型中选择。配置不可用时提示检查参数或分类权限。
- 新增款式和子款使用配置类型，若左侧已明确选中该范围内的可用分类，新增款式可带入该节点。分类数据的读取和保存仍执行人员分类权限。
- 参数键为 `rd.style.defaultCategoryScheme`，写入接口 `POST /system/config/style-default-category` 要求系统参数编辑权限并记录业务审计；款式页通过 `GET /rd/style/default-category` 获取当前人员可用的默认定位。

## 季节与款式附件

- 季节选春、夏、秋、冬、春夏、秋冬、四季，不带年份；列表可按季节筛选。历史文本保留原值，后续报表对历史值单列，按业务确认后整理。
- 款式与子款分别维护图片列表，并从列表中指定一张主图；已有独立主图兼容显示在列表中。主标、尺码标、洗标、吊牌、吊牌贴纸和文档附件每类支持多个文件；图片支持 PNG/JPG，文档另支持 PDF/DOCX/XLSX/PPTX，单文件最多 10 MB。
- 附件使用私有桶和款式分类权限，只有上传人可以把新上传文件绑定款式。移除附件解除关联，不物理删除文件；套装和子款的附件相互独立。
- 开发数据库增量脚本为 `sql/款式附件_20261109.sql`。文件引用随款式事务保存，上传后如放弃表单会产生未关联文件，后续需单独设计安全的定期清理机制。

## 字段规划与业务边界

研发、样衣和生产订单引用同一款式。款式档案维护基础资料、单款可用规格及套装组成。BOM、工艺、部件和裁片各有独立功能页，选套装后在各自页面按子款分别维护。实际套装配色配码归订单或 PO 明细，确认后保存快照。

### 基础资料

| 字段 | 适用范围 | 填写规则 | 当前情况 |
|---|---|---|---|
| 款式类型 | 单款、套装 | 必填，默认单款。套装显示生产方式与组成区 | 新增 |
| 款号 | 单款、套装 | 必填，全局不区分大小写唯一，创建后固定。参数启用自动编码时可带出建议，保存前可修改 | 已有手填，规划补编码规则 |
| 款式名称 | 单款、套装 | 必填 | 已有 |
| 款式分类 | 单款、套装 | 必填，复用公共多级分类，按人员授权选择。套装类型和组成角色单独记录 | 已有 |
| 客户 | 单款、套装 | 选填，复用客户档案，自主研发可以先留空 | 已有 |
| 款式来源 | 单款、套装 | 建议选填。可维护的选项，例如客户来样、客户来图、自主研发 | 新增 |
| 设计／技术负责人 | 单款、套装 | 建议选填，引用员工 ID，复用人员选择器 | 新增 |
| 季节 | 单款、套装 | 选填，如 2026 秋冬 | 已有 |
| 款式标签 | 单款、套装 | 选填，按标签分组展示；每组可多选，复用公共标签体系并支持按标签筛选款式 | 新增 |
| 主图、款式说明、备注 | 单款、套装 | 选填。主图沿用私有附件访问规则 | 已有 |
| 状态 | 单款、套装 | 启用或停用，停用后禁止新业务引用，保留历史记录 | 已有 |
| 创建人、创建时间、最后修改人、最后修改时间 | 单款、套装 | 系统记录，页面只读 | 已有 |

建议将研发阶段随样衣、封样和订单等业务形成后再展示。该阶段与档案启停分开。

款式分类用于主归类，例如上装、下装、帽饰；标签用于补充可扩展属性，并按用途分组，避免把不同维度的词混在一个多选框里。款式标签建议至少分为：

| 标签分组 | 示例 | 说明 |
|---|---|---|
| 默认分组 | 尚未归类的现有标签或新标签 | 系统默认分组，保证每个标签都有明确归属；用户之后可以调整分组 |
| 适用人群 | 童装、男装、女装、中性款 | 描述款式面向的人群；一个款式可多选 |
| 使用场景 | 校服、工装、运动、通勤 | 描述穿着或销售场景；一个款式可多选 |
| 款式特征 | 连帽、宽松、加绒 | 描述款式外观或穿着特征；一个款式可多选 |
| 主题风格 | 可按需维护 | 可选分组，供品牌系列、联名主题等扩展 |

分组是标签的组织维度，不替代款式分类，也不把标签值锁死成枚举：用户仍可在相应分组下新增标签，并把常用标签设为提示。每个标签都必须归属一个分组；未指定分组的新标签默认进入“默认分组”，已有未分组标签也迁入“默认分组”，之后允许用户调整。分组和标签都按“款式”模块隔离；同名标签可存在于同一功能的不同分组中，但筛选和报表需同时保留分组语义。套装和子款分别维护标签，按当前档案自身标签筛选。款式类型、套装生产方式及颜色尺码由对应业务字段管理。标签报表允许一款出现在多个标签下，汇总款式总数时按款式去重。

公共标签管理集中提供入口，每个具体功能独立拥有自己的分组。款式档案应复用 `sys_tag_group`、标签管理分组维护和分组标签选择器，不另建款式专属分组字段或组件；款式功能安装增量脚本后获得自己的默认分组，具体款式标签仍由业务人员按需维护。

### 单款可用规格

| 字段 | 填写规则 |
|---|---|
| 可用颜色 | 多选，引用颜色管理中的颜色 ID |
| 可用尺码 | 多选，引用尺码 ID，支持从尺码组批量带入。均码从尺码档案选择 |
| 有效颜色尺码组合 | 默认按所选颜色和尺码生成，可取消实际不存在的组合。例如白色有 S、M、L，黑色仅有 M、L |

建议允许研发先建款后补规格，订单确认时校验本单使用的规格是否齐全、有效。样衣同样使用单款或子款规格。尺码组提供带入选项，单款实际保存所选尺码。

### 套装组成

| 字段 | 填写规则 |
|---|---|
| 生产方式 | 套装必填，选合并生产或分开生产。后续按所选方式分流 |
| 必须同架生产 | 合并生产时可设。用于严格控色差的套装，当前先记录现场要求并保留衣架绑定入口 |
| 子款 | 每行必选一个单款。支持同页新建、选择已有单款及按权限编辑其完整档案 |
| 组成角色 | 每行必填，如上衣、下装、帽子。角色表示这件在当前套装里的用途 |
| 每套件数 | 每行必填，正整数，默认 1 |
| 展示顺序 | 默认按添加顺序，支持调整 |

新建子款可带出套装客户与季节，允许调整。编辑已有子款时提示会更新共用档案。移除组成行只解除当前套装关联。合并生产套装的子款只能作为套装订单的组成明细，分开生产套装允许整套下单或单独选择子款。

表单按「基础资料 → 可用规格／套装组成 → 说明与附件」排列。单款显示本款规格，套装显示生产方式和组成，各子款规格随子款档案编辑。订单／PO另设配套明细，按具体颜色尺码组合和套数记录，例如上衣 M、裤子 L、帽子均码，共 100 套。

## 后续规划：从款式档案查看生产资料（2026-11-15）

款式档案列表提供“查看生产资料”入口，进入只读详情工作区。先接入已验收的款式 BOM，默认展示当前已发布版本，并支持查看历史版本；套装按“套装共用用料 → 子款”组织，单款直接查看自己的用料。后续工艺工序、部件、裁片功能各自建设后，逐步接入同一详情工作区的对应页签。

该入口只聚合查看，不复制或维护各独立功能的数据。具体布局、BOM 明细显示、差异展开、权限及分阶段验收见[款式档案生产资料查看规划](ZY-ERP-20261115-款式生产资料查看.md)。当前尚未实施。


## 后续规划：款式标签支持智能体和沙盘（2026-11-19）

款式档案功能可按产品特征、工艺难度、特殊工艺、面料特点、生产要求及质量风险规划标签分类。标签用于检索和候选匹配，款式版本、BOM、颜色尺码、工艺路线和客户确认要求仍由正式业务记录提供。上述分类为后续业务设计，不改变本任务原有验收状态，不自动预置标签。

# 模块-客户档案

> 版本：v2（一期实现，待用户验收）
> 更新日期：2026-11-02
> 所属入口：左侧“订单”模块 → “客户”分类；供订单跟单、生产打样、寄样与后续财务业务引用。
> 术语依据：《服装加工厂专业名词词库.json》v1.8。“客户档案 / Customer Master”“业务员 / Sales Representative / Merchandiser”“统一社会信用代码 / Unified Social Credit Code”按词库使用。

---

## 一、目标与边界

客户档案集中维护客户主数据、联系人和可复用地址，订单、款式/样衣及寄样记录引用客户档案，避免在各业务单据重复录入客户名称和联系方式。

- 客户档案是客户主数据，不是 CRM；一期不做销售漏斗、客户评分、报价管理或客户门户。
- 客户档案归订单模块“客户”分类，不另设左侧一级模块。
- 款式可早于正式订单独立建立；样衣任务必须关联客户。厂内自用样衣使用“自产客户”客户档案，不要求先有正式订单。
- 客户与供应商档案是否允许同一主体复用，暂不假设；现有财务文档分别定义客户和供应商档案。
- 订单账期按《模块-财务与采购.md》所述逐单配置，不在客户主档设置默认账期。
- 主档中的客户名称/联系方式用于当前信息；订单、寄样等历史单据如需保持开单时信息，应在单据中保存必要快照，快照范围待对应单据设计时确认。

## 三、字段草案

### 3.1 客户主档

| 字段名称 | 建议英文名 | 必填建议 | 说明/来源 |
|---|---|---:|---|
| 客户编号 | `customer_code` | 是 | 支持系统自动生成，生成后保持不变；词库没有“客户编号”专词，可复用“自动编号 / Auto Numbering”概念；编号前缀/格式待定 |
| 客户名称 | `customer_name` | 是 | 客户法定/业务名称；词库未查到专用字段译名，需确认后补词库 |
| 统一社会信用代码 | `unified_social_credit_code` | 境内企业客户建议必填 | 识别中国境内企业主体；词库新增“统一社会信用代码 / Unified Social Credit Code”。境外客户不适用 |
| 客户简称 | `customer_short_name` | 否 | 列表、订单和看板展示用；词库未查到专用字段译名，需确认后补词库 |
| 客户类型/属性标签 | 按《地基/属性标签.md》存储，不设专用字段 | 否 | 客户命名空间下自由配置标签；手动新增并保存的标签自动进入“客户”标签档案，后续可提示/筛选/复用；重复标签不重复创建 |
| 客户所在国家/地区 | `country_region_code` / `country_region` | 否 | 从统一国家/地区基础资料选择稳定编码，同时保留名称快照；不代表订单目的地 |
| 业务员 | `sales_representative_id` | 是 | 从人员信息选择并保存人员 ID；选择器支持按岗位、组织架构节点和小组筛选；不校验是否属于特定岗位 |
| 客户状态 | `customer_status` | 是 | 启用/停用；停用后不能新建引用该客户的订单或样衣任务，但历史单据和已进行中的订单/样衣不受影响并可继续执行；状态英文需补词库 |
| 备注 | `remark` | 否 | 一般业务说明，不存密码、Token 等秘密信息；字段英文沿用系统常用命名，需以术语规范核对 |

### 3.2 联系人（客户下可多条）

| 字段名称 | 建议英文名 | 必填建议 | 说明/来源 |
|---|---|---:|---|
| 联系人姓名 | `contact_name` | 是 | 多联系人，不把联系人信息压在客户主档单字段里；需补词库 |
| 联系人职务 | `contact_title` | 否 | 客户侧岗位/职务；需补词库 |
| 联系电话 | `phone_number` | 至少一种 | 电话或手机至少填一种；展示和权限按敏感信息规范处理；字段名需核对词库 |
| 电子邮箱 | `email` | 否 | 邮件沟通地址；需核对词库 |
| 联系人用途 | `contact_role` | 否 | 如业务、跟单、技术、收样；是否需要字典及选项待确认 |
| 默认联系人 | `is_primary` | 是 | 每个客户建议最多一个默认联系人；切换默认时保证唯一 |

### 3.3 地址（客户下可多条）

| 字段名称 | 建议英文名 | 必填建议 | 说明/来源 |
|---|---|---:|---|
| 地址用途 | `address_type` | 是 | 支持客户维护多个地址；至少区分办公联系、样衣收件；订单发货地址是否共用此档案待确认 |
| 收件人 | `recipient_name` | 条件必填 | 寄样地址需要；可选择联系人，也允许录入该次收件人 |
| 收件电话 | `recipient_phone` | 条件必填 | 寄样/快递联系；可从联系人带出并允许按地址保存 |
| 国家/地区、省/州、城市、区县 | `country_region_code` / `province` / `city` / `district` | 否 | 国家/地区从统一基础资料选择并保存名称快照，省/州、城市、区县继续手动输入 |
| 详细地址 | `address_line` | 条件必填 | 用于寄样；需补词库 |
| 邮政编码 | `postal_code` | 否 | 按客户所在地需要填写 |
| 默认地址 | `is_default` | 是 | 建议每种地址用途最多一个默认地址 |

> 国家/地区由系统基础资料统一维护；详细地址仍手动录入。客户所在地区、地址地区、订单目的地和实际发货目的地是独立字段，不能互相代替。

### 3.4 系统维护字段

创建人、创建时间、更新人、更新时间、删除标记等沿用项目通用审计字段，不作为客户业务字段重复设计；具体表结构按开发规范和底座现状核对。

## 四、列表与操作范围建议

- 客户列表：客户编号、客户名称、客户简称、业务员、默认联系人、联系电话、状态。
- 查询：按客户编号/名称/简称、联系人、电话和状态查询；敏感信息搜索范围按权限与脱敏规范确认。
- 详情：分区展示客户基本信息、联系人、地址及被订单/样衣等业务引用的概要。
- 操作：新增、编辑、启用/停用；停用客户不阻断已有单据和进行中业务；未被业务引用时可确认后删除，并同时删除其联系人、地址及标签关联；已被业务引用时禁止删除，可停用。新增业务表必须通过外键声明客户及其联系人、地址的引用。
- 客户名称允许重复；新增/修改时发现同名客户应提醒，用户可确认后继续保存，不自动合并。
- 导入/导出、客户合并：一期暂不纳入，除非用户提出。

## 五、与现有业务的关系

- **订单**：订单引用客户档案；客户交期、订单 PO、供料方式和订单级账期仍属于订单/财务单据，不写入客户主档。
- **打样**：款式可独立存在；样衣任务必须引用客户，厂内自用样衣关联“自产客户”；寄样可引用客户联系人和样衣收件地址。
- **样衣反馈**：反馈记录关联客户及对应寄样批次；具体反馈联系人、确认凭据由打样任务契约定义。
- **应收**：财务按订单/PO 处理客户付款；收款账户、开票抬头、税号等是否纳入客户档案需财务边界确认，本草案不先纳入。

## 六、业务员选择规则（已确认）

- 业务员从现有人员信息中选择，保存关联人员 ID，不手填业务员姓名。
- 人员选择器支持按岗位、组织架构节点和小组筛选，筛选条件用于快速定位人员。
- 不要求被选人员必须具有“业务员”或“外贸业务员”岗位，也不做岗位软校验/硬校验。
- 客户档案不依赖在初始化 SQL 中预置特定业务员岗位；岗位目录是否包含某岗位仍由岗位权威清单单独维护。

## 七、需要确认的业务决策

1. 客户编号的前缀/格式，以及导入时能否保留已有编号。
2. 订单是否必须关联客户。
3. 联系人是否需要业务/技术/收样等用途分类，以及默认联系人是否限制为每客户一位。
4. 地址用途是否要覆盖订单发货、发票/对账地址。
5. 是否需要国际地址多语言展示或邮编校验（国家地区已改为标准资料选择，详细地址仍手动录入）。
6. 除统一社会信用代码外，是否还需要其他税务识别号、开票资料、付款方式；若需要，确认归客户档案还是财务/订单，并遵循逐单账期规则。
7. 是否存在集团客户/母子客户/多个品牌共用一个法人主体。

## 一期实现记录（2026-11-02）

- 入口：订单 → 客户 → 客户档案。代码 `CustomerManage.vue` 保留列设置、拖拽、分页和弹窗；订单首页复用 `FunctionCardGrid`。现行页面标准以 `SystemTemplate.vue` 为准。
- 已实现：客户主档新增与编辑、查询筛选、同名提醒后允许保存、业务员人员选择及组织/岗位/小组筛选、多联系人、多地址、统一信用代码、通用标签关联、启用/停用。支持删除未被业务引用的客户，删除权限独立控制。
- 编号先采用 `KH` + 至少8位序列数字，保存时自动生成；不提供手工覆盖或导入。格式属于本期实现默认值，不宣称已有可配置编号规则。
- 客户类型可空，通过 `customer_master` 命名空间的通用标签维护；首次使用才登记模块。不内置客户、不内置标签。
- 地址用途与联系人用途均手动录入；每客户最多一个默认联系人，每种地址用途最多一个默认地址。样衣收件地址必须填收件人和电话。国家/地区使用系统基础资料，省市及详细地址仍手动输入。
- 客户列表权限为 `system:customer:list`，新增、修改/启停和删除分别为 `system:customer:add`、`system:customer:edit`、`system:customer:remove`。一期客户目录按客户功能权限共享，不自动继承人员信息的数据范围；如需按业务员隔离客户，后续单独确认范围。
- 供后续业务使用的 `/system/customer/options` 仅返回启用客户，详情仍保留停用客户；后续订单/样衣保存时须校验新引用，已有单据不得因客户停用而拦截推进。
- 联系人和地址当前按档案整组更新；正式订单/寄样接入时须存必要快照，不依赖子表行号作为历史事实。
- 新增/编辑客户弹窗按双列展示基本信息；业务员通过标准人员选择弹窗按组织、岗位、小组筛选。联系人和地址在主弹窗中以列表展示，通过子弹窗编辑后随主档一起保存；地址可从联系人带出收件人及电话并允许修改。切换默认联系人或默认地址时，同一范围内的原默认项自动取消。
- DDL：`sql/客户档案_20261102.sql`，已并入权威 `sql/主建表.sql`。已有库标签归属表权限兼容修复见 `sql/标签模块权限修复_20261102.sql`（管理员执行）。
- 尚不纳入：财务开票/付款配置、集团层级、国际地址多语言、客户合并、导入导出、订单与样衣的实际业务接入。

# 织云 ERP（ZhiYun）

织云 ERP 面向服装加工企业，规划覆盖款式研发、客户订单、物料、采购、库存、生产、财务、人员及厂务等业务。系统按共享主数据和单据关系规划跨模块协作；各项能力的实际完成状态以[功能实现状态](Docs/项目记录/功能实现状态.md)为准。

## 产品设计理念

- **从 0 到 1，再持续做到 1 到 100**：完成基础功能后，继续完善完整流程、异常处理、权限、审计、数据关联和日常维护体验。
- **模块按业务链衔接**：款式与规格、订单及 PO、款式 BOM、物料需求、采购与库存、生产等按统一数据关系规划；已接通和待建设的环节分别记录，不把规划写成已上线。
- **重视易用性与完整度**：界面保持清晰，常用录入方式、详情查看、批量处理和流程操作围绕实际岗位设计。
- **智能体嵌入业务场景**：让员工可以结合 ERP 当前页面、截图和业务附件提问；涉及写入业务数据的动作保留用户确认及服务端权限检查。

## 当前功能概况

下表仅作项目概览。具体范围、验收记录和待办以[功能实现状态](Docs/项目记录/功能实现状态.md)及对应功能任务为准。

| 业务领域 | 当前已有能力 | 当前状态与后续工作 |
|---|---|---|
| 基础资料与组织 | 已有颜色、计量单位、分类、标签、尺码、尺码组、客户、仓库与库位、组织及岗位等基础能力。 | 各功能验收状态不同；人员档案、物料档案的部分账号权限和审计仍需核验。 |
| 款式与 BOM | 款式档案支持单款及套装资料；款式 BOM 支持单款/套装用料、规格规则、版本发布和用量试算。 | 款式 BOM 一期已通过用户验收；款式档案近期详情交互变更需按状态记录复验。打样和研发全流程仍在规划建设。 |
| 客户订单与物料计划 | 已有客户订单、多 PO、单款/套装规格、BOM 试算，以及从订单生成物料需求计划的部分链路。 | 订单与计划页面、审批/反审核联动尚待首次用户验收；采购执行、库存台账、收发料和生产报工仍需建设。 |
| 审批 | 已接入 Warm-Flow，并有本人待办、已办、发起记录及若干业务关联能力。 | 部分审批页面已验收；流程配置、通知、催办及更多业务联动按清单逐项验收。 |
| ERP 内嵌智能体 | 代码支持员工身份关联、按权限筛选工具、写操作确认、本地 Skill 读取，以及上传附件和截取 ERP 页面截图后提问。 | 实时模型对话、MCP 工具发现与调用及员工页面验收仍待验证；代码实现不等同于运行验收。 |
| 人事、财务与厂务 | 已有组织、岗位、人员及部分建筑、后勤基础能力和相关模块规划。 | 人员信息完整验收、财务与采购、宿舍、食堂、车辆、物业资产等按模块规划逐步建设。 |
| 生产与经营分析 | 已建立服装生产流程及报表规划。 | 裁剪、吊挂、缝制、后整、质检、外协等生产执行和报表中心尚未整体完成。 |

## 技术基础

| 层次 | 当前技术与边界 |
|---|---|
| 后端 | Java 21、Spring Boot、Maven，基于 RuoYi-Vue-Plus 进行项目扩展；使用 Sa-Token 处理认证与权限。 |
| 前端 | Vue 3、TypeScript、Vite、Ant Design Vue，面向 PC 管理端。 |
| 数据 | PostgreSQL 为 ERP 主数据库；pgvector 用于向量检索。 |
| 缓存与文件 | Redis 按业务需要提供缓存等能力；MinIO 保存对象文件，敏感文件通过受控访问处理。 |
| 审批 | 使用 Warm-Flow 承载审批流程及业务联动。 |
| 定时任务 | 项目规范选型为 XXL-Job。仓库中的 SnailJob 属于框架集成组件，当前不代表 ERP 业务任务已迁移或已接入该调度平台。 |
| 大模型与智能体 | ERP 员工侧当前接入 SnailAI Client/OpenAPI；另有 Spring AI Alibaba Agent Studio 并行测试平台。两者都尚未完成最终框架选型。 |

## AI 框架并行测试

当前并行测试 SnailAI 和 Spring AI Alibaba，重点评估工作流能力及其与 ERP 员工身份、权限、MCP 工具、文件处理和审计的集成。测试的主要动因是：SnailAI 当前尚未提供项目所需的工作流能力；并行测试用于确认其他框架或组合方案能否满足业务流程，不预设测试结果或替换结论。

- **SnailAI**：ERP 员工侧 Client/OpenAPI 接入代码已实现；实时对话、工具发现与调用及页面验收仍待验证。
- **Spring AI Alibaba**：以独立 Agent Studio 作为并行测试平台，当前使用独立登录，尚未打通 ERP 员工登录，也未确定为正式框架。

框架能力、实际接入和验收结论以项目 AI 集成规划及功能状态记录为准。

具体依赖版本、运行服务、配置变量和迁移步骤以代码、`.env.example` 及[开发环境文档](Docs/规范/开发环境与同步流程.md)、[部署与迁移说明](Docs/规范/部署与迁移.md)为准。

## 开发入口

项目日常开发、构建和 Git 操作在 WSL 工作区 `/home/it/ZhiYun` 中完成。首次启动或需要数据库初始化、服务依赖和环境变量配置时，按[开发环境与同步流程](Docs/规范/开发环境与同步流程.md)操作；生产环境迁移须另行遵循[部署与迁移说明](Docs/规范/部署与迁移.md)。

本地环境准备完成后，可在项目根目录使用：

```bash
bash scripts/start.sh
bash scripts/status.sh
```

停止本地服务：

```bash
bash scripts/stop.sh
```

`.env` 中的数据库、对象存储和模型凭据不得提交 Git。仓库不提供通用初始账号密码；账号初始化及权限分配按当前部署环境和项目规则处理。
